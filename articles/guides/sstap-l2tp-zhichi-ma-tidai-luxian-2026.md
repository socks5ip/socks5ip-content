# SSTap 支持 L2TP 吗：两者不在同一层，替代路线有三条

想在 SSTap 里连一条 L2TP 线路，要么换个客户端，要么让系统或路由器自己拨号——它只处理应用层的代理出口，隧道这一层从头到尾都不归它管，重装也不会多出这个入口。

## 界面上只有三种类型，这是定位决定的

SSTap 界面上的「+」号点开，可选类型只有三种：SOCKS5、Shadowsocks、HTTP。这是它的定位决定的，不是版本问题。

它要干的事只有一件：把你填进去的那一条代理出口接管过来，让整机的出站流量都从这里走。L2TP 不属于这个体系——它做的是把两点之间的链路整体隧道化，由操作系统的网络连接组件或路由器来拨号，第三方客户端插不上手。

## 要填的字段对比：代理与隧道差在哪

| 你要填的东西 | SSTap（SOCKS5 / HTTP / SS） | L2TP 拨号 |
|---|---|---|
| 服务器地址 | 代理服务器 IP 或域名 | L2TP 节点地址 |
| 端口 | 平台给的代理端口（惯例 1080 一带） | 固定 UDP 1701 |
| 身份凭证 | 代理用户名 + 密码 | 用户名 + 密码 |
| 额外字段 | 无 | 预共享密钥（部分平台要填） |
| 谁来实现 | SSTap 这类代理客户端 | 系统的网络连接 / 手机 / 路由器 |

## 接管整机流量的机制，为什么容不下隧道

SSTap 的做法可以拆成两步：先用一张虚拟网卡把整机出站流量接进来，再统一交给界面里配置的那一条代理出口。这套设计有两个特征，正好都和 L2TP 冲突。

一是它接管的是「整机流量」而不是「一条链路」，走的是应用层代理，不参与网络层的隧道封装。二是它认准的是「代理服务器 + 端口 + 账号密码」这套写法，对应 SOCKS5 的认证方式；L2TP 需要的是「服务器 + 用户名 + 密码 + 预共享密钥」，还要求对端在 UDP 1701 上建隧道——这个字段和这个端口，在 SSTap 里都没有位置可填。

换个说法：SSTap 解决的是「我的出口是谁」，L2TP 解决的是「我的链路怎么走」。同一个需求场景下两者可能都能用，但工具本身不通用。

| 维度 | 代理类（SOCKS5 / HTTP / SS） | 隧道类（L2TP / PPTP） |
|---|---|---|
| 生效范围 | 交给代理客户端的那部分流量 | 整机（或整条链路） |
| 配置位置 | 客户端软件里 | 系统的网络连接或路由器里 |
| 要填几个字段 | 服务器、端口、账号、密码 | 服务器、账号、密码、预共享密钥 |
| 能不能按窗口分线 | 取决于客户端，SSTap 不行 | 不行，一条隧道一个出口 |
| 典型用途 | 模拟器多开、指纹浏览器、采集脚本 | 软路由一拖多、整机换出口 |

## 路线一：系统自带的拨号客户端

Windows、macOS 和手机都自带 L2TP/IPSec 客户端，不用装任何东西。字段就四个：服务器地址、用户名、密码、预共享密钥。难点不在操作，而在「填什么」。

| 字段 | 长城IP 的口径 | 光子IP 的口径 |
|---|---|---|
| 连接类型 | L2TP（部分档支持 PPTP） | L2TP（后台 E / F 分区套餐） |
| 服务器 | 后台 L2TP 节点页面给出的 IP | 后台提取的服务器地址 |
| 账号密码 | 后台给的一组线路账密，不是平台登录账密 | 后台提取的用户名与密码 |
| 预共享密钥 | 官方固定 123456 | 软路由留空；手机端填 123456 |
| 服务端口 | 按后台给定 | 默认 1701 |

注意「密钥填不填」这件事，两家口径看着相反，其实不矛盾：光子IP 在软路由侧不需要 IPSec 预共享密钥，所以留空；手机自带的连接界面强制要求填一栏，就填 123456。照着自己用的位置对号入座即可。

连上之后别只看系统托盘那个「已连接」——那只代表隧道通了。出口到底有没有换过去，用站内的 IP综合检测中心 看一眼归属地和线路品质更实在。

## 路线二：让路由器拨号，全屋生效

如果你要的不是「一台电脑换出口」，而是「连上 WiFi 的所有设备都走同一条线路」，那 L2TP 确实比 SOCKS5 顺手——这也是 L2TP 档位存在的主要理由：电脑、手机、电视盒子、游戏机，连上就生效，不用一台台装客户端。

以爱快为例，路径是：网络设置 → 隧道拨号客户端 → L2TP → 添加，然后按四个字段填。有三处细节容易踩：拨号名称必须以 L2TP 开头；服务端口默认 1701 不用改；预共享密钥这一栏直接留空，不要顺手填 123456。保存后点「连接」，接口显示「已连接」就通了。

需要把不同设备分到不同出口时，路由器侧的方案是按源地址或按接口做策略路由，而不是给每台设备单独拨号。

## 路线三：多数业务换代理客户端更省事

如果只是要某一台机器、某几个程序换出口，L2TP 反而是绕远路。SOCKS5 这类代理协议在客户端里填四个字段就能用，还能按进程或按应用挑程序，不必动系统设置。

判断标准很简单：需要「全屋所有设备一起换」就选隧道，需要「指定程序换」就选代理。两条路线的入口在同一条线路上往往都能买到，不必为了工具去换平台。

## 最容易填反的两栏

| 容易填错的栏位 | 填错的后果 | 正确做法 |
|---|---|---|
| 把平台登录账密填进 L2TP | 握手失败，报账号或密码错误 | 用后台给出的那一组线路账密 |
| 软路由里填了预共享密钥 | 连不上 | 软路由侧留空，手机端才填 123456 |
| 服务端口从 1701 改成别的 | 隧道建不起来 | 默认 1701 不用动 |
| 拨号名称没有 L2TP 前缀 | 部分路由器不识别 | 名称以 L2TP 开头 |

## 两类故障的排查路径不同

客户端连不上和隧道拨不上，是两条独立的链路，排查顺序也不一样。

| 现象 | 先查什么 | 为什么 |
|---|---|---|
| SSTap 里填完参数连不上 | 参数是不是抄错、线路是不是代理类 | 它只吃代理协议，参数格式错一步就不通 |
| 系统拨号一直停在「正在连接」 | 预共享密钥与端口 | 密钥不匹配或 UDP 1701 被网络策略挡住 |
| 路由器的接口显示已连接但设备没换出口 | 策略路由规则 | 隧道通了不等于流量被引到隧道里 |
| 连上之后出口还是本机 IP | 用检测中心读一次 | 接管动作没生效或规则没命中 |

## 同为一条线路，隧道版为什么更贵

L2TP 通常比 SOCKS5 贵一档，原因不在协议本身，而在落地方式：一条隧道对应一个出口，卖给你的是一条独占链路而不是一份可分配的资源。

以站内价格表为例：极驰云 SK5 静态 10M 折后 6 元/月，同一张表上 L2TP 三档是 8／16／24 元/月；长城IP 的 L2TP 第一档月卡 10 元，而同表 SOCKS5 最低做到 5 元档。站内 23 家横向比价页显示，国内起步价最低 2.24 元/月。

如果你的用途不需要整机接管，为隧道多付的这部分差价买不到对应的价值。

## 常见问题

**Q：SSTap 支持 L2TP 吗？**
不支持。它支持 SOCKS5、Shadowsocks、HTTP 三类代理协议，L2TP 属于隧道协议，界面里没有对应入口，重装也不会多出来。

**Q：那要连 L2TP 线路该怎么办？**
三条路：用系统自带的拨号客户端、让路由器拨号，或者换一个支持隧道的客户端。三种方式的落地成本各不相同。

**Q：L2TP 的预共享密钥到底填不填？**
看位置。软路由侧通常留空，手机和服务器的连接界面强制要求一栏时填平台给定的值，长城IP 是固定 123456，光子IP 手机端填 123456、软路由留空。

**Q：L2TP 的默认端口是多少？**
UDP 1701，按 RFC 2661。平台给的端口如果是 1701 就不要改，改了隧道建不起来。

**Q：为什么 L2TP 比 SOCKS5 贵？**
一条隧道对应一个出口，卖的是独占链路。极驰云同一张表上 SK5 静态 10M 折后 6 元/月，L2TP 三档是 8／16／24 元/月，差价买的是整机接管能力。

**Q：连上了但出口没变是什么原因？**
隧道通了不等于流量被引到隧道里。用站内 IP综合检测中心 读一次出口归属，再检查策略路由或客户端规则是否命中。

数据口径：协议端口按 RFC 2661 等标准口径，平台档位与起步价取自站内各平台价格表页，核实于 2026-10-08；价格如有调整，以平台后台实时显示为准。
