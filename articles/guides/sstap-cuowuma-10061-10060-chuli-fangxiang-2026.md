# 报错分两层：有码的查配置，没码的查网卡

连接失败的两种报错，成本差着十倍：10061 是端口没人应答，10060 是包在路上被丢了。

前者换十条线路也不会好转，后者换一条就能修好；还有一类情况一个字都不报，节点全绿、网页打不开——那是虚拟网卡没把流量接过去。**先判层级，再动手，比反复换 IP 省事得多。**

## 一句话结论

**SSTap 的报错分两层：一层是它去连代理服务器时 Windows 套接字返回的错误码（10061 端口不通、10060 超时、10054 被重置、11001 解析失败），另一层是 TAP 虚拟网卡没把系统流量接过去——没有错误码，表现为节点全绿但网页打不开。** 错误码只说明「失败在哪一步」，不说明「这个 IP 好不好用」，所以 10048、10013、11001 这三类换十条线路都不会好转。

**10061 → 回后台核对 IP:端口，别换线｜10060 → 换一条线路测同一个目标｜10048 → 查本地端口被谁占着｜11001 → 代理地址直接填 IP｜没有错误码 → 查 TAP 网卡与「绕过大陆 IP」勾选项。**

| 错误码 | 系统含义 | 通俗解释 | 最常见原因 | 先做哪一步 |
|---|---|---|---|---|
| 10061 | 连接被拒 | 目标端口没有程序在听 | 端口填错，或这个 IP 没开该端口 | 回后台核对 IP:端口 |
| 10060 | 连接超时 | 握手包发出去没回来 | 落地不可达、被丢包，或本地网络拦了 | 换一条线路测同一目标 |
| 10054 | 连接重置 | 被对端或中间设备打断 | 长连接被打断、落地点不稳 | 缩短会话，换端口重试 |
| 10048 | 地址已被占用 | 本地端口被别的程序占着 | 1080 / 7890 已被其他客户端拿走 | 查占用进程，或改监听端口 |
| 10013 | 权限被拒 | 系统不让绑定 | 防火墙、安全软件拦截，或没管理员运行 | 加白名单 + 管理员身份启动 |
| 11001 | 主机未找到 | 域名解析不出来 | 代理地址填了域名，本机 DNS 不干净 | 直接填 IP，绕开解析 |
| 10065 | 主机不可达 | 路由层面到不了 | 常在本机网卡，不在代理 | 先关代理直连，分清是不是本地断网 |

## 10061 与 10060：一个有人拒绝，一个没人回应

**这两种报错指向完全不同的地方，处理方向也是反的。**

| 对比项 | 10061 连接被拒 | 10060 连接超时 |
|---|---|---|
| 谁在表态 | 对方明确回了拒绝 | 没人回，等到超时才报错 |
| 报错速度 | 通常一两秒就弹 | 要等十几秒甚至更久 |
| 指向哪里 | 端口号、协议、账号权限 | 落地可达性、线路是否被丢包 |
| 换 IP 有用吗 | 基本没用 | 多数有用 |
| 第一步动作 | 回后台核对端口与协议类型 | 用线路检测跑一遍整条线 |

**报错快慢本身就是线索。** 一秒弹出的是「有人回了个拒绝」，十几秒后弹出的是「根本没人理」。前者查配置，后者查线路。

## 10048：本地那个端口到底被谁拿着

**这一条与代理质量毫无关系，纯本地冲突。** 1080、1081、7890 这几个常用端口，只要装了第二个代理客户端，就很容易被抢。

判断方法很直接：关掉所有同类客户端，只留 SSTap 单独启动；通了就是端口冲突，仍不通再往下查。改 SSTap 的监听端口同样有效，改完记得同步改系统的代理设置。

## 节点全绿却打不开：TAP 网卡这条线

**这一类是「没有错误码」的失败，也是最容易被当成 IP 质量问题的。** 四个检查点按顺序看：

| 检查点 | 在哪里看 | 不正常怎么处理 |
|---|---|---|
| TAP 虚拟网卡是否存在 | 设备管理器 → 网络适配器，找名称带 TAP 的那块 | 重装并允许装驱动；仍无则手动装 |
| 网卡是否被禁用 | 同上，图标带向下箭头即禁用 | 右键启用，重启客户端 |
| 是否勾了「绕过大陆 IP」 | 客户端设置面板 | 关掉再测一个境外目标站 |
| DNS 有没有被别的软件接管 | 命令行 `ipconfig /all` 看 DNS 服务器 | 改回自动获取 |

第三行是最常见的假故障：**勾着「绕过大陆」时访问国内站点本来就不走代理，很多人拿国内站当测试目标，得出「代理没生效」的结论。**

## 闪退与界面空白：先排除系统层

**客户端打不开不是网络问题，顺序要反过来查。** 先用管理员身份运行一次；不行就换安装目录（中文路径与受控文件夹常出问题）；再不行检查安全软件是否把主程序隔离了。

界面空白但进程在跑，多数是运行时组件缺失——重装一次并允许安装全部依赖，比逐个排查快。

## 能开网页、游戏进不去：UDP 不在默认路径

**网页走 TCP，游戏多走 UDP，两者在客户端里是两条不同的通路。** 网页正常而游戏连不上，说明 TCP 那条通了、UDP 没接管。

处理方向：确认客户端是否开启了 UDP 转发、是否只对部分进程生效。有些客户端默认只处理 TCP，需要手动勾选游戏进程。

## 换更贵的 IP 也治不好的四类

**这四类错误的共同点是：问题不在 IP 上。** 花更多钱买住宅段、买独享，都不会让它们好转。

- **10048**：本地端口冲突，换线无用；
- **10013**：权限被拦，换线无用；
- **11001**：域名解析不出来，换线无用；
- **TAP 网卡没接管**：根本没有错误码，换线无用。

反过来，**只有 10060、10054，以及「部分节点超时、部分正常」这三类，才值得换线路**。判断依据不是报错文字，而是「同一目标换一条线能不能通」。

## 四步收口

排完还不通，按这个顺序走一遍，能定性九成情况：

1. 关掉客户端直连目标，确认本地网络本身正常——排除宽带、DNS、路由器；
2. 用线路检测直接测 IP:端口——这是 10061 唯一的判据；
3. 只开一个窗口、一个会话连一次——排除并发与配置互相覆盖；
4. 换第二条线路测同一个目标——分清是「这条线坏了」还是「目标站在封这一段」。

## 常见问题

### 10061 换一条线路能好吗？

基本不能。10061 表示对方明确拒绝，多半是端口填错、协议选错，或这个 IP 没有开放该端口。先把后台给的 IP 与端口逐字对一遍，再考虑换线。

### 10060 是不是说明这条线坏了？

不一定。10060 表示包发出去没回来，可能是落地点不可达，也可能是本地网络拦了。用另一条线路测同一个目标，能通就说明是原来那条的问题。

### 没有错误码，但网页就是打不开，怎么回事？

查 TAP 虚拟网卡：设备管理器里有没有那块网卡、是否被禁用、客户端是否勾了「绕过大陆 IP」、DNS 有没有被别的软件接管。这四项都不涉及代理质量。

### 10013 一定要关掉安全软件吗？

不必关。先以管理员身份运行客户端，再把安装目录加进白名单；仍被拦再临时关一次确认，确认后把规则加上。

### 能开网页但游戏连不上是什么原因？

网页走 TCP、游戏多走 UDP，客户端默认可能只接管 TCP。检查是否开启 UDP 转发，以及游戏进程有没有被纳入处理范围。

### 闪退是 IP 的问题吗？

不是。闪退发生在客户端自身启动阶段，与线路无关。按管理员运行、换安装路径、补运行时组件三步排查。
