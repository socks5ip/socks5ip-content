# 三款客户端的三条接管路线

手机上的 App 全部换出口，还是只让电脑上某个程序走？这两个需求看着接近，落到工具上却是两套完全不同的机制——**一个要在系统层面插一层，另一个要在网卡层面插一层。** Postern、SSTap、NekoBox 恰好各占一条路线。

## 一句话结论

三款客户端不是替代关系，而是三种不同的接管方式：**Postern 用系统级转发接管整台安卓设备**，适合「所有 App 都要换出口」；**SSTap 用虚拟网卡接管指定程序**，解决「电脑上的程序根本不认代理设置」；**NekoBox 把协议与路由规则做到最全**，适合「一份线路要同时喂给多个应用」。选型的顺序是：先问要接管的范围有多大，再看协议够不够用，最后才比界面。

| 项目 | 具体口径 |
|---|---|
| 安卓端 | Postern（全局接管）／ NekoBox（协议与路由最全） |
| 电脑端 | SSTap（虚拟网卡接管指定程序） |
| 共同前提 | 一条标准 SOCKS5 线路即可，起步档 2.6 元/月 |
| 最容易选错的地方 | 把「全局接管」当「分流」用 |
| 三者的关系 | 互补而非替代，两端各用各的都能挂在同一条线路上 |

## 接管范围决定工具，不是协议决定工具

选客户端之前先把自己的需求归到两类里，因为这两类对应完全不同的实现方式。

**转发**指的是让本来不走代理的程序也走代理。很多程序（游戏客户端、桌面软件、部分 App）压根没有填代理地址的地方，或者填了也不生效，因为它们直接调系统网络栈。要把这类流量接进代理，必须在系统层面插一层——安卓上靠系统的虚拟网络接口建本地通道，Windows 上靠 TAP 虚拟网卡。Postern 和 SSTap 都属于这一类。

**分流**指的是决定哪些流量走代理、哪些直连。这件事发生在客户端内部：它按规则表（按应用、按域名、按 IP 段）决定每条请求的去向。NekoBox 的强项在这里，路由粒度比前两者细得多。

理解这两件事之后定位就清楚了：Postern 管接管范围，SSTap 管「电脑上接不进来」，NekoBox 管「接进来之后怎么分流」。

## 场景 A：整台手机一起改出口

手机上装了若干个 App，需要它们全部经由同一条 IP 出口访问，而这些 App 大多数并不提供代理设置项——此时需要的是系统级接管。

Postern 的做法是在安卓上建立一条本地虚拟网络，把设备流量整体导入它所连接的 SOCKS5 线路。配置逻辑是「先建代理，再建规则，最后启用」：代理里填线路的地址、端口、账号密码，规则里决定哪些应用走它。对「全部 App 一起走」这个需求，规则留空或选全局即可。

| 要点 | 说明 |
|---|---|
| 代理类型 | SOCKS5 / HTTP / SSH，填线路信息即可 |
| 接管方式 | 安卓系统虚拟网络接口，首次启用会请求系统授权 |
| 规则的作用 | 决定哪些应用进代理；留空即全局接管 |
| 适合谁 | 需要「装了就能用、不必逐 App 适配」的场景 |

这里有一个常被跳过的地方：**授权之后要确认「正在运行」的提示是否真的出现**——安卓各厂商对后台长期连接的限制不同，有的机型会在息屏后回收它。

## 场景 B：桌面程序绕过了系统设置

电脑端的情况和手机不同：Windows 有系统代理，但它是给浏览器那类「遵守系统设置」的程序用的。游戏客户端、某些桌面工具会绕过系统代理直连，于是出现「浏览器走代理了、游戏没走」的现象。

SSTap 解决的就是这一环。它在 Windows 上创建一个 TAP 虚拟网卡，把指定程序（按进程名或 IP 段匹配的流量）导入这条网卡，网卡再把流量交给 SOCKS5 线路。**对程序来说，它只是连了一块普通网卡，完全不需要知道后面有代理。**

| 要点 | 说明 |
|---|---|
| 接管方式 | TAP 虚拟网卡，把进程流量导入 SOCKS5 |
| 匹配方式 | 按进程路径 / 进程名 / IP 段选择要接管的程序 |
| 典型用途 | 客户端不提供代理设置项、或设置后无效 |
| 需要注意 | 安装网卡驱动需要管理员权限，首次配置后建议重启程序 |

SSTap 原版已多年未更新，但它依赖的 TAP 网卡机制本身没变，所以旧版仍能工作，现在主流做法是搭配社区维护的规则包使用。

## 场景 C：一条线路要喂给多个应用

第三种需求和前两种不在一个维度：线路已经有了，协议也是标准的 SOCKS5，但你要在同一台手机上同时用好几条线路，还要按应用决定哪条走哪个出口。**这时候缺的不是接管能力，而是调度能力。**

NekoBox 的强项就是把协议和路由做全。它支持 SOCKS5、HTTP 等多种协议，同时支持节点分组、订阅导入、按应用 / 按域名 / 按 IP 的路由规则。同一份 SOCKS5 线路，可以在它里面建多份配置，再用规则把不同应用指向不同配置。

| 要点 | 说明 |
|---|---|
| 协议支持 | 覆盖主流代理协议，SOCKS5 / HTTP 直接可填 |
| 多节点 | 分组管理 + 订阅导入，节点多时不用反复手动填 |
| 分流粒度 | 按应用 / 域名 / IP 段，比「全局开关」细得多 |
| 适合谁 | 一份线路要同时服务多个应用、且出口要求各不相同的场景 |

它的安装渠道需要留意——同名「冒牌版」不少，认准官方仓库下载。如果你的线路是标准 SOCKS5，配置时协议栏选 SOCKS5，把地址、端口、账号密码填进去即可，不需要额外参数。

## 一张选型表

把三个场景压缩成一张判断表，按「你要接管的范围」往下读即可。

| 你的情况 | 选它 | 原因 |
|---|---|---|
| 手机上所有 App 要一起换出口 | Postern | 系统级接管，不必逐 App 适配 |
| 电脑上的程序不认代理设置 | SSTap | 虚拟网卡在系统层接管，绕开程序自身限制 |
| 手机上要按应用分不同出口 | NekoBox | 路由规则粒度细，支持多配置并行 |
| 手机 + 电脑都要覆盖 | Postern + SSTap | 两端各用各的接管方式，线路可以共用一条 |
| 只是想先验证线路通不通 | 任意一款 + 检测工具 | 先用客户端连上，再去检测中心看出口是否生效 |

## 动手前要备齐的四样

三款客户端的界面差别不小，但配置前要准备的东西是同一套。**缺任何一样都会卡在「连不上但不知道卡在哪」。**

| 要准备的 | 从哪里拿 |
|---|---|
| 连接地址与端口 | 平台后台的线路列表，复制 host 与 port |
| 账号与密码 | 同一条线路的线路账号与密码，不是平台登录密码 |
| 协议类型 | 确认线路是 SOCKS5 还是 HTTP，填错会直接连不上 |
| 系统权限 | 安卓的系统网络授权 / Windows 的管理员权限（装网卡驱动） |

第三项最容易被忽略：不少平台同一档位同时给 SOCKS5 和 L2TP 两种接入方式，**凭据并不通用**。如果客户端里填了 SOCKS5 的端口却按 L2TP 的账号密码来，报错信息通常只写「认证失败」，看不出是协议选错了。

## 三处最容易搞反的地方

**一、把「全局接管」当成「分流」。** Postern 的全局模式会让所有流量都走线路，如果你的本意只是让某一个 App 换出口，多余的流量会白白消耗线路带宽。反过来，NekoBox 的规则没写全时，没被规则覆盖的流量会走默认出口，也不是「什么都不走」。两边的默认行为都要确认一次。

**二、以为装了客户端就等于线路生效。** 客户端只是「把流量交出去」的那一环，出口 IP 是否真的变了，得另测。配完顺手测一次是最省事的验证方式。

**三、在电脑上照搬手机的配置思路。** SSTap 的「进程匹配」和 Postern 的「应用选择」看起来类似，但前者匹配的是可执行文件路径，程序更新后路径变了就得重新加；手机端按包名匹配，一般不会因为升级失效。换平台时这两处的维护成本不一样。

## 常见问题

**Q：Postern 和 NekoBox 都是安卓上的，装一个就够了吗？**
A：看你要做什么。只求「所有 App 一起换出口」，Postern 更直接；要「按应用走不同出口」或同时管多条线路，NekoBox 的路由规则更合适。两者可以并存，但同时启用会争夺系统转发通道，实际只留一个运行。

**Q：SSTap 是不是已经停止更新了，还能用吗？**
A：原版确实多年未更新，但它依赖的是 Windows 的 TAP 网卡机制，这个机制本身没变，所以旧版仍能工作。现在主流做法是搭配社区维护的规则包使用，配置逻辑和原版一致。

**Q：一条 SOCKS5 线路能同时给三款客户端用吗？**
A：能，但要注意并发。同一组账号密码在多台设备上同时连接，是否会互相顶掉取决于平台的并发策略——有的平台一账号一线路只允许一个连接，第二个连上会把第一个断掉。多设备场景建议先确认平台的并发规则。

**Q：客户端连上了，但网页还是提示 IP 没变，怎么排查？**
A：按顺序查三处：① 客户端里是否真的显示「已连接」而不是「已启动」；② 目标程序是否走的是被接管的流量（部分浏览器自带代理设置会覆盖系统级）；③ 到检测中心直接看当前出口 IP 与线路是否一致。三步就能定位到是接管没生效还是规则漏了。

**Q：NekoBox 里协议那么多，我只用 SOCKS5 会不会浪费？**
A：不会。协议多只是「能接的更多」，你完全可以在配置里只建一条 SOCKS5。它的价值在于同一份线路可以配成多个条目，再按应用分发，这一点是协议数量之外的能力。

**Q：三款客户端配好之后，怎么确认出口是干净的？**
A：用检测工具看两项：出口归属地是否符合预期，以及该 IP 的类型（机房 / 住宅 / 移动）。如果业务对 IP 类型有要求，配完客户端后再测一次比事后排查便宜得多。
