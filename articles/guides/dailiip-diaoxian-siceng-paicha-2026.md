# 四层顺序走完，再决定要不要换线路

10 台机器里只有 1 台掉线，先把四层顺序走完再考虑换线路。代理IP 掉线的定位顺序是 **DNS 解析 → 路由路径 → 端口连通 → 防火墙 / 风控**，前三层各有一条命令就能判定，**只有四层全过之后，才值得怀疑线路本身**。国内平台的月卡 **2.6 元/月起**、多数还带免费测试额度，所以「换一条线路验证」的成本远低于反复排查的时间成本——但前提是你知道该换的是线路，而不是自己那台机器的配置。

## 一、先把「掉线」拆成两类，两类不走同一条路

把掉线当成一件事去查，是排查变慢的主要原因。**「一开始就连不上」和「连上以后跑一会儿断」，病因在不同的层**，用同一套动作试只会来回折腾。

| 表现 | 更可能出问题的层 | 第一步做什么 |
|---|---|---|
| 客户端提示连接失败、超时，从来没连上过 | DNS 或端口 | 确认解析结果，再测端口连通 |
| 能连上，跑十几分钟到一小时断一次，重连又正常 | 客户端并发或本地防火墙策略 | 看并发数是否超过档位上限 |
| 每天固定时段断（比如整点前后） | 平台侧切换 / 心跳机制 | 看后台的切换设置与公告 |
| 换了手机热点立刻就通 | 本地出口、路由器或本机安全软件 | 不用往下查，直接处理本地环境 |

先做完这一层分流，后面四层里至少有两层不用查。

## 二、DNS 层：填 IP 能通、填域名不通，就是这一层

DNS 层有一个很干净的判据：**同一条线路，客户端里填 IP 能连、填域名连不上**，那就是解析问题，和线路质量、平台好坏都没有关系。

| 系统 | 命令 | 看什么 |
|---|---|---|
| Windows | `nslookup 你的代理域名 223.5.5.5` | 返回的 IP 是否与后台公布的节点 IP 一致 |
| macOS / Linux | `dig @223.5.5.5 你的代理域名 +short` | 同上 |
| 交叉对比 | 再用 `8.8.8.8` 查一次同一域名 | 两次结果不同 → 本地 DNS 被劫持或污染 |

三种结果分别怎么读：解析到 `0.0.0.0` 或 `127.0.0.1`，是被本地 DNS 或运营商直接拦了，换公共 DNS 试；解析结果与后台 IP 不一致，多为本地缓存过期，Windows 用 `ipconfig /flushdns`、macOS 用 `sudo dscacheutil -flushcache` 清一次；解析正常但仍连不上，说明这一层通过，进第二层。

还有一条顺手的解法：把连接串从 `socks5://` 改成 `socks5h://`。两者的差别不在速度，而在**域名由谁解析**——前者在本机解析，后者把解析交给代理服务器，能顺带绕开本地 DNS 污染。

## 三、路由层：tracert 全红，并不代表端口不通

路由层要回答的是「数据到底从哪条路走到目标」。命令按系统选一个：Windows 用 `tracert -d 目标IP`，Linux 用 `mtr -rwzc 20 目标IP`，macOS 用 `traceroute 目标IP`。

| 现象 | 说明与处理 |
|---|---|
| 第 1–2 跳就不通 | 本地网关或运营商出口问题，先重启路由器与光猫，换网线复测 |
| 中间某跳开始全是星号并持续到结尾 | 该段链路屏蔽 ICMP。**ICMP 不通不等于端口不通**，必须进第三层用 TCP 确认 |
| 只有最后一跳超时 | 目标侧禁 ping，是常见配置，不代表线路坏 |
| 国内目标的路径绕到境外再回来 | 路由异常（BGP 绕路），表现是延迟整体抬高，这类只能找平台换节点 |

很多人看到 tracert 全红就断定线路死了，实际端口一直是通的。**ICMP 和 TCP 走的是两条不同的判断路径**，这句话能省掉一半无谓的换线。

## 四、端口层：三种「连不上」的含义完全不同

端口层是最容易误判的一层，因为三种返回结果看起来都像连不上。

| 系统 | 命令 | 通过的标准 |
|---|---|---|
| Windows（PowerShell） | `Test-NetConnection 目标IP -Port 端口` | `TcpTestSucceeded` 显示 True |
| Windows（旧系统） | `telnet 目标IP 端口` | 黑屏无报错＝通；长时间无响应＝不通 |
| Linux / macOS | `nc -vz 目标IP 端口` | `succeeded`＝通，`refused`＝被拒 |
| 带账号实测 | `curl -v -x socks5h://用户:密码@IP:端口 https://ipinfo.io` | 返回的出口 IP 与购买时一致＝全链路通 |

三种结果的读法：**立即被拒**说明端口没开或服务没起，最常见的原因是 IP / 端口抄错，其次才是节点下线；**超时无响应**说明数据包被中间设备丢弃，可能在本机防火墙，也可能在目标侧，需要第四层来分；**能连上但卡在认证**说明账号密码或协议类型不匹配——SOCKS5 与 HTTP 在同一个 IP 上用的是不同端口，填错会一直在认证环节打转。

## 五、防火墙层：三处都可能掐断，用换环境法区分

要查的不是一个地方，而是三个：本机安全软件与系统防火墙、路由器（含软路由）上的策略、服务商侧的风控。它们造成的现象很像，用换环境的方式最容易区分。

| 做一次 | 结果 | 结论 |
|---|---|---|
| 换手机热点重试 | 恢复正常 | 问题在原网络出口或本机防火墙 |
| 换手机热点重试 | 依旧断 | 问题在目标侧、账号或线路本身 |
| 临时退出安全软件（360 / 火绒 / Defender） | 恢复正常 | 本地拦截，把客户端加进白名单即可 |
| 把并发从很高降到档位上限以内 | 不再断 | 触发了服务商侧限流，需错峰或升级并发档位 |

软路由环境还要多看一处：`iptables` / 爱快 / OpenWrt 的防火墙规则与分流策略。旁路由做分流时，如果规则的判断条件写得过窄，会出现「某几个目标走代理、其余直连」的情况，表现出来就是部分业务正常、部分业务一直失败。

## 六、四层全过还断：五种归因按顺序对号

| 现象 | 归因 | 处理 |
|---|---|---|
| 同一批线路里只有一两条断 | 单节点问题 | 后台重新提取或换节点，不用换平台 |
| 整批线路同时断 | 账号侧或平台侧 | 看公告，换协议（SK5 换 L2TP）交叉验证一次 |
| 手里几个不同平台都断 | 本地网络出口 | 回到第一、二层重查 |
| 断的频率和任务量正相关 | 并发或频控超限 | 降并发、错峰跑 |
| 连通性正常但业务侧判失败 | 出口 IP 的地区或类型与标称不一致 | 用检测工具复核并截图，这是要处理的问题本身 |

客户端层还有三个高频坑，症状都像「平台不稳定」，实际都在自己这边：**多个客户端同时接管流量**（SSTap、Proxifier、老鱼一起开）会时通时断，同一时间只留一个接管全局流量；**把 SOCKS5 端口填进 HTTP 代理框**会一直认证失败，协议与端口必须成对使用；**并发数拉得比档位上限高**会「跑一段时间固定掉一次」，需要把并发降到上限以内或换更高的并发档。

第三种的误判率最高：国内平台的月卡价差主要买三样东西——**带宽、并发条数、独享程度**。低价档（如 **2.6 元/月**级别的 SK5 档）适合少量窗口的轻量任务，把几十个窗口压在同一档上，掉线是必然的，不是平台的问题。价格以平台后台实时显示为准（本节核对于 2026-09-19）。

## 常见问题

**Q：换了 IP 还是掉线，是不是该换平台了？**
先别换。同一个客户端、同一个任务，换手机热点再跑一次：症状跟着网络环境变，问题在本地；症状一模一样，才去怀疑线路或平台。

**Q：开了代理还是本地 IP 怎么办？**
说明请求没有真正走代理。查三件事：客户端是不是只代理了部分程序、系统代理有没有真正开启、DNS 是不是还在本地解析（改用 `socks5h` 或在客户端里打开「DNS 走代理」）。最后用检测工具看出口 IP 是否已变。

**Q：为什么白天正常，晚上八点以后开始断？**
两个方向分开验。跑一次 `mtr`，看中间跳的延迟是否在晚上整体抬升（本地出口晚高峰丢包）；如果延迟没变，那就是多台机器同时开跑把并发顶上去了，降并发或错峰都能试出来。

**Q：怎么确认端口是被本地防火墙拦的？**
临时关掉系统防火墙与第三方安全软件各跑一次做对比。一关就通，把它加进白名单即可，不建议长期关着防护。

**Q：客户端提示连接成功，但网页就是打不开？**
说明 TCP 已经通了，问题在上层。检查是不是只代理了部分程序、系统代理是否真正生效、DNS 是否仍走本地解析这三项。

**Q：每换一个平台都要这样排查一遍吗？**
不用。四层排查与平台无关，命令和现象是通用的。换平台时只有三项要重新确认：端口号、协议类型、并发上限。
