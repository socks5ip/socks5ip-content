# 代理出口乱跳：不是节点在换，是路由表里有几条默认路由（2026）

出口乱跳这件事，八成不是平台在换节点，而是这台机器出门时有两条默认路由在抢——系统按跃点数挑一条，跟你在客户端里填了哪个地址没有关系。

**一句话结论：**代理客户端改的是**应用层**（哪个程序走代理），数据真正从哪块网卡出门由**系统路由表**决定。笔记本同时插网线、连 WiFi、开着 TUN 客户端时，路由表里会躺着**三到四条默认路由**，系统按**跃点数**选一条。所以「上午能连、下午超时」多半是备用链路接管了出口，**加买一条线修不好这一层**。

## 一、应用层管程序，系统层管出门

这两层各自解决不同的问题，混在一起就会误判。

| 层 | 谁在管 | 管什么 | 出问题的表现 |
|---|---|---|---|
| 应用层 | 代理客户端 | 哪些程序把请求交给代理 | 某个程序不走代理 |
| 系统层 | 路由表 | 请求从哪块网卡、经哪条链路出去 | 时好时坏、换网络就变 |

客户端里填好地址只是第一步。请求交给代理之后，代理自己的连接要从系统出门，这一跳由路由表决定。

## 二、为什么笔记本里会同时躺着几条默认路由

默认路由就是「不知道往哪走时走这里」。系统允许存在多条，按跃点数排序，数字小的优先。

| 来源 | 会不会插默认路由 | 典型表现 |
|---|---|---|
| 有线网卡 | 会，一条 | 插上网线后代理像失效，拔掉又恢复 |
| WiFi | 会，一条 | 路由器重启后出口跟着换 |
| TUN 模式客户端 | 会，且常带更小的跃点数 | 与 SOCKS5 客户端抢接管，退出后残留 |
| 游戏加速器 | 部分会 | 只对指定进程生效，命令行照样直连 |
| VMware／Hyper-V／WSL 虚拟网卡 | 多数不插，但会改 DNS | 本机地址显示成 172.x，解析变慢 |
| 手机热点／USB 共享 | 会，一条 | 与 WiFi 优先级接近，网络一抖就切 |

关键在于**跃点数会随链路状态变化**：WiFi 信号变差、网线松动、TUN 客户端启动或异常退出，都会让排第一的那条换人。出口"自己变了"，其实是排序变了。

## 三、症状对得上状态，先认哪一种

| 症状 | 常见误判 | 实际所在层 |
|---|---|---|
| 时好时坏、隔一阵全超时 | 平台节点不稳 | 系统路由，多默认路由争用 |
| 客户端绿灯，检测页显示本地 IP | IP 没换成功 | 应用层，程序没走代理 |
| 换几条线都一样慢 | 带宽不够 | 路径被 TUN 或加速器绕行 |
| 只有某个软件不通 | 线路封了该业务 | 程序自身的代理设置 |

第一行和第三行是路由层，第二行和第四行不是。分清楚再动手，能省掉一半无效排查。

## 四、先读出来再改：三条命令看清现状

改动之前必须先看清有几条默认路由、谁的跃点最小。

1. **看默认路由（Windows）**：`route print -4`，找 `0.0.0.0` 那几行，看「接口」与「跃点数」两列。
2. **看排序（PowerShell）**：`Get-NetRoute -DestinationPrefix 0.0.0.0/0 | Sort-Object RouteMetric`，第一条就是当前生效的出口。
3. **看走哪条（链路跟踪）**：`tracert -d 一个公网地址`，第一跳的地址属于哪块网卡，就是实际出口。

macOS 与 Linux 的对照：`netstat -rn | grep default`、`ip route show default`。

## 五、收敛动作就四条，代价各不一样

看清楚之后，按需要选一条，不用全做。

| 动作 | 命令／位置 | 代价 |
|---|---|---|
| 拔掉不用的链路 | 物理断开网线或关 WiFi | 最简单，失去冗余 |
| 调高备用链路跃点 | `Set-NetIPInterface -InterfaceIndex N -InterfaceMetric 50` | 需要记接口号，重启后仍生效 |
| 关掉 TUN 的全局接管 | 客户端设置里关「全局／TUN」 | 部分流量不再走代理 |
| 固定只走一条出口 | 客户端「仅代理」模式 + 停用虚拟网卡 | 灵活性下降，排查面变窄 |

**改跃点数是最稳的一条**：不影响物理连接，只调整优先级，且重启后依然生效。改完用第 2 条命令复查排序，确认目标链路排第一。

## 六、什么时候真该加线

路由问题用路由手段解决，但有两种情况确实该加线。

- **单条线带宽不够**：多个窗口同时刷新带图列表，卡在下载速度上，而不是时断时续。
- **出口数量不够**：需要同时开 N 个独立出口，一条线只能给一个出口。

判断方法很直接：**换一条同档的线，症状一模一样 → 不是这条线的问题；换一条就顺 → 是这条线的问题**。前者继续查本地，后者才考虑加买或换平台。

## 常见问题（FAQ）

### Q：客户端显示已连接，检测页却显示本地 IP，是线路坏了吗？

多数不是。先看客户端是「全局」还是「规则」模式，再看这个程序有没有被规则覆盖。检测页如果是在浏览器里打开的，而浏览器走了直连规则，看到的就是本地 IP。

### Q：route print 里有好几条 0.0.0.0，正常吗？

正常。有线、WiFi、TUN 客户端各插一条是常见状态。系统按跃点数选一条生效，其余作为备用。问题是这些备用的跃点数会随链路状态变化，导致出口在你不察觉的时候换人。

### Q：改跃点数会不会影响上网？

不会影响连通性，只影响优先级。把不用的链路跃点调高，等于让它排在后面；那条链路本身照样能用，只是不再抢默认出口。

### Q：为什么重启 TUN 类客户端之后网络就乱了？

部分客户端退出时不清路由，残留的默认路由还在表里，指向一个已经不存在的接口。表现是所有流量走不通。处理办法是重启网络适配器，或手动删除残留路由。

### Q：虚拟机网卡也会抢出口吗？

多数不插默认路由，但会改 DNS 和邻居表。典型表现是本机地址显示成 172.x、域名解析变慢，而不是出口乱跳。遇到解析慢可以先停用虚拟网卡试一次。

### Q：加了第二条代理线，出口还是老跳，为什么？

路由层没解决。多一条线只是多一个可用的代理地址，出门那一跳仍由系统决定。先把默认路由收敛到一条，再评估是否需要第二条线。
