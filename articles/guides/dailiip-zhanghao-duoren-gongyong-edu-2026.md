# 代理 IP 账号能不能几个人共用？先分清额度是按人还是按账号

成员 A 点了「切换节点」，成员 B 的采集窗口当场报错——同一份额度被三个人同时占用时，先停下活的往往是别人。

**「能不能登录」从来不是瓶颈。** 真正先被花光的，是切换额度、出口条数和并发这三样按账号算的资源——先停下活的往往是别人。站内低价档 2.24 元/条起，额度常常比线路先见底。

## 一句话结论

代理 IP 是按账号计价的，不是按人头计价。**所以「几个人一起用」这件事，平台既不禁止也不提醒——它只是在你把额度花光的那一天，让所有人的业务一起停摆。**

| 账号级资源 | 计数口径 | 被花光的典型表现 |
|---|---|---|
| 切换额度 | 按账号 / 按条，单位是次数 | 有人切了，别人当场掉线 |
| 出口条数 | 按账号可同时持有的线路数 | 想多开时提示无可用出口 |
| 并发 | 账号级同时连接上限 | 部分请求直接失败，重试也失败 |

## 第一批被花光的，是切换额度

把场景压到最小：三个人挂同一条 IP。谁在后台点了「切换」，另外两人当场的会话就断了——**这不是故障，而是切换是账号级动作，不区分是谁点的。**

| 动作 | 影响范围 | 是否可重试 |
|---|---|---|
| 后台切换出口 | 全账号，所有使用者 | 不可重试，会话已断 |
| 新增一条出口 | 占用账号的条数额度 | 可重试 |
| 高峰并发叠加 | 挤占账号并发上限 | 部分可重试 |

## 条数按业务线切，不按人头切

一个常见的误判是「给每个成员分一条线就互不干扰了」。出口条数确实可以分配，**但真正决定体验的是并发和切换**：分到不同出口只解决了关联问题，没有解决额度问题。

| 分配方式 | 解决什么 | 没解决什么 |
|---|---|---|
| 按成员分出口 | 关联风险 | 并发仍共享、切换仍互相影响 |
| 按业务线分出口 | 关联 + 额度隔离 | 需要更多条数 |
| 共用一个出口 | 成本最低 | 三样资源全部共享 |

## 第三个隐性上限落在并发上

切换和条数还能在后台看见，并发往往看不见，直到有人开始报「请求失败」。**它不体现在界面数字上，而是体现在业务失败率上。**

| 现象 | 先怀疑 | 怎么验证 |
|---|---|---|
| 间歇性请求失败 | 并发上限 | 减少同时在线的成员数再试 |
| 只有高峰时段失败 | 并发被挤占 | 错开时段复测 |
| 单独用正常、一起用就失败 | 账号级并发 | 分开跑同一任务对比 |

## 登记表要写清三件事

多人共用一个账号，最容易失控的是没人说得清当前谁在占哪条线。**一张登记表就能把大部分「莫名其妙掉线」变成可解释事件。**

| 列 | 记什么 | 为什么必须记 |
|---|---|---|
| 成员 | 谁 | 出事时能找到人 |
| 业务线 | 跑的是什么任务 | 判断是否关键动作 |
| 当前出口 | 占用哪条线 | 排查切换冲突 |
| 切换记录 | 谁在什么时候切过 | 对上掉线时间点 |

## 可以不拆账号的四种情形

| 情况 | 一个账号够不够 | 理由 |
|---|---|---|
| 2–3 人、时段错开 | 够 | 切换动作不重叠 |
| 只跑可重试的吞吐任务 | 够 | 失败重试成本低 |
| 有人跑注册、支付这类不可重试动作 | 不够 | 掉线代价无法承受 |
| 多人同时在线且都要切 | 不够 | 切换互相打断 |

判断口诀：**先数人、再数动作、最后看额度口径。** 只要「不可重试动作」有两个以上同时在线的使用者，就按业务线拆账号，而不是按人头拆。

## 自测口径

| 要验的 | 怎么验 | 达标线 |
|---|---|---|
| 出口是否生效 | IP 综合检测中心看归属地 | 与预期属地一致 |
| 切换是否互相影响 | 两人同时段各切一次 | 不掉线 |

| 条数是否够分 | 后台看可用出口数 | 覆盖业务线数量 |

## 常见问题

**一个账号最多能几个人用？**
平台通常不设人数限制，因为计价口径是账号而不是人头。真正会先到上限的是切换额度、出口条数和并发，这三样与人数相关但不与人数成正比。

**为什么别人一切换我就掉线？**
切换是账号级动作，作用范围覆盖账号下所有正在使用的会话。要避免这种互相打断，只能把使用者拆到不同账号。

**多买几条出口能解决共用问题吗？**
能解决关联和部分额度问题，解决不了并发共享。并发是账号级的，加条数不等于加并发。

**怎么判断是并发不够还是线路不行？**
让成员分开跑同一个任务，都能成功说明线路没问题；一起跑才失败，就是账号级并发被挤占了。

**什么时候该按人头拆账号？**
基本不按人头拆，而是按业务线拆。把不可重试的关键动作单独放到一个账号里，比按人数平均分配更省，也更稳。
