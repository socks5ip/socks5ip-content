# 同一个代理，http 能开 https 报错，问题多半不在加密

先别怀疑代理把加密流量挡了——被拒的多半是那一步隧道请求，跟协议支持没关系。

## 一句话结论

**HTTP 代理处理 https 目标时不转发明文，而是先发一句 CONNECT 域名为自己开一条只认「域名:端口」的盲隧道。隧道建不起来，你看到的就是 407、403 或 ERR_TUNNEL_CONNECTION_FAILED。** 站内常见档位是 **4 元/月**（光子IP B 特惠 3–5M，走渠道价）与 6 元档；这两档都支持 CONNECT，**换一条更贵的线解决不了隧道被拒的问题**。

| 概念 | 实际含义 |
|---|---|
| 为什么 https 特殊 | 内容是加密的，代理没法代为请求，只能中转字节，于是有了 CONNECT |
| 代理能看到什么 | 只有域名与端口；路径、Cookie、正文都看不到 |
| 三类报错各在哪一层 | 407＝认证没送到；403＝目标被挡；隧道失败＝CONNECT 没建起来 |
| 最常见的误判 | 把 407 当成出口被封，于是换平台、换档位，钱花了症状没变 |
| 成本锚 | 站内起价 2.24 元起，常见 4 元与 6 元档，这笔钱买的是出口，不是 CONNECT 权限 |

## 一、四类报错，四个不同的责任方

先看提示，再决定查哪里。四类提示指向四个完全不同的层，混着查最费时间：

| 你看到的提示 | 谁发出的 | 说明什么 | 先查哪里 |
|---|---|---|---|
| 407 Proxy Authentication Required | 代理服务器 | 要认证，但凭据没送到或格式坏了 | 账号密码、URL 编码、白名单 |
| 403 Forbidden | 代理或目标站 | 认证过了，但这条线不允许访问该目标或端口 | 目标域名、端口是否在放行范围 |
| ERR_TUNNEL_CONNECTION_FAILED | 浏览器 | CONNECT 没拿到 200，隧道根本没建立 | 代理地址端口、协议类型、目标端口 |
| 证书告警（ERR_CERT_AUTHORITY_INVALID） | 浏览器 | 有设备在替换证书，或端口填成了明文代理口 | 本机是否装了陌生根证书、协议是否写错 |
| 一直转圈后超时 | 网络层 | 连代理入口都没通，与 CONNECT 无关 | 入口 IP:端口是否可达、IP 是否过期 |

表格第一行与第四行最容易混淆：407 是「代理不认识你」，证书告警是「有人在你和目标之间换证书」。前者换密码，后者换端口或查本机根证书，两件事没有交集。

## 二、HTTPS 走 HTTP 代理，多了一次握手

把两种目标站放在一起对比，差别一目了然：

| 目标站 | 客户端对代理说的第一句话 | 代理能看到 | 能否改写内容 |
|---|---|---|---|
| `http://` 站点 | GET http://域名/路径 HTTP/1.1 | 完整 URL、请求头、正文 | 能，这也是明文代理的风险来源 |
| `https://` 站点 | CONNECT 域名:443 HTTP/1.1 | 只有域名与端口 | 不能，除非装根证书做中间人 |
| 走 SOCKS5 时 | 二进制握手，带目标地址与端口 | 目标地址与端口 | 不能，与 http/https 无关 |

第三行说明一件事：**能开 http 不能开 https，跟协议是 HTTP 还是 SOCKS5 关系不大，跟「这条链路允不允许 CONNECT」关系很大。**

## 三、地址栏里的 http:// 说的是代理，不是目标站

客户端里填代理地址时，前面那个 `http://` 描述的是「我用什么协议跟代理说话」，跟你要访问的站是不是 https 没有任何关系。这一点被误解的频率极高。

| 你写的 | 实际含义 | 结果 |
|---|---|---|
| `http://1.2.3.4:8080` | 用 HTTP 协议连代理，再由代理 CONNECT | 访问 https 站正常 |
| `https://1.2.3.4:8080` | 要求与代理之间先建 TLS | 多数代理不支持，直接连不上 |
| `socks5://1.2.3.4:1080` | 用 SOCKS5 握手，不涉及 CONNECT | 与目标站协议无关 |

第二行是常见自伤：把代理地址写成 https，等于要求代理端口先支持 TLS 握手，绝大多数线路不支持，表现就是「一直转圈」。

## 四、密码里有 @ 或 #，凭据在路上就断了

把账号密码拼进 URL 时，`@` 与 `#` 是保留字符，会被解析成「主机分隔符」或「锚点」。密码里带这两个字符，凭据在到达代理之前就已经碎了。

| 密码形态 | 拼接后的样子 | 结果 |
|---|---|---|
| 纯字母数字 | `user:abc123@1.2.3.4:8080` | 正常 |
| 含 `@` | `user:a@b@1.2.3.4:8080` | 被解析成主机名 `b@1.2.3.4`，407 或连接失败 |
| 含 `#` | `user:ab#c@1.2.3.4:8080` | `#` 之后被当锚点丢弃，密码变短，407 |
| 含 `%` 或空格 | 需要百分号编码 | 未编码则解析异常 |

处理办法只有两个：在客户端里分开填账号与密码两格，或者对特殊字符做百分号编码。**能分开填就别拼 URL。**

## 五、只放行 443 的线路，非标端口必然打不开

部分线路的放行策略是按端口来的，只开 80 与 443。这种情况下：

| 目标端口 | 结果 | 说明 |
|---|---|---|
| 443 | 正常 | 在放行范围内 |
| 80 | 正常 | 在放行范围内 |
| 8080 / 8443 / 2053 | 403 或隧道失败 | 端口不在白名单 |
| 自定义端口 | 同上 | 隧道请求被拒 |

判断办法是换一个标准 443 的站试一次。443 通、非标端口不通，就是端口策略问题，跟加密无关，换线路也未必解决——要换的是「放行所有端口」的那类线路。

## 六、该不该换线，三条反证就够了

花钱换线之前，先做三个不花钱的排除：

| 反证 | 怎么做 | 结论 |
|---|---|---|
| 同一个代理，换 http 目标站 | 打开任意 http 站 | 能开 ⇒ 隧道层有问题，不是线路不通 |
| 同一个目标站，换直连 | 关掉代理访问 | 能开 ⇒ 问题在代理侧，不在目标站 |
| 同一个代理，换一个标准 443 站 | 访问主流 https 站 | 能开 ⇒ 是目标端口或域名策略问题 |

三条里任意一条成立，都不该急着换平台。真正需要换线的情形只有一种：三条反证全不成立，直连也不通——那才是出口本身出了问题。

## 七、贵 4 元的隧道档，什么时候值

同平台的整机隧道档（L2TP/PPTP）比 Socks5 档贵 4 元左右，它解决的不是 HTTPS 打不开，而是另一类需求：

| 需求 | Socks5 档 | 整机隧道档 |
|---|---|---|
| 只让某个程序走线 | 支持 | 不支持，整机走 |
| 设备不支持代理设置（如某些采集硬件） | 接不了 | 能接 |
| 需要手机、路由等设备直连 | 需装客户端 | 系统自带拨号即可 |
| 排查 HTTP/HTTPS 兼容问题 | 更简单，层次清楚 | 更难定位 |

**HTTPS 打不开这类问题，隧道档帮不上忙，反而多一层。** 它的价值在「设备接不上代理客户端」的场景。

## 常见问题

### 代理支持 HTTPS 吗，为什么 http 能开 https 不能？

支持与否看这条链路允不允许 CONNECT。能开 http 只说明 TCP 层通了，https 还要多一步隧道请求，卡住的通常是这一步。

### 407 是不是 IP 被封了？

不是。407 是代理要求认证而凭据没送到，跟出口是否被封无关。换 IP、换平台都不解决，先查账号密码与编码。

### ERR_TUNNEL_CONNECTION_FAILED 怎么修？

先确认客户端里的协议类型写的是 HTTP 而不是 SOCKS5，再确认端口填的是代理端口而不是目标端口。两项都对仍报错，就是这条线不放行该目标。

### 密码里有 @ 用什么办法最稳？

在客户端里把账号、密码分开填两格，不要拼成 `user:pass@host` 的形式。必须拼时对 `@` 做百分号编码。

### 换个贵一点的档能不能解决打不开？

只有在「线路放行端口不足」这一种情形下换档有效。认证、凭据编码、协议填错这三类问题，换多贵的档都一样。
