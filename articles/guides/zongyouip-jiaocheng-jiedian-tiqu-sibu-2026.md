# 纵游IP 节点怎么落到客户端？三类协议各填哪一栏

打开纵游IP 后台的节点列表，别急着复制那串连接信息，先把目标国家确认对——静态长效住宅的出口不会自己跳，**选错国家的节点，后面所有配置动作都要重来一遍**。字段本身不难填，真正让人绕的是「三类协议各自的参数落在哪一栏」。

## 一句话结论

纵游IP 的使用链路是**后台取节点 → 客户端填字段 → 需要批量时换 API** 三段。Socks5 与 HTTP 填的字段几乎相同、只改「代理类型」那一栏；游戏协议（Shadowsocks 类）是另一套带加密方式的参数。配完先自测，再接入业务。

| 关键项 | 口径 |
|---|---|
| 协议入口 | Socks5 / HTTP（mixed）· 游戏协议（Shadowsocks 类） |
| 全档统一 | 5Mbps 带宽 · 100 连接并发 |
| 节点形态 | 静态长效住宅，一条线路用一段时间，出口不自动跳 |
| API 对接 | 官方接口文档（52 个接口 · 请求头 X-Api-Key 鉴权） |
| 上线前建议 | 先用约 2 小时 / 1GB 的测试卡跑通链路 |

## 先确认国家，再去拿字段

节点是「先取后用」的模式，所以第一步一定是登录后台把连接信息取出来。这一步最容易出错的地方不在复制动作，而在选地区。

| 顺序 | 在后台做什么 | 拿到什么 |
|---|---|---|
| 第一步 | 登录账号，进入静态住宅 / 代理列表 | 已购套餐与可用地区清单 |
| 第二步 | 按业务目标选定国家 / 地区节点 | 一条静态长效住宅出口记录 |
| 第三步 | 查看详情，复制连接信息 | 服务器地址、端口、用户名、密码（或授权串） |

有一处要提前知道：静态长效住宅是「一条线路用一段时间」的形态，第三步复制下来的那组信息就是你接下来一直在用的那组。**把它当成「临时代理地址」来用、等着它自己换，是新手最常踩的一个坑。**

## 三类协议参数各填哪一栏

| 协议 | 客户端要填的字段 | 典型适用工具 |
|---|---|---|
| Socks5 | 地址 + 端口 + 用户名 + 密码 | 桌面代理工具、指纹浏览器、开发脚本 |
| HTTP / mixed | 地址 + 端口 + 账号密码 | 浏览器、系统代理、需要 HTTP 口的上游 |
| 游戏协议（Shadowsocks 类） | 地址 + 端口 + 加密方式 + 密码（或 ss:// 链接） | 支持该协议的客户端、软路由插件、移动端 |

Socks5 和 HTTP 的差别只落在「代理类型」那一栏：地址、端口、账号密码是同一组，切协议不用回后台重新提。**判断该走哪条路的动作很简单——字段里有没有「加密方式」这一栏。** 有，就是游戏协议那条通道；没有，就是 Socks5 / HTTP。把 ss:// 参数填进「Socks5 代理」栏，客户端通常只回一句「认证失败」，看起来像账号问题，实际是协议填错了。

## 客户端落地的三个场景

同一个节点落在不同设备上，要改的位置完全不同。这三个是最常见的，也最容易配错。

| 场景 | 改哪一处 | 要注意的点 |
|---|---|---|
| 软路由 / 整机接管 | 上游节点里加一条 Socks5 或游戏协议节点 | 整机与下级设备共用同一条出口，换节点会一起变 |
| 指纹浏览器 | 每个环境单独填一条 Socks5 代理 | 一个环境一条出口，复用会让排查分不清是哪边的问题 |
| 安卓云机 / 模拟器 | 系统或 App 内填代理，或走游戏协议导入 | 云机数量多时优先考虑用 API 批量下发 |

这三个场景的共同点：一旦出口被多个业务共用，后续出问题时定位就要多绕几层。**「一个业务一条出口」这条组织原则，比选哪一种协议更影响最终体验。**

## 批量场景才需要动 API

只有一条两条节点，手动提最省事；节点数量上到几十条、还要跟着业务节奏轮换时，才值得走 API。接口基址在官方文档里给出（形如 `zunoip.com/api`），共 52 个接口，鉴权靠请求头里的 `X-Api-Key`。

| 对接要点 | 说明 |
|---|---|
| key 从哪来 | 登录后台在账号 / 接口设置处生成 |
| 保管要求 | 不要写进前端代码或公开仓库，外泄等于把套餐额度交出去 |
| 频率限制 | 脚本里务必加退避重试，不要拿到报错就死循环重发 |
| 接口细节 | 具体路径与参数以官方接口文档为准 |

## 连通之后的验收顺序

从「连得上」到「跑得动」是两层。按下面的顺序逐层验，出问题时才能定位到具体哪一层。

| 验收项 | 怎么验 | 合格的样子 |
|---|---|---|
| 线路连通 | 线路可用性检测里填节点跑一遍 | 握手通过，返回实测延迟 |
| 出口归属 | IP 综合检测中心看归属地与机房 / 住宅识别 | 出口国家与所选节点一致 |
| 协议可用 | 用目标业务客户端实际发一次请求 | 请求正常返回，不报认证失败 |
| 稳定性 | 连续跑一轮业务动作 | 不出现中途掉线或出口跳变 |

四步都过了再接业务。**反过来做——先上业务、出问题再回头验——会把线路问题和业务问题混在一起，排查成本翻好几倍。**

## 常见问题（FAQ）

**Q：Socks5 和 HTTP 要分别提两次节点吗？**
A：不用。两者共用同一组地址、端口和账号密码，只改客户端里的「代理类型」那一栏。只有游戏协议那条路需要另填一套带加密方式的参数。

**Q：复制下来的地址，过几天会不会自己变？**
A：静态长效住宅的出口不自动跳，一条线路用一段时间。所以那组信息可以长期用；要换出口是主动动作，不是自动发生。

**Q：客户端一直报「认证失败」，先查哪里？**
A：先看协议栏和字段对不对得上——用 ss:// 参数去填 Socks5 代理是最常见的成因。其次是账号密码是不是平台生成的线路账号，而不是登录官网用的那套。

**Q：软路由整机接管后，下面所有设备都是同一个出口吗？**
A：是。整机接管意味着下级设备共用同一条出口，换节点会一起变。要给不同设备分不同出口，得在设备侧分别配，或者放弃整机接管。

**Q：什么时候该从手动提取换成 API？**
A：节点数量上到几十条、或者要跟着业务节奏批量轮换时才值得。只有一两条线路时，手动提比写脚本更快。
