# 两个客户端都亮着灯，出口却只有一个

跑满一个模拟器窗口再打开游戏加速器，两次查到的出口 IP 是同一个——这不是巧合，而是两条链路里只有一条真的在转发流量。游戏加速器和代理客户端可以同时安装、同时启动，但它们都会往系统里插一条 0.0.0.0/0 默认路由，同一时刻只有接口跃点数（InterfaceMetric）更小的那一条在真正转发，另一条只是控制连接还活着。

**能同时开的前提是：至少有一方不去接管默认路由。** 这一点决定了后面所有排查的方向。

## 先分清：加速器和代理客户端其实在做同一件事

游戏加速器和代理客户端在 Windows 上干的是同一件事——把出站流量从物理网卡「借走」，拐进自己的链路。常见实现有两条路：新建一块 TUN/TAP 虚拟网卡，再往系统路由表里插一条 0.0.0.0/0 默认路由，让全部出站流量改从这块网卡离开；或挂一层 WFP（Windows Filtering Platform）过滤驱动，在网络栈内部直接改写目标地址。

两条路都会踩到同一块地方：默认路由和本地 DNS。Windows 判断「两条默认路由谁赢」的规则很朴素——接口跃点数小的优先，数值一样时才比路由自身的 metric。两个客户端各插一条，就必然有一条在睡觉。

| 现象 | 真实原因 | 一句话判据 |
|---|---|---|
| 两个图标都是绿的 | 只有控制连接活着，业务流量没走 | 两个客户端各跑一次出口 IP 检测，结果相同说明只生效一条 |
| 关掉加速器后网页打不开 | 网卡 DNS 被客户端改成了一个没人应答的地址 | 把网卡 DNS 改回自动获取，再刷新解析缓存 |
| 后启动的客户端连不上 | 本地监听端口撞车 | 查 1080 / 1081 / 7890 / 2080 的占用进程 |

还有一类容易忽略的差别：SOCKS5 以 TCP 为主，要转发 UDP 得客户端支持并开启 SOCKS5 UDP ASSOCIATE，不少工具默认关着；而游戏局内实时对战、语音、部分登录流程大量走 UDP。L2TP/PPTP 是整机隧道，一张虚拟网卡接管全部流量，TCP/UDP 通吃，代价是它同时改写默认路由与 DNS，代价是灵活性。所以「用代理替代加速器」这句话，在 UDP 重的场景里并不成立。

## 冲突点只有四处，按底层到上层的顺序看

不用一个个试开关看效果。下面四处按「越靠近网卡越先看」的顺序排，前一处过了再看下一处，基本不会走回头路。这套顺序的价值在于：多数「连不上」其实是路由层面的问题，把顺序搞反会在端口上折腾很久。

| 顺序 | 冲突点 | 会看到什么 | 怎么确认 |
|---|---|---|---|
| ① | 默认路由写入顺序 | 两个都显示已连接，其中一个流量明显没走 | 看路由表里 0.0.0.0/0 的第一条指向哪块网卡 |
| ② | 虚拟网卡叠加 | 适配器列表多出两块「以太网 X」，描述带 TAP/TUN/Wintun 字样 | 列出全部适配器，数虚拟网卡数量与启用状态 |
| ③ | 本地监听端口撞车 | 后启动的报「端口已被占用」，或能启动但端口指向了别人 | 查 1080 / 1081 / 7890 / 2080 被哪个进程占用 |
| ④ | DNS 被改写 | 加速器能连、游戏能进，但浏览器打不开网页 | 看网卡 DNS 字段，再用两个不同 DNS 解析同一域名对照 |

第②条常被误读成「装了两个软件所以网卡多」。虚拟网卡本身不是问题，信号是两块虚拟网卡同时在位且都处于启用状态——那意味着两个客户端都在改写网络栈。第④条是「关掉加速器后网页还是打不开」的典型成因：DNS 被改成客户端自己的解析地址，客户端退出后这个地址没人应答，但网卡配置还留着。

## 四种接管模式交叉下来，只有一种配法最稳

把「加速器怎么接管」和「代理怎么接管」两个维度交叉，结论很集中：只要两边都不去抢默认路由，就能和平共处。

| 加速器模式 | 代理客户端模式 | 结果 | 说明 |
|---|---|---|---|
| 全局（接管默认路由） | 全局（接管默认路由） | ✗ 只有一个生效 | 两条默认路由并存，跃点数小的赢，另一条只是「表面连着」 |
| 全局 | 只代理指定进程 | ✅ 可用 | 加速器管整机，代理只把模拟器或浏览器引到本地 SOCKS5 |
| 只对指定游戏生效 | 全局 | ⚠️ 能跑但不稳 | 代理整机接管后，加速器只能对目标进程插队，先启后启结果可能相反 |
| 只对指定游戏生效 | 只代理指定进程 | ✅ 最稳 | 谁都不碰默认路由，各管各的进程，启停顺序也不影响 |

一条例外：整机隧道形态的代理（L2TP / PPTP 拨号）不在上表范围内。它建的是系统级连接，会同时改默认路由和 DNS，跟加速器属于硬碰硬，实务上按「二选一」处理更快。

## 想让代理只服务模拟器，改的是模式而不是参数

核心动作只有一句：把代理客户端切成「按进程」或「按规则」分流，只把目标进程引到本地 SOCKS5，不让它接管默认路由。主流客户端都支持，差别只在菜单名字。

| 客户端 | 分流做法 |
|---|---|
| SSTap / SSTap-Beta | 模式选「进程」，把模拟器主进程加入代理列表，其余走直连 |
| NekoBox | 用路由规则或进程规则，单独指定目标进程的出站为本地 SOCKS5 |
| Proxifier | 新增规则：目标选模拟器进程，动作走本地 SOCKS5，规则顺序放最前 |
| 带规则模式的通用客户端 | 把游戏与加速器进程加入直连白名单，只放模拟器、浏览器进代理 |

配完回到上一节第①条复查一次：默认路由的第一条应该仍指向加速器或物理网卡，TUN 只在有进程命中规则时才参与。如果默认路由被代理抢走了，多半是模式留在了全局。

只是给模拟器或浏览器换一条出口的话，预算可以压得很低：公开价格对比页显示，共享档起步 2.24 元/月起，面向游戏与视频加速的独享档大约 2.8 元/月起，需要整机 L2TP 的档位普遍在 10 元/月上下，独享定制类在 28–38 元/月。价格以后台实时显示为准。

## 本机自查五步，顺序不能颠倒

下面五步都在 Windows 本地执行，PowerShell 窗口就够，整套跑完通常两三分钟，比反复开关客户端试错快得多。

| 步骤 | 要看的东西 | 正常 / 异常判据 |
|---|---|---|
| 1. 列适配器 | 一共几块、哪几块是虚拟的（描述含 TAP / TUN / Wintun / 加速器字样） | 虚拟网卡 ≥ 2 块且都启用 → 两个客户端都在改写网络栈 |
| 2. 看默认路由归属 | 0.0.0.0/0 按接口跃点数升序排，第一条指向哪块网卡 | 第一条指向加速器网卡 → 加速器赢；指向 TUN → 代理赢 |
| 3. 看端口占用 | 1080 / 1081 / 7890 / 2080 分别被哪个 PID 占用 | 同一端口出现两个 PID，或端口属于意料之外的进程 → 冲突 |
| 4. 看 DNS 配置 | 活动网卡的 DNS 服务器字段 | 变成 127.0.0.1 或某段内网地址 → 有客户端接管了解析 |
| 5. 对照解析结果 | 用系统 DNS 与公共 DNS 各解析一次同一域名 | 两次结果不一致 → 解析路径被改写，先恢复 DNS 再谈其他 |

顺序不要颠倒：先确认默认路由归谁，再去查端口。端口占用只影响那一个本地代理端口，不会让整机断网；真正让「换了 IP 却还是本地出口」成立的，是路由第一条。

## 有几种场景不用纠结，直接二选一

共存方案不是万能的。联机竞技、反作弊严格的游戏，出口同时被两条链路改写本身就是「网络环境异常」的信号，只留加速器更干净；要走整机隧道（软路由、多窗口共用一条出口），L2TP 拨号与加速器都在抢默认路由，共存没有收益；既要低延迟打游戏又要给模拟器换出口，则按上表最后一行的配法，各管各的进程。

如果业务里 UDP 占比高（实时对战、语音、部分推流），又确实需要换出口，优先考虑带 L2TP 的档位而不是 SOCKS5 单条，因为整机隧道不需要逐个客户端配规则。

## 常见问题

**Q：两个客户端都开着，怎么快速判断现在走的是哪条出口？**
A：先各跑一次出口 IP 检测做对照。两次结果完全一样，说明只有一条在生效，另一条只是控制连接活着；两次不一样，说明它们真的在分别接管不同进程。想更确定就看默认路由第一条指向哪块网卡。

**Q：代理客户端显示「已连接」，但游戏里查到的 IP 没变，是什么原因？**
A：最可能是它没抢到默认路由——加速器的接口跃点数更小，流量仍从加速器出去。其次是模式停在「只对指定进程生效」，而游戏进程不在名单里。先看路由表第一条，再看模式设置。

**Q：关掉加速器之后网页还是打不开，怎么办？**
A：先看网卡 DNS 字段是不是被改成了一个没人应答的地址，改回自动获取后刷新一次解析缓存；顺手确认默认路由第一条已经指回物理网卡——有些客户端退出时不会清理自己插的路由。

**Q：L2TP 形态的代理能不能和加速器一起用？**
A：基本不行。L2TP 是系统级拨号，会同时改写默认路由和 DNS，跟加速器的冲突最直接，按「二选一」处理更省时间。确实两个都需要，就换 SOCKS5 形态，用进程分流把它们错开。

**Q：模拟器多开时，能不能给不同窗口配不同出口？**
A：取决于客户端是否支持按进程分流。支持的话，把每个模拟器实例的主进程分别指向不同的本地 SOCKS5 端口即可；不支持就只能整机一个出口，这也是选客户端时该先确认的一条。

**Q：换 IP 之后出口没变，是 IP 本身的问题吗？**
A：先排除路由归属再谈线路质量。默认路由还在加速器或物理网卡上时，换多少条 IP 都是同一个出口。用线路可用性检测核对真实出口，比反复换 IP 有效。
