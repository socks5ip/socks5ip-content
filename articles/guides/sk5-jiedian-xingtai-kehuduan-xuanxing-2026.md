# SK5 节点怎么管：三个客户端吃的东西不一样

节点是整段复制来的，还是逐项字段抄下来的？这一个差别，基本决定了你该装哪个客户端。同一批 SK5 线路，国内起步价可能只有 **2.6 元/月**，可整段粘贴和逐条手工填，花掉的时间差好几倍。选客户端之前，先回去看一眼后台「导出」按钮给你的究竟是什么。

## 后台给你的东西，只有三种形态

| 形态 | 长什么样 | 导入方式 |
|---|---|---|
| 整段文本 | 多行内容，每行一套主机、端口、账号、密码 | 一次性整段粘贴 |
| 订阅链接 | 一条以 http 开头的地址 | 填进订阅栏，由客户端拉取 |
| 单条字段 | 分成若干独立的输入框或表格列 | 逐项手工填 |

形态由平台决定，不是你能挑的。很多人把「能不能一次导进去」当成客户端的能力问题，其实先看是哪一种形态更省事。

## 三个客户端各认哪一种

| | 大白加速器 | NekoBox | Postern |
|---|---|---|---|
| 主打形态 | 整段 SK5 文本 | 订阅与配置文件 | 规则在前，字段在后 |
| 批量导入 | 支持，粘贴即入列表 | 走订阅或文件导入 | 手动添加为主 |
| 检测能力 | 内置批量检测 | 内置连通性测试 | 依赖规则命中 |
| 上手成本 | 低，三步跑通 | 中，要理解订阅与配置 | 偏高，先设计规则 |
| 适合谁 | 手上是一串现成节点 | 有订阅来源、节点常更新 | 需要按应用或域名分流 |

## 大白加速器：吃的是整段文本

它的定位很窄——把节点导进来、连上、断开。安装包约 6.9 MB，只跑 Android 7.0 以上。拿到一整段 SK5 文本时，它是三者里最快的：复制、粘贴、核对条数，三步完成。**验收信号是导入条数与文本行数一致**，少进来的那部分通常是分隔符被改动过。

## NekoBox：吃的是订阅和配置文件

如果你的节点来源会变，或者平台给的是订阅地址，NekoBox 更合适。它的强项是把订阅当作单一入口，换节点不用重粘。代价是要先弄清「订阅」和「单条节点」在它界面里的位置不同，第一次配置会多花几分钟。

## Postern：规则在前，字段在后

Postern 的思考方式不一样：先决定哪些应用的流量要走哪条线，再往规则里塞节点。**适合要按应用分流的人**，不适合只想整串导入的人。用它去管一堆现成 SK5 节点，等于用分流器的复杂度处理一份清单。

## 一次导入当验收，别用「能不能连上」当标准

| 验收项 | 通过的样子 |
|---|---|
| 导入条数 | 与文本行数一致，不差条 |
| 检测结果 | 有延迟数值的条目占多数 |
| 出口核对 | 检测页显示的落地地址与节点归属一致 |
| 断线恢复 | 断开再连，列表与选中项都还在 |

四项里前三项一次就能跑完，别只测「能不能打开网页」。

## 三种容易选错的情况

| 情况 | 为什么错 | 该换成 |
|---|---|---|
| 手上是订阅链接，却装了只认整段文本的客户端 | 订阅进不去或只能当一次性文本用 | 换能吃订阅的客户端 |
| 只有一条节点，却上了规则分流工具 | 复杂度全花在配置上 | 换成三步跑通的轻量客户端 |
| 要按应用分流，却选了最轻的客户端 | 做不到按应用区分 | 换成规则优先的客户端 |

## 常见问题

**Q：怎么判断后台给我的是哪一种形态？**
看点「导出」之后出现的内容：多行、每行一套四项的是整段文本；只有一条 http 地址的是订阅；分成若干独立框的是字段。

**Q：整段文本粘进去只进来一半，怎么办？**
多半是粘贴过程中换行或分隔符被改动。回到后台重新复制一次，按原样整段贴，导入后对着条数核一遍。

**Q：订阅链接能不能直接塞进只认文本的客户端？**
不能当订阅用，最多只能当成一次性的节点文本，而且节点更新后要重新导。节点来源会变的话，直接选支持订阅的客户端。

**Q：三个客户端哪个最快上手？**
手上是一串现成节点、只要求连上就用的，轻量那个最快。需要按应用分流的，慢一点是必然的代价，不是客户端做得差。

**Q：客户端要花钱吗？**
客户端本身一般免费，收费的是节点。节点按平台与档位单独购买，站内价格中心可横向比价。
