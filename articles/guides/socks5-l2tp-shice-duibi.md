# 同一批线路，SOCKS5和L2TP分别怎么配？

## 一句话结论

**同一批线路两种配法解决的是两种需求**：SOCKS5 = "某个软件走代理"（配置 2 分钟，精确到应用）；L2TP = "整台设备/整网走代理"（拨号一次，全家生效）。没有谁更好，只有你此刻要不要"整机生效"。

## 前置：同一批线路意味着什么

同一平台买的线路通常同时支持 SOCKS5 和 L2TP（账号体系共用）。这意味着你可以**同一个账号，软件场景用 SOCKS5、整机场景拨 L2TP**——两条通道共用配额，不用买两份。实测确认：多数平台支持这种"一账号双通道"。

## SOCKS5 配置全流程（单软件场景）

1. 在平台后台复制 **IP:端口 + 连接账号/密码**（注意是"连接账号"不是登录账号）
2. 打开目标软件 → 代理设置 → 协议选 **SOCKS5**
3. 填入 IP、端口、账号、密码 → 保存
4. 打开 IP 查询确认出口已变（不是本地地址）
5. 连测 5-10 次确认稳定

**实测要点**：80% 的"连不上"是协议类型选错（填成了 HTTP）或账号密码复制不全。填完先单独测一条，别批量导入后再排查。

## L2TP 配置全流程（整机/路由器场景）

**电脑/手机（系统拨号）：**
1. 后台复制 L2TP 服务器地址、账号、**预共享密钥**
2. 系统"网络设置 → 添加 VPN"→ 类型选 **L2TP/IPsec**
3. 填服务器/账号/密码 + IPsec 预共享密钥 → 连接
4. 连接成功后整机流量走隧道，IP 查询确认

**软路由（OpenWrt 等）：**
1. 新增 L2TP/IPsec 客户端，填入服务器/账号/预共享密钥
2. 注意把**管理流量排除在隧道外**（防止路由器自身失联）
3. 拨号成功 → 局域网内所有设备自动共享这条线

**实测要点**：iOS 只支持 L2TP over IPsec（必须填预共享密钥）；安卓新版对旧协议原生支持在收紧，连不上优先考虑软路由方案。家用 NAT 环境要放行 UDP 500/1701/4500。

## 两种方式实测对比

| 维度 | SOCKS5 | L2TP |
|---|---|---|
| 生效范围 | 单个软件 | 整台设备/整网 |
| 配置耗时 | 约 2 分钟 | 约 3-5 分钟 |
| 常见失败点 | 协议选错/账号填错 | 预共享密钥漏填/NAT 不放行 |
| 适合 | 采集工具、单游戏、爬虫 | 多设备、软路由、整网统一出口 |
| 灵活性 | 高（按软件开关） | 低（整机走隧道） |

## 一个常见疑问的实测回答

**Q：能不能 SOCKS5 和 L2TP 同时开着？**
能，但要小心路由冲突——两个通道同时接管流量可能互相打架（表现为时通时断）。实际做法：按场景切换（需要单软件代理时用 SOCKS5，需要整机时拨 L2TP），别长期双开。
