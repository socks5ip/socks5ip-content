# 手机能开电脑转圈：同一条代理在两端差的是四层

为什么在手机上装好客户端就能开，同一组参数搬到电脑上却只剩转圈？

因为两端配的本来就不是一套东西。同一组参数在一台机器上通、另一台上不通，多数时候与线路质量无关——一条 4 元的线和一条 10 元的线，遇到这件事的表现几乎一模一样，连转圈的样子都相同。真正换掉的是**接管入口、认证载体、协议实现、网络栈**这四样，而它们在手机和电脑上从来不是同一套。

| 现象 | 优先查哪一层 | 典型成本 |
|---|---|---|
| 一端报错、另一端正常 | 接管入口 / 认证载体 | 0 元（改配置） |
| 手机流量通、Wi-Fi 不通 | 白名单绑定的出口 IP | 0 元（换认证方式） |
| 能拨上、网页打不开 | 私有 DNS / MTU | 0 元 |
| 两端都不通 | 线路或授权本身 | 4–10 元/月换线 |

数据来源：全网低价IP 整理（2026-11-28）；价格取自站内各平台价格表页，以平台后台实时显示为准。

## 先各测一次，别急着换线

三个动作五分钟出结论：把 host、端口、账号、密码原样复制到两端，**协议保持一致**（一边 SOCKS5 一边 L2TP 比出来的是两种技术的差别）；两端各打开一次 IP 综合检测中心看出口与属地；写下当时的网络是蜂窝、Wi-Fi 还是公司网。

| 两端看到的情况 | 指向 | 下一步 |
|---|---|---|
| 出口 IP 相同，只有一端报错 | 那一端的客户端或系统层 | 查接管与认证 |
| 出口 IP 完全不同 | 有一端没走代理，或被改走别的出口 | 查客户端分流规则 |
| 手机流量通、Wi-Fi 不通 | 白名单绑的是 IP，蜂窝出口变了 | 换认证方式或固定出口 |

## 接管入口：手机系统里没有 SOCKS5 这一项

iOS 的 Wi-Fi 设置里能填的只有 HTTP 代理，主机加端口，类型里没有 SOCKS5；Android 的 Wi-Fi 高级选项同样是 HTTP 代理。想在手机上用 SOCKS5，必须装客户端，由它在系统里建一条本地隧道再把流量导进去。

| 系统 | 原生 SOCKS5 入口 | 支持账号密码 | 常见做法 |
|---|---|---|---|
| iOS | 无 | 无 | 装客户端建隧道 |
| Android | 无（仅 HTTP 代理） | 无 | 装客户端或 App 版 |
| Windows | 有，但不带认证 | 无 | 白名单免密，或装第三方客户端 |
| macOS | 有 | 有 | 系统设置直接填 |

Windows 那一行是最大的误判源：Internet 选项里确实有 SOCKS 字段，地址端口都能填，可它没有用户名密码的位置。带认证的 SOCKS5 填进去只会一直转圈，最后超时——这跟线路没关系，是那一栏给不出凭据。

## 白名单认的是此刻的 IP

白名单绑的是当下这个出口 IP，跟账号无关。家用宽带多数拨号后长期不变，加一次能管很久；手机走蜂窝就不一样，运营商地址池按需分配，飞行模式切一次、跨个区、进个电梯掉回 4G，出口就换了，平台那头看到陌生地址就拒。

| 认证方式 | 手机蜂窝 | 手机 Wi-Fi | 电脑固定宽带 |
|---|---|---|---|
| IP 白名单 | 基本不可用（出口会变） | 可用 | 可用 |
| 账号密码 | 可用 | 可用 | 需支持认证的客户端 |
| 链接内嵌免密 | 取决于客户端 | 可用 | 可用 |

手机上还有个小坑：密码里的特殊字符容易被输入法改成全角或自动大写，看上去一模一样，实际差一个字符。建议直接粘贴，或者给账号设一个纯字母数字的密码。

## 同一个协议，两端不是一家写的

Windows 内置支持 PPTP、L2TP/IPSec、SSTP、IKEv2；macOS 从 10.12 起拿掉了 PPTP，iOS 从 iOS 10 起也不支持 PPTP，Android 12 起系统自带的隧道客户端同样去掉了它，部分定制系统连 L2TP/IPSec PSK 的入口都不在系统设置里。所以「同一条 L2TP」在 iPhone、安卓、Windows 上是三种不同的东西，报错自然也不一样。

| 协议 | Windows | iOS | Android | 跨网络穿透 |
|---|---|---|---|---|
| SOCKS5 | 需客户端（带认证） | 需客户端 | 需客户端 | 最好（单 TCP 端口） |
| L2TP/IPSec | 内置 | 内置 | 部分机型已移除入口 | 一般（UDP 常被封） |
| PPTP | 内置 | 已移除 | 已移除 | 差，不建议 |

L2TP 靠 UDP 1701 承载，IPSec 协商还要用 UDP 500 和 4500。公司网、酒店、校园网经常把这类 UDP 一起封掉，家里宽带和手机流量却放行——表现是同一位置电脑拨不上、手机也拨不上，回家全好。Windows 报 789 多数出在协商阶段，先换网络试一次，能拨上就说明是网络封了端口。

## 隧道通了页面不开：三处埋雷

| 症状 | 落在哪一层 | 怎么验证 |
|---|---|---|
| 先转几秒才出内容 | IPv6 优先回落 | 关掉该端 IPv6 再试一次 |
| 隧道通、网页打不开 | 私有 DNS 或私密代理 | 关掉私人 DNS 后重开页面 |
| 小页面正常、大文件卡住 | MTU 偏大 | MTU 调到 1400 或 1300 复测 |

蜂窝网络普遍双栈且 IPv6 优先，代理只给 IPv4 地址时，部分 App 会先试 IPv6、超时再回落，表现出来就是手机转圈几秒才出内容，而很多家用路由器默认关了 IPv6，电脑反而更快。L2TP over IPSec 的有效 MTU 常在 1400 上下，手机开热点共享给电脑时还会再小一截——小页面能开、图片传一半停住，就是这一层。

## 四步把范围缩到一层

| 步骤 | 动作 | 判据 | 结论 |
|---|---|---|---|
| 1 | 两端同参数各连一次 | 是否只有一端失败 | 都失败 → 查线路 |
| 2 | 两端看出口 IP | 号码是否一致 | 不一致 → 查分流 |
| 3 | 看认证方式 | 白名单里的 IP 对不对 | 不对 → 换认证或出口 |
| 4 | 换网络复测 | 换网后是否变好 | 变好 → 网络侧封锁 |

四步走完仍不通，才动 DNS 与 MTU；这两项只在「隧道通、页面打不开」时才有意义，在连不上阶段改它们属于无效操作。

## 什么时候别折腾

两端都不通、且换网络也没变化，那已经不是设备端的事，是线路或授权本身。这时候继续在两端改配置，只会把可复现的状态改乱。判断方法很朴素：用同一条线在新装的一台设备上试一次，通说明原来那台有残留配置，不通说明该换线——换线的成本是每月几元，排查的时间成本远高于它。

## 常见问题

**Q：手机能上电脑上不了，是买到假线路了吗？**
A：多数不是。先看两端出口 IP 是否一致：一致说明线是好的，问题在那一端的接管或认证；不一致说明有一端压根没走这条线。

**Q：Windows 系统代理里填了 SOCKS5 地址，一直转圈怎么办？**
A：那一栏没有账号密码的位置，带认证的线路填进去必然超时。要么装能写认证的客户端，要么把这台机器的出口 IP 加进白名单走免密。

**Q：iPhone 上能用 SOCKS5 吗？**
A：系统设置里没有这个类型，只能用客户端。客户端在系统里建本地隧道，再按规则把流量导进去，App Store 里几款常见工具都支持。

**Q：同一条 L2TP，公司能拨家里不行，是谁的问题？**
A：多半是网络侧封了 UDP 1701 或 500/4500。换一个网络能拨上就说明是端口策略，不是账号问题；跨网络场景优先用 SOCKS5，它只走一条 TCP。

**Q：手机连上就转圈几秒才出内容，怎么破？**
A：先关掉那一端的 IPv6 再试。蜂窝网络普遍 IPv6 优先，代理只给 IPv4 时会先超时再回落，几秒的等待就出在这一步。
