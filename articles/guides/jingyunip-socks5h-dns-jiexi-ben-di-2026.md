# 换 IP 只换了一半：socks5 后面少个 h，解析还在本地

把后台导出的那串凭据粘进客户端，出口一栏写着深圳，DNS 那一栏却仍是郑州。

同一个账号、同一条线，差的只是地址开头那一个字母：写成 `socks5://`，域名由本机先解析成 IP 再交出去，解析请求打的是你家宽带；写成 `socks5h://`，域名原样交给代理服务器，由它那一侧解析。检测站把两件事分开记录，一份记**出口归属**、一份记**解析来源**，于是出现了最别扭的那种状态——**出口深圳、解析郑州**。鲸云把「DNS 跟随出口」做成了服务端能力，官方自检示例写的正是 `socks5h://`，说明这个能力要客户端配合才生效。

| 环节 | 谁在发请求 | 检测站看到什么 |
|---|---|---|
| 解析域名 | 默认是本机（系统 DNS 或加密 DNS） | 解析来源 IP、城市、运营商 |
| 建立连接 | 代理服务器出口节点 | 目标站看到的来访 IP、ASN、机房还是家宽 |
| 页面脚本回连 | 浏览器，可能绕过代理 | WebRTC 暴露的本地网段地址 |

数据来源：全网低价IP 抓取鲸云官网（www.51tcp.com）DNS 说明与自检示例，核对日期 2026-11-28。

## 那个 h 改的是地址类型字段

SOCKS5 的请求报文里有一个地址类型字段：填 IP 是一种，填域名是另一种。用 `socks5://` 连，代理收到的永远是一个已经算好的 IP，它无从知道你要访问哪个域名，也就没法用自己的 DNS 去解析；用 `socks5h://` 连，代理收到的是一串域名字符串，解析发生在它那一侧，出来的记录自然带着它的出口归属。

| 写法 | 解析在哪发生 | 两栏是否同源 | 典型用途 |
|---|---|---|---|
| socks5:// | 你的本机 | 否，城市常不一致 | 内网访问、依赖 hosts 的老工具 |
| socks5h:// | 代理服务器 | 是，两栏应同城 | 需要出口与解析一致的业务 |
| http 代理 | 多数是本机 | 多数为否 | 只做端口转发的临时调试 |

这件事的代价不只是「隐私」这么抽象。做店铺后台、社媒运营、评论采集这类活，判断一条线干不干净从来不是单看 IP，而是看几份记录能不能互相印证。出口在深圳、解析在天津，等于自己多交出一句「这个人不在深圳」——它未必立刻触发什么，但它是白白多出来的一处不一致。

## 鲸云那句话成立的前提

官网原文有两句：「全部 IP 均支持 DNS 检测。域名解析跟随出口节点完成，检测网站看到的 IP 归属地和 DNS 归属地一致。」紧接着一句对比：「普通代理：出口在深圳，DNS 还在郑州。鲸云：出口在深圳，DNS 也在深圳。」

这两句说的是同一件事的两面：能力在服务端，结果取决于调用方式。更能说明问题的是它给的自检命令——官方示例写的是 `curl -x socks5h://账号:密码@网关:端口 ieb.cc`，而不是 `socks5://`。写文档的人不会无故多打一个字母，只有远端解析，输出里的 `dns_server` 与 `dns_geo` 才是出口那一侧的。

顺带分清另一套机制：首页还讲「网关域名由智能 DNS 解析，你是电信就返回电信入口」，那是入口就近接入，解决绕路和延迟，和「解析跟随出口」不是一件事。

## 五处开关，名字各不相同

能不能远端解析，取决于你用的软件暴不暴露这个开关。

| 环境 | 开关在哪 | 默认 |
|---|---|---|
| curl | `--socks5-hostname` 或代理写 `socks5h://` | 看写法 |
| Python requests | 代理串写 `socks5h://` | 看写法，`socks5://` 即本地 |
| Firefox | `network.proxy.socks_remote_dns` 置 true | 可设，需手动打开 |
| Proxifier | 名称解析里的「通过代理解析主机名」 | 可设，默认关闭 |
| 软路由分流插件 | DNS 转发链路里是否启用域名直投 | 视规则而定，最易忽略 |

最后一类要单独提醒：软路由做分流时，域名往往在本地就被判断完该走哪条线，再以 IP 形式转出去。这种结构下出口能对、解析很难对，因为它本来就是靠本地解析做决策。在意 `dns_geo` 这一栏的话，要么改成域名直投规则，要么把这条线放到终端上单独用。

还有一处容易误判：机器上开了加密 DNS，解析会绕开系统设置直接走加密通道，这时候即使客户端写的是 socks5h，`dns_geo` 也可能落在本地——那是加密 DNS 抢在前面做完了。排查前先把它关掉再看一遍。

## 三种情况要故意把解析留在本地

内网域名只有你所在那张网认识，公司 OA、局域网打印机管理页、127.0.0.1 这类地址，交给代理服务器去解析当然查不到。很多人在开远端解析后发现本地服务打不开，以为代理坏了，实际只是解析被送到了一个不认识这些名字的地方。

第二种是 hosts 文件：本机写了一条映射，远端解析看不到这个文件，只会去公共 DNS 问，答案完全不同。做本地联调、或用老工具做域名劫持的都会撞上。

第三种算半个例外——本地做分流时，规则表里「国内直连、国外走代理」这个判断本身就得靠本地解析完成，强行远端解析等于把规则废掉。真在意 `dns_geo`，正确做法是给这条线单独配一个浏览器实例，而不是把整台机器的解析全推过去。

## 自测口径：同一条线跑两遍

| 字段 | 读的是什么 | 对不上说明什么 |
|---|---|---|
| exit_geo | 出口 IP 的归属城市与运营商 | 不是你选的城市：地区选错或节点池按省分配 |
| dns_server | 这次解析实际用了谁 | 是本地地址：解析根本没走代理 |
| dns_geo | 该 DNS 的归属地 | 与 exit_geo 不同城：就是本文要修的那项 |
| webrtc | 浏览器暴露的本地地址 | 有本地网段值：浏览器没走代理 |

把后台那串凭据拆开填进去，同一条线跑两遍：一遍 `socks5h://`、一遍 `socks5://`，把两次的 `dns_geo` 摆在一起看，差在哪一目了然。这一步一分钟，比任何说明都直接。

## 常见问题

**Q：socks5h 里的 h 是不是加密更强的意思？**
A：不是。h 是 hostname，指把域名交给代理解析，跟加密强度无关。SOCKS5 本身不加密流量，加不加 h 只改解析在哪一端完成。

**Q：后台导出的节点粘进客户端，默认是本地解析还是远端解析？**
A：导出的是 IP、端口、账号、密码四段，宿主地址通常直接给 IP，所以默认是本地解析。想让解析跟着出口走，得改用域名入口，或者打开客户端的「通过代理解析」选项。

**Q：两栏同城了，为什么站里还是显示国内版？**
A：那是另一层的问题。解析对齐只解决「在哪解析」，页面按哪国版本渲染还取决于出口 ASN 与 CDN 调度。先看 ASN 是机房还是家宽，再谈换档。

**Q：开了远端解析，本地服务打不开了怎么办？**
A：给那条线单独留一个例外，或者在本机分流规则里把内网域名排除。内网名字只有你那边的 DNS 认识，远端解析必然失败，这不是配置错。

**Q：价格表上家庭 A/B 区带宽到底是多少？**
A：同一页给的是 10Mbps，对比表写 3–5M，教程页写 5–10M。按区间理解，别按峰值做容量规划；切换额度以「每月 30 次免费」为准。
