# 先数三个数，再翻价格表

怎么知道自己的业务该买哪一档？先别翻价格表——把并发数、会话时长、每月 IP 消耗量这三个数写出来，档位基本就自己浮出来了。价格表上写着带宽、线路、地区，但真正决定档位的是这三个与价格无关的数。**站内 23 家平台月卡最低 2.24 元/月起**，住宅出身普遍落在 6-10 元/月，带 L2TP 入口的档位多在 10 元一线，独享定制档集中在 28-38 元/月，海外线路按条计价、起价约 12 元/条。顺序反了，买回来的就是自己用不上的资源。

## 一句话结论

同一个 6 元档，买对了是能长期挂机的主力线，买错了是三天两头掉线的鸡肋；同一条 5 元档，切换额度给 30 次和给 500 次，适用的业务强度差出十几倍。**选档的正确顺序是：先数并发，再确认会话时长与出口身份要求，最后才看带宽与价格。**大多数「买贵了」的案例，都是把第三件事提到了第一步。

| 要先数清的数 | 它决定什么 | 数不清时的典型误判 |
|---|---|---|
| 并发：同时需要几个互不相同的出口 | 要不要独占、带宽下限在哪 | 以为「多开」只是软件里的一个开关，买一条线硬分给十个窗口 |
| 会话时长：一次要连续挂多久不断 | 该选动态线还是静态线，要不要 L2TP | 只盯带宽数字，忽略路径抖动，挂了六小时断一次就白跑 |
| 每月 IP 消耗量：一个月用掉多少条 | 切换额度够不够，该买月卡还是日卡周卡 | 拿月卡的固定额度去跑采集，几天就换完，剩下时间只能干等 |

这三个数还会互相牵制：并发越高，单条 IP 上的压力越大、被目标限制得越快，每月的 IP 消耗量也跟着涨。所以「我并发是 20」这一个条件，往往就把候选档位压缩到很小的范围里。

## 一、五类业务把这笔账算成一张表

| 业务类型 | 最吃紧的指标 | 该配的线路 | 起步档位落点 | 买错的典型症状 |
|---|---|---|---|---|
| 多账号运营（店铺 / 社媒矩阵） | 出口身份 + 独占 | 长效静态或住宅静态，一账号一条 | 6-10 元/月 | 用共享机房段，登录就被要求二次验证 |
| 数据采集与爬虫 | 每月切换额度 + 并发 | 动态机房或动态住宅 | 3-6 元/月 | 额度几天耗尽，任务停在半途 |
| 游戏多开与挂机 | 延迟抖动 + 长连接 | 静态住宅或机房，一窗一出口 | 4-8 元/月 | 多窗口共享一条线，第四个起频繁掉线 |
| 抢单 / 秒杀 / 票务 | 换 IP 速度 + 池子规模 | 动态住宅，池子越大越好 | 按天或按周，10 元以内 | 用少量月卡 IP 硬扛，第一轮就被限 |
| 跨境访问 | 出口国家 / 地区 | 海外线，按条计价 | 12 元/条/月起 | 地区买错，或拿海外线跑大流量 |

四类之外还有一类容易漏掉：视频、推流、批量下载这类大流量业务。它的判据与上面五类都不同，只吃独享带宽，低价档的 1-5M 是硬上限，超了就是排队和断流，合理落点通常在独享定制档，价格集中在 28-38 元/月；如果一个月只在几天里跑，按天买比按月买更合适。

## 二、几处容易被标签带偏的地方

**住宅出身不等于干净。** 家宽段里同样存在被反复使用过的地址，是不是干净只能实测，靠档位名称判断容易踩空。

**采集类业务不吃带宽，吃额度。** 带宽只要跟得上解析速度就够，真正的硬上限是一个月能换多少条 IP。把额度折算成成本会更有用：一条 5 元上下、赠送 30 次切换的线路，每次更换约 0.17 元；同价位若能拿到 500 次，单次成本会掉到 0.01 元量级。**同样是「5 元档」，适合的业务强度差出十几倍。**

**游戏线不看带宽。** 多数游戏的单开实际吞吐远低于 1M，但一次几秒的抖动就足以让角色掉线。窗口数在三个以内且不要求出口身份，机房档最划算；窗口数上到五个以上又要长时间在线，就该看 L2TP 档——端口与预共享密钥由平台提供，一次配置能带多台设备，比在每个客户端里逐条填 SOCKS5 省事得多。

**抢单场景要动态住宅，不要机房段。** 机房段的整体数量远小于住宅段，热门活动期间容易整段被目标站限流，表现就是网络没断但请求被挡。另外账号数越少、每条 IP 分担的请求越少，成功率越高——加账号比加带宽有用得多。

## 三、临界点：什么时候该往上一档走

| 出现这个信号 | 判断 | 该做的动作 |
|---|---|---|
| 任务跑一段时间固定掉一次，重连就正常 | 并发或带宽到顶，不是线路坏了 | 把并发降到档位上限内，或直接跳到住宅档 |
| 换了两家平台，失败率一样高 | 出口身份问题，与平台无关 | 换住宅或长效静态线，换之前先测 |
| 每月切换次数总是提前用完 | 额度不够，与带宽无关 | 换更高额度的档位，而不是换平台 |
| 只有一两个窗口、也不需要特定出身 | 不要向上跳档 | 留在最低档，预算留给免费测试额度 |
| 一个月里真正用的只有几天 | 按月买不划算 | 改用周卡或日卡，用完即停 |
| 目标服务只在境外可访问 | 这是地区问题，不是质量问题 | 买对应地区的海外线，别在国内线上反复试 |

## 常见问题

**Q：带宽越大的线路，跑我的业务就越稳吗？**
不一定。带宽是吞吐上限，稳定性来自路径质量与并发空间。游戏、抢单、多账号这类业务的单窗口吞吐都远低于 1M，把预算花在带宽上通常收不到效果；真正会卡带宽的只有视频、推流、批量下载这类场景。

**Q：同一个账号，IP 固定不变好还是经常换好？**
看业务类型。需要长期登录同一账号的场景，固定一条专属 IP 更安全，频繁更换反而像异常行为；采集、抢单这类本来就要轮换的场景，固定 IP 会成为瓶颈。判据是这个操作在真实用户身上会不会天天换地方。

**Q：住宅 IP 一定比机房 IP 好用吗？**
看用途。需要看起来像真实用户的操作，住宅出身更合适；纯下载、跑接口、批量抓取这类对身份不敏感的活，机房档往往更快也更便宜。

**Q：怎么在买之前就知道这一档够不够？**
两条路同时走。一是把并发数、会话时长、每月 IP 消耗量算出来，对照上面的表先筛一遍；二是用免费测试额度实测，并在买之前用检测工具看清出口类型与线路质量。

**Q：月卡和日卡周卡，什么时候该换计费方式？**
只看使用时长，与带宽无关。周期越长单位成本越低，但一个月里真正只用几天的话，按月买就是浪费。抢单、活动型业务适合按周或按天，长期挂机、矩阵运营适合按月。

**Q：为什么同一档位在不同平台价格能差好几倍？**
多数情况下不是贵的在割人。同档标的低价往往意味着更小的带宽、更少的切换次数或更长的换线等待。把带宽与切换额度一起看，再折算成每次可用成本，结论经常会反过来。
