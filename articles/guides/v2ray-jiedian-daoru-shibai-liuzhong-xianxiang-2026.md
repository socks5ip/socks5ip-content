# 导入报错不在节点上：六种现象各指向一层

把那一行 vmess 从后台复制，粘进剪贴板导入框，列表一条也没多——格式没写错的前提下，问题通常出在「解出来的那段是不是完整的一段」。

V2Ray 类客户端的导入报错，看着都是「失败」，实际分属三层：**格式层**（字符串本身不完整）、**入口层**（把网页当订阅填了）、**网络层**（格式与入口都对，就是握手过不去）。三层里只有第三层值得换线路。

## 一句话结论

**六种常见现象里，只有「节点全绿但目标站打不开」「部分节点超时」属于线路问题，其余四种换十条线路也不会好转。** 判断顺序固定：先看客户端列表有没有多出节点（格式层）→ 再确认填进去的网址返回的是不是节点列表（入口层）→ 最后用在线检测跑一遍 IP:端口（网络层）。**公开裸链接的寿命以小时计，付费固定线路按计费周期走，平台线路起价 2.24 元/月。**

| 现象 | 落在哪一层 | 该动哪里 |
|---|---|---|
| 粘完剪贴板，列表一条没多 | 格式层 | 整段重新复制，别从聊天窗口手动框选 |
| 订阅提示更新成功，节点数是 0 | 入口层 | 浏览器打开该网址，返回网页就不是订阅 |
| 有节点、全是绿的，网页打不开 | 网络层 | 出口被目标站识别，或 DNS 没走代理 |
| vmess 连上几秒就断，提示时间不同步 | 本机环境 | 打开系统时间自动同步，重启客户端 |
| trojan / vless 一律握手失败 | 参数层 | 补齐 sni / host，确认 TLS 与端口对得上 |
| hysteria2 一直超时 | 网络层 | 所处网络封 UDP，不看节点死活 |

## 格式层：先自己解一次 base64

**vmess 那一长串不是密文，是 base64 包住的一段 JSON。** 把 `vmess://` 后面那段拿去做一次 base64 解码，能读出 `add`（地址）、`port`（端口）、`id`（UUID）、`net`（传输方式）四个字段，说明字符串完整；解出来是中文字符或报错，就是复制时断了行、夹了空格或中文标点。

这一步能排掉最常见的误会：**列表没多不等于节点坏了，多数是字符串被截断。** 微信、QQ 这类聊天窗口里手动框选长文本，末尾几个字符最容易漏。

五种分享格式的差异，决定了「导入后连不上」时该查哪里：

| 格式 | 长什么样 | 导入入口 | 最常见的失败 |
|---|---|---|---|
| vmess | base64 包住 JSON，字段含 add / port / id / net | 剪贴板批量导入 | 字符串被截断；net 写了 ws 但 path 丢了 |
| vless | 明文 URI，参数挂在 `?` 后面 | 剪贴板导入 | 客户端内核太旧，直接提示格式不支持 |
| trojan | 明文 URI，密码顶在 uuid 的位置 | 剪贴板导入 | TLS 没开，或 SNI 与证书不匹配 |
| ss | base64 的「加密方式:密码」拼上主机端口 | 剪贴板导入 | 加密方式不在客户端的可选列表里 |
| hysteria2 | 明文 URI，底层 QUIC，走 UDP | 需较新内核 | 网络封 UDP，握手一直超时 |

## 入口层：订阅是一个会返回节点列表的网址

**订阅地址必须能在浏览器里打开成一大段没有标点的乱码（base64），否则它就不是订阅。** 分享网页、GitHub 仓库页、论坛帖子页，打开都是排版正常的网页，把它们的网址填进「订阅」栏，更新会提示成功但节点数是 0——客户端拿到了 HTML，当然解不出节点。

这一层的自检只有一个动作：把网址粘进浏览器地址栏，看返回什么。

- 返回一大段乱码 → 是订阅，可以填进订阅栏；
- 返回排版正常的页面 → 是分享页，只能人工挑其中一条，当单节点导入；
- 返回 404 或跳转到首页 → 地址已被撤，这一批作废。

## 网络层：只有这一层该换线路

**节点显示绿色只说明客户端连上了本地转发端口，不说明流量到了目标站。** 真正的判据是目标站看不看得见你。

用在线工具直接测 IP:端口，比在客户端里反复切换快得多：端口通、握手成功，问题在目标站那一侧的识别；端口不通，才轮到换线路。这一步做完，六种现象里能定性四种。

DNS 是另一个常被漏掉的点。本地运营商 DNS 解析出来的地址，可能与代理线路出口所在地区不一致；把 DNS 交给代理解析，或者统一改成系统默认，能修掉一批「节点全绿、网页打不开」。

## 公开源为什么当天就空

**公开页上的裸链接，寿命通常以小时计；订阅站给的地址，多则一两天。** 原因不在技术，在于这类地址被大量复用：同一批节点被几千人同时挂在上面，落地 IP 很快进入目标站的黑名单，提供者只能换新的。

按形态估算寿命，比逐个测试省事：

| 来源形态 | 典型寿命 | 复用人数 | 适合什么 |
|---|---|---|---|
| 公开页单条链接 | 数小时 | 极多 | 临时打开一个页面 |
| 公开订阅地址 | 一两天 | 多 | 试客户端功能 |
| 平台免费测试额度 | 按条计次，可领 10 条 | 仅本人 | 下单前验货 |
| 付费固定线路 | 整个计费周期 | 仅本人 | 长期业务 |

## 额度这条路的用法

**平台给的免费测试是「按条计次」，不是按时长。** 以聚合站的价格表为例，静态机房档 30 天 5 元起，住宅档 25 元，差价 5 倍——先用 10 条额度把五类线路各测一条，比盲买一档更省事。

兑换流程通常只有两步：注册后实名，再在后台领额度。领到的每一条都能单独提取地址、端口、账号、密码，配进 NekoBox 或 v2rayN 都一样，不需要订阅地址。**这也是它比公开订阅稳的地方：地址归你一个人用，不存在被别人拖进黑名单。**

## 常见问题

### 订阅导入后节点是 0，是不是订阅地址失效了？

先别下结论。把地址粘进浏览器：返回乱码是订阅、失效或格式不对；返回网页说明你填的是分享页，本来就不能当订阅。只有返回 404 或跳首页，才是地址被撤。

### vmess 导入成功但连上几秒就断，是节点的问题吗？

多数不是。vmess 校验里带时间戳，本机时间与标准时间偏差过大就会连上即断。先打开系统时间自动同步，再重启客户端；仍然断，再看 net 与 path 是否匹配。

### 节点全绿却打不开网页算什么情况？

算网络层。绿色只代表客户端连上了本地转发端口。用代理线路检测跑一遍 IP:端口，通了就查目标站识别与 DNS；不通就换一条线路测同一个目标。

### 免费节点和平台试用额度，哪个更稳？

试用额度更稳。公开节点被大量复用，落地 IP 很快进黑名单，寿命以小时计；平台额度按条计次、只给你一个人用，提取出来就是一份账密，不依赖订阅更新。

### 客户端要装几个才够？

一个就够，除非你要按应用分流。NekoBox 支持按应用走不同线路，SSTap 把整机流量接进虚拟网卡，两者定位不同。装之前先确认后台给你的是订阅、单条链接，还是一份地址端口账密。

### 换线路能修好所有导入报错吗？

不能。六种现象里只有两种属于线路问题。字符串被截断、把网页当订阅、参数缺失，这三类换多少条线路都一样，先按层级定位再动手。
