# 客户端换了一圈还没连上

连不上就换客户端，为什么大多数时候白换一场？代理链路分三层：**线路账号、内核、客户端界面**。客户端只是最上面那层皮，它负责把下面的东西喂进去；换掉它，不会让线路变得能通，八成以上的连不上都发生在第一层。

## 一、三层各自管什么，出错概率差多少

先看清三层各自的职责，才知道该动哪一层。三者的可替换性完全不同，换错层的代价也差得远。

| 层 | 它是什么 | 出问题的典型表现 | 换掉它的收益 |
|---|---|---|---|
| 线路账号 | 平台给你的 IP、端口、账号密码或订阅，决定出口归属地、类型与稳定度 | 端口不通、鉴权失败、出口不在标称地区 | 最大，多数连不上出在这一层 |
| 内核 | 真正建连接、跑分流的那一层（sing-box / Xray / mihomo） | 订阅导入报解析失败、字段不认识 | 中等，决定你认哪套配置格式 |
| 客户端界面 | 手机上点开的那个 App | 界面不顺手、分应用列表为空、备份找不到入口 | 最小，只影响操作体验 |

**判断顺序应该是自下而上：先确认线路能通，再看内核口径，最后才轮到界面。** 反过来做，就是每次换 App 都重踩一遍同样的坑。

## 二、按症状定位，别按感觉定位

同一句"连不上"，落在不同层里处理方式完全不一样。下表左边是你能观察到的现象，中间是它指向的层。

| 你看到的现象 | 指向的层 | 先做什么 |
|---|---|---|
| 客户端里节点列表全空 | 线路账号未生效或未提取 | 回平台后台看套餐是否已开通、节点是否已提取 |
| 一直转圈、最后超时 | 端口不通或出口被封 | 用真实握手检测确认端口可达性，再决定换不换线路 |
| 提示鉴权失败 / 用户名密码错误 | 线路账号参数 | 核对大小写、空格与协议类型是否与后台一致 |
| 订阅导入报"解析失败" | 内核口径 | 看订阅是 YAML 还是 JSON 格式，对应换成能吃这种格式的客户端 |
| 连上了，但分应用列表是空的 | 客户端界面 + 系统权限 | 补授读取已安装应用列表的权限 |
| 只有某个应用走不了代理 | 分流规则 | 检查该应用是否被排除，或规则组是否启用 |

第一行和第三行都属于线路层，跟装什么客户端没有关系。**把这两类问题记成"线路层"，可以省掉后面大部分无意义的尝试。**

## 三、订阅格式不通用，是"解析失败"的主因

订阅链接在客户端里导不进去，多数人第一反应是链接过期了，其实更常见的原因是格式不对口。**Clash 系客户端读 YAML 结构的订阅，sing-box 与 NekoBox 这类读自己的 JSON 结构**，把 YAML 直接丢给 sing-box 内核多半报解析错误。

| 你手上的节点 | 匹配的客户端内核 | 不匹配时的表现 |
|---|---|---|
| 机场订阅链接（YAML） | mihomo / Clash 系 | 导入报解析失败或节点列表为空 |
| Xray 核心的分享链接 | Xray 口径客户端 | 字段不认识、配置存不下 |
| 独立 SOCKS5 / HTTP 账号 | 任意支持手动加节点的客户端 | 不存在格式问题，只有参数填错 |

遇到解析失败时，先确认平台给的是哪一类格式，再换对应客户端——这比重新申请一条订阅快得多。

## 四、什么情况下换客户端是真有用的

前面讲的是"别急着换"，但确实有三种情况换了才解决问题。

| 情况 | 为什么必须换 |
|---|---|
| 设备换了平台 | 安卓版客户端在 iOS 上没有对应版本，只能改用该平台适用的客户端 |
| 要用的协议或字段新的才有 | 老客户端内核版本旧，认不了新字段，配置写进去也不生效 |
| 需要跨设备统一配置思路 | 同一项目覆盖多平台时，配置迁移成本最低 |

除这三种之外，掉线、连不上、出口不对这三类问题，都应该先回到线路层排查。**用检测工具把 IP 质量、端口连通和延迟跑一遍，通常比装三个新 App 更省时间。**

## 五、搬过去要重做的三件事

换客户端不是装完就完，下面三件少做一件，都会让人误以为是"新工具不好用"。

| 事项 | 怎么做 | 漏做的后果 |
|---|---|---|
| 先备份旧配置 | 在原客户端里导出一次配置 | 卸载后节点与分组一起丢，只能重新录 |
| 核对权限 | 安卓要补授读取已安装应用列表权限 | 分应用代理规则全部失效，看着像没生效 |
| 用测试额度验线路 | 拿平台赠送的测试线路跑通再充值 | 先付费再发现线路不合适，退起来更麻烦 |

顺带把一个常见误会说清：**换客户端不需要重新买线路。** 线路是账号层面的东西，跟你装哪个 App 无关；同一套 SOCKS5 / HTTP 账号在新客户端里照样能用，需要重填的只是配置字段。

## 常见问题

**Q：换了客户端还是连不上，最该先查什么？**
A：先查线路。端口通不通、鉴权对不对、出口在不在标称地区，这三项都属于线路层，跟客户端无关。线路确认没问题，再去看内核口径和系统权限。

**Q：同一份订阅，为什么在 A 客户端能用、B 客户端报错？**
A：客户端背后的内核不一样。Clash 系读 YAML，sing-box 与 NekoBox 读自己的 JSON 结构，格式不对口就会报解析失败。换客户端前先确认订阅属于哪一类格式。

**Q：卸载旧客户端会丢配置吗？**
A：会。节点、分组、分流规则都随应用数据一起清除。卸载或降级之前，先在原客户端里导出一次备份，几秒钟的事。

**Q：分应用代理设了没用，是什么原因？**
A：大概率是权限没给全。安卓的分应用代理需要读取已安装应用列表的权限，拒绝这一项不会影响连接，但代理列表会是空的，看起来就像功能失效。

**Q：客户端是免费的吗？**
A：安卓和桌面端有一批开源客户端完全免费，付费主要买的是 iOS 上的可用性和图形化规则管理。客户端一律免费，真正花钱的是线路——起点是 2.24 元/月，且支持先测后买。

**Q：手机和电脑能共用一份线路吗？**
A：账号层面可以，同一个 SOCKS5 / HTTP 账号在两台设备上都能填。但要注意并发数是否超了套餐上限，以及两台设备的配置字段口径是否一致。
