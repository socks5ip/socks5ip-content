# Clash 分流规则不是按类型分级：命中即止，顺序就是优先级

很多人以为规则写得越精确就越优先，Clash 恰恰不看这个：从第一行往下匹配，命中即止，排在后面的写法再精确也读不到。

**Clash 的 rules 是线性列表，第一条匹配成功就结束判断，后面的规则不再参与。** 这意味着规则类型之间不存在「精确优先」的自动排序，`DOMAIN-SUFFIX` 写在第 20 行，就一定会输给第 3 行的 `GEOIP`。写规则的本质不是选类型，是排顺序。

## 先接受一个事实：没有「优先级」，只有「先后」

很多人以为具体规则会自动优先于宽泛规则，这是最贵的误解。Clash 不会因为 `DOMAIN-SUFFIX` 比 `GEOIP` 精确就把它提前，它只按文件里的行序走。

由此可以推出两条判断方法：想让某条规则生效，就往上放；发现「规则写了一大堆都没用」，先看是不是前面有一条宽泛规则拦住了。

## 六种规则类型，精度差得很远

| 类型 | 匹配依据 | 精度 | 注意 |
|---|---|---|---|
| DOMAIN | 完整域名完全相同 | 最高 | 子域不匹配，要逐条写 |
| DOMAIN-SUFFIX | 域名后缀 | 高 | 最常用；写成 `.com` 会误伤一大片 |
| DOMAIN-KEYWORD | 域名包含关键词 | 低 | 容易误伤同名字段 |
| IP-CIDR | 目标 IP 段 | 中 | 对域名目标要先解析，务必加 `no-resolve` |
| GEOIP | 按 IP 库判国家 | 粗 | 依赖 IP 库准确度，必须放最后 |
| PROCESS-NAME | 发起连接的进程 | — | 只有 TUN 模式拿得到进程信息 |

精度高的类型不自动靠前，但把它们放在前面，能减少误伤概率——这是唯一需要记住的经验法则。

## 一条能直接照抄的排序骨架

不确定怎么排时，用下面这个顺序起步，再按业务微调。

| 位置 | 写什么 | 为什么在这个位置 |
|---|---|---|
| 1 | PROCESS-NAME（要先分流的软件） | 进程条件最精确，不受后续域名规则干扰 |
| 2 | DOMAIN / DOMAIN-SUFFIX（必须直连或必须走代理的站） | 精确意图优先于任何粗粒度判断 |
| 3 | RULE-SET（广告拦截、常用分流集） | 批量规则放在精确规则之后 |
| 4 | IP-CIDR（内网、特定机房段） | 内网段必须直连，且要加 `no-resolve` |
| 5 | GEOIP,CN,DIRECT | 国内直连，粗粒度兜底之一 |
| 6 | MATCH,代理组名 | 兜底，必须最后一行 |

骨架的价值在于「兜底永远在最后」。只要 MATCH 在末尾，前面怎么调都不会出现「全部直连」这种灾难性结果。

## 三个错误，出现一个就等于没配

1. **GEOIP,CN,DIRECT 放第一条。** 它会把所有解析到国内 IP 的域名按直连处理，包括那些你本来想走代理的站。表现是「规则写了几十条，只有第一条在工作」。
2. **IP-CIDR 漏写 `no-resolve`。** 对域名目标，Clash 需要先做一次 DNS 解析才能比对 IP 段；不加 `no-resolve` 会带来额外解析，既慢又可能泄漏真实解析请求。
3. **兜底规则指向 DIRECT。** 把 MATCH 写成直连，所有没被命中的流量都会走到本机网络。想「出问题时至少能连上」可以这么做，但要清楚这是有意的取舍，不是默认配置。

## 怎么确认一条连接命中了哪条规则

不要靠猜。Clash 的「连接」页会列出每条活跃连接与它匹配的规则，这是唯一可靠的验证入口。

操作顺序：打开连接列表 → 发起一次目标请求 → 在列表里找到这条连接 → 看它落在规则名还是 DIRECT 上。如果它显示 DIRECT 而你以为该走代理，问题就在顺序上，不在规则本身。

改完之后再验一次出口：把流量指向代理组，打开 [IP 综合检测中心](https://socks5ip.com.cn/ip-check-center/) 看归属地是否符合预期。规则配对但出口没变，通常是策略组里选错了节点。

## 规则配好之后，线路才是变量

分流只决定「谁来走」，走得好不好取决于线路本身。规则层面能做的只有一件事：把需要固定出口的业务单独分到一个组，别和日常浏览混在同一个出口里。

| 需求 | 规则怎么写 | 线路怎么配 |
|---|---|---|
| 某后台必须固定城市 | 域名后缀 → 固定组 | 该组只挂一条静态线 |
| 日常浏览走默认出口 | MATCH → 默认组 | 默认组可挂多条 |
| 内网、打印机、路由管理 | IP-CIDR + no-resolve → DIRECT | 不需要线路 |
| 采集类脚本走独立出口 | PROCESS-NAME → 采集组 | 按并发配多条 |

## 常见问题

**Q：Clash 的规则是不是越具体的越优先？**
不是。规则按文件行序匹配，命中即止，不存在「具体优先」的自动排序。想让精确规则生效，必须把它写在宽泛规则之前。

**Q：为什么我写了三十条规则，实际只有一条在起作用？**
大概率是前面有一条 `GEOIP,CN,DIRECT` 或 `MATCH`，把所有流量提前拦下了。把宽泛规则挪到最后，再逐条验证。

**Q：DOMAIN-SUFFIX 和 DOMAIN 该怎么选？**
要连子域一起覆盖就用 DOMAIN-SUFFIX，只针对某一个完整域名就用 DOMAIN。写 `.com` 这种后缀会误伤几乎所有站点，不要这么写。

**Q：IP-CIDR 后面的 no-resolve 是干什么的？**
告诉 Clash 不要为了匹配这条规则专门去做 DNS 解析。漏写会带来额外解析请求，增加延迟，也可能让真实解析结果外泄。

**Q：规则都对了，为什么访问还是走本地网络？**
检查策略组选中的节点，以及代理模式（规则／全局／直连）。规则只决定「去哪」，实际走不走取决于模式与组的当前选择。

**Q：MATCH 一定只能写一行吗？**
是。它匹配所有剩余流量，写在它后面的规则永远不会被执行。所以 MATCH 必须是最后一行，且只能有一条。
