# TCP 重传率怎么看：差值法 + 一个数量级门槛

2.4% 的重传率落在 1GB 的文件上，等于白传 24MB，而 ping 那边全程零丢包。

**一句话结论：重传率＝被重发的 TCP 段 ÷ 已发送的段，它回答「对方到底收全了没有」，比 ping 的丢包率更接近体感；判读只用两个动作——取五分钟内的差值而不是开机累计，以及要求换线前后差一个数量级才认定是线路差异，差两三成在无线环境下属于噪声。**

## 一、ping 全绿却传不完：测的不是同一条路

| 测法 | 实际测的是什么 | 能不能反映代理线路 |
|---|---|---|
| ping 目标域名 | 本机到目标的 ICMP 往返 | 不能，ICMP 不进 SOCKS5 隧道 |
| 浏览器打开一个重页面 | 连接、握手、首屏资源 | 只看得到「成不成」 |
| 持续上传或下载一个文件 | 整条 TCP 流的稳定吞吐 | 能，连续流量才暴露重传 |
| 平台后台的线路检测 | 从机房侧发起的探测 | 能，但测的是机房到目标 |

第一行是绝大多数误判的来源：**挂了 SOCKS5 之后 ping 依然直连出去**，它测的是本机到目标的 ICMP，跟隧道内部一毛钱关系都没有。所以「ping 不丢包」这条结论，对传文件卡住这件事没有解释力。

## 二、重传有三种触发，丢包只是其中一种

| 触发原因 | 表现 | 能不能自己改 |
|---|---|---|
| 段丢失 | 发送端等不到确认，超时重发 | 换线或改善本地网络 |
| 乱序到达 | 接收端收到乱序段，触发快速重传 | 多路径与跨境链路，难改 |
| 接收窗口塞满 | 对端处理不过来，发送端重发 | 换目标站或降低并发，不能靠换线 |
| 链路误码 | 无线或长距离链路比特翻转 | 换有线、换信道 |

**只有第一种和第四种是线路的锅**，第二种在跨境链路上很常见，第三种干脆跟线路无关——目标站自己处理不过来，你换多贵的线都一样。

## 三、用差值，不要用累计

| 系统 | 取数命令 | 看哪两个值 |
|---|---|---|
| Windows | `netstat -s -p tcp` | 已发送的段、已重传的段 |
| Linux | `nstat -az TcpOutSegs TcpRetransSegs` | 两个累计计数器 |
| Linux 单连接 | `ss -ti` | 连接级的 retrans 字段 |

这三个都是**累计值**。开机三天的机器上，累计重传率会把凌晨那几次波动一起平均掉，读出来的数没有意义。正确做法是隔五分钟取两次，用差值算：

重传率 ＝ (第二次重传数 − 第一次重传数) ÷ (第二次发送数 − 第一次发送数)

五分钟内至少要有几百个段的样本，否则算出来的百分比会被一两个段带偏。

## 四、一个数量级的门槛

这是最容易出错的地方：很多人看到「重传率 1.8%」就断定线路有问题，其实 1%–2% 在跨境链路上属于正常波动。

判据只有一条：**同一台机器、同一时段、只换线路，两次读数差一个数量级才算真实差异。**

| 换线前后 | 判断 | 该做什么 |
|---|---|---|
| 0.2% → 2.4% | 差一个数量级以上 | 大概率是线路，换线或换档 |
| 1.8% → 2.6% | 差两三成，噪声范围内 | 不换，继续观察 |
| 2.4% → 2.6% | 基本没变 | 问题在客户端或目标站，不在线路 |
| 都高于 5% | 两端都有问题 | 先查本地网络与目标站 |

**差两三成不值得为它换平台**，这个幅度在无线环境里一天之内就能自己变回去。

## 五、配合吞吐一起看，才有结论

单看重传率会误判：一条限速 3M 的线，重传率高但吞吐稳定，体感是「慢但不断」；一条 100M 的线重传率低，一遇到高峰就抖动，体感是「时快时慢」。

所以正确的读法是两列并看：**重传率上升的同时吞吐掉一半，才是线路问题；重传率上升但吞吐没变，多数是对端限速或并发过高。**

## 六、能自己改的三件事

1. **把测量点挪到有线网络**。无线信道的误码会让重传率凭空翻倍，先排除这一项。
2. **关掉并发**。同时开五个下载，接收窗口被塞满的概率大增，重传率跟着涨，但这跟线路无关。
3. **换一种协议形态验证**。同一档位如果同时给了 SOCKS5 与 L2TP，两个都测一次：只有一种高，问题在协议栈或客户端；两种都高，才指向线路。

## 八、常见问题

### Q：重传率多少算正常？

没有通用阈值。跨境链路 1%–2% 属于常见区间，同城链路可以低到 0.2% 以下。有意义的是同一条线在不同时段的对比，以及同机换线后的对比，绝对值只在同类型链路上才有参考性。

### Q：为什么 ping 显示 0% 丢包，重传率却有 2%？

因为两者测的不是同一条路。ping 走 ICMP，通常不进代理隧道；重传发生在隧道内的 TCP 流上，两者的路径、样本量、协议都不同，一个正常另一个异常完全可以同时成立。

### Q：Windows 上只有 netstat，看不到单连接的重传怎么办？

用 `netstat -s -p tcp` 取全局两次差值就够判断线路级问题；要定位具体连接，需要抓包工具看重传标记，普通排查用不到这一步。

### Q：换了线重传率降下来了，是不是就说明原来那条线有问题？

只有在「同机、同时段、同目标站、只换线」这四个条件都满足时才能这么下结论。少了任何一个，降下来的原因可能是时段变化或目标站负载变化。

### Q：重传率高会不会影响账号安全？

间接会。重传多意味着连接不稳定，客户端可能反复重连、出口地址频繁变化，而地址频繁变化本身就是一个信号。所以排错时先看稳定性，再看速度。
