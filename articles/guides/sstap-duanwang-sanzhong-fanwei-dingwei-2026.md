# SSTap 断网了先做什么：三种断法对应三层根因

点完连接，浏览器开始转圈，微信也发不出消息——第一步不是继续调参数，是把网先还回去。

SSTap 属于虚拟网卡那一类工具，接管的是整机流量。进程被强杀、电脑休眠、两个工具抢同一层，规则都可能留在半接管状态，于是出现「关掉了也上不了网」。**先断开并停用虚拟网卡，确认本机能正常上网，再谈代理**——顺序反了，所有排查都建在流沙上。

## 断的范围决定往哪一层查

| 断的范围 | 根因层 | 先验一件事 |
|---|---|---|
| 整机都上不了网 | 虚拟网卡 / 路由 | 能不能访问本地网关 |
| 能 ping 通、网页打不开 | DNS | 直接用 IP 访问是否能开 |
| 只有某几个站不通 | 出口被目标站拦 | 同一条线换个站试试 |
| 只有某个程序不通 | 程序自有网络栈 | 换个浏览器走同样地址 |

数据来源：站内 SSTap 配置教程与代理工具中心各工具说明，核对日期 2026-11-27。

这张表的用法只有一个：先用一个动作把范围缩到一行，再动手。范围没缩就改配置，改完还是同样的现象，你连「改了有没有用」都判断不了。

## 整机断是最严重的一类，也最容易被误判

连本地网关都访问不了，说明路由被打乱了，跟线路没有任何关系。

这时候换线路、换节点、重装客户端全是无效动作，因为数据包根本出不了本机。判断「能不能救回来」的标准很朴素：**断开 SSTap 并停用虚拟网卡之后，本地网络是否恢复**。恢复了说明只是接管没撤干净，问题范围很小；没恢复才需要往系统路由、DNS 缓存、驱动这几处查。

半接管状态是这类断网的主因。正常断开时工具会把自己加的规则撤掉；进程被强杀时来不及撤，规则就留在系统路由表里，指向一块已经停用的网卡。表现很有辨识度：客户端显示未连接，浏览器提示无法访问此网站，但同一台机器上的手机热点共享却能上网。

## 能 ping 通却打不开，几乎只指向解析

代理显示已连接、流量也确实走了，但网页打不开或打开的是错乱版本，八成是域名解析没跟着走。

验证方式很直接：用 IP 直接访问一个站点，能开就说明链路是通的、只是名字没解开。这一步能省掉大半天，因为「能 ping 但打不开」这个组合几乎只指向 DNS。

| 现象 | 更像 | 一处验证动作 |
|---|---|---|
| 网关都 ping 不通 | 路由被改乱 | 停用虚拟网卡后是否恢复 |
| 能 ping、打不开网页 | DNS 没跟着走 | 直接用 IP 访问同一站点 |
| 只有目标站报错或跳验证 | 出口被拦 | 换一条线访问同一站点 |
| 只有某个软件不走代理 | 程序自有网络栈 | 换浏览器访问同一服务 |

处理上有两条路：把解析交给远端，或把系统 DNS 换成公共解析再清一次本地缓存。两条都做完仍不行，检查有没有别的软件在接管 DNS——某些安全软件会拦截并改回自己的解析。顺带说一句，解析走本地意味着你访问了哪些域名对本地运营商可见，对隐私有要求的场景值得单独确认一次。

## 只有某站或某程序不通，问题不在接管层

同一条线打开别的站正常、只有目标站拦，是出口被标记，换线立刻好转。这一类跟 SSTap 本身无关，重装十次也不会变。

只有一个程序不通，是那个程序有自己的网络栈。浏览器扩展、下载器多线程、游戏更新器都可能在虚拟网卡之外单独发包，表现是主页面走了代理、某个模块仍然是本地地址。这类问题不给提示，只能逐个功能试。

## 速度掉到几十 KB，按线路 → MTU → 本机的顺序查

多一层封装时，MTU 不匹配的典型症状是「小页面能开、大文件卡住」：网页首屏出来，图片和视频一直转，小文件随手下完，大文件永远停在开头。

| 顺序 | 查什么 | 判据 |
|---|---|---|
| ① 线路 | 同一条线换到另一个工具跑同样目标 | 快＝线路没问题 |
| ② MTU | 看是否小页面能开、大文件卡死 | 是＝封装后包过大 |
| ③ 本机 | CPU、其他代理工具、后台更新 | 换线也一样慢＝本机原因 |

跳过第一步，后面全是猜。三种原因用三种现象一对，基本能定位；测速记得固定同一个测速点和同一时段，换来换去的数字没有可比性。

## 复原四步，别跳步

| 步骤 | 动作 | 做完应该看到 |
|---|---|---|
| ① 断开 | 客户端点断开，不要直接关窗口 | 客户端显示未连接 |
| ② 停用网卡 | 系统网络连接里禁用那块虚拟网卡 | 网卡图标变灰 |
| ③ 复位 DNS | 系统 DNS 改回自动，清一次缓存 | 网页能正常打开 |
| ④ 复查 | 打开 IP 综合检测中心看出口 | 出口回到本地或目标地区 |

四步做完再重连。跳步留下的残留会在下一次连接时叠加上去，症状从「连不上」变成「连上也没网」，更难查。装网卡这一步也有个特点：失败时几乎不吭声，判断只能看结果——系统网络连接列表里有没有多出那块网卡，比任何提示都可靠。

## 自测口径：三个动作定位九成问题

| 动作 | 花多久 | 能定位什么 |
|---|---|---|
| 断开并停用网卡，看本地网是否恢复 | 1 分钟 | 半接管残留 vs 系统层故障 |
| 用 IP 直连同一站点 | 1 分钟 | DNS 问题 vs 链路问题 |
| 同线换站、同站换线各一次 | 3 分钟 | 出口问题 vs 客户端问题 |

三个动作加起来五分钟，比重装一次客户端快，也比换三条线路便宜。做之前先记下当时的三个数：网关是否通、IP 直连是否开、别的站是否正常——有这三个数，任何一次求助都能少绕两轮。

## 常见问题

**Q：SSTap 断开之后电脑还是上不了网，怎么办？**
A：这是半接管残留。去系统网络连接里找到那块虚拟网卡并禁用，再把系统 DNS 改回自动、清一次解析缓存，本地网络通常立刻恢复。恢复之后再重连，不要在没网的状态下继续调客户端。

**Q：为什么开着 SSTap 访问不了公司内网和打印机？**
A：接管范围覆盖了本该走本地的流量。全局模式下所有出站包都先进虚拟网卡，内网 IP 段也被吸进去，自然访问不了。解决办法是把内网网段加进直连规则，或改用规则模式。

**Q：连接显示成功，测出来还是本地 IP，是没生效吗？**
A：先看虚拟网卡装没装上。装成功后系统网络连接列表里会多出一块网卡，没有这块网卡时点连接不会真的接管流量，界面也不给红字。装失败最常见的原因是被杀软拦，需要管理员权限重装。

**Q：小网页能开、视频一直转，是带宽不够吗？**
A：更像 MTU 不匹配。多一层封装后包变大，链路上有一环不允许就会表现成「连接建立很快、一传数据就卡」。先把线路换到别的工具里验一遍，快就说明不是带宽问题。

**Q：SSTap 和普通 SOCKS5 客户端能同时开吗？**
A：不建议。两者抢的是同一层接管权，同时开会互相覆盖路由规则，症状是「两个都显示已连接、都上不了网」。要用两个，就一个走虚拟网卡、另一个只给指定进程用。
