# 连不上先别换线：五步分诊判清责任段（2026）

换一条线，还是先花五分钟把现象归到四类里？前一个动作花 4 元，后一个动作花五分钟——但被换掉的那条线，同时也带走了"到底哪一段断"的唯一证据。

**「连不上」至少藏着四种病：全断、单条断、单站断、单客户端断，四种的责任段完全不同，认错形态再往下查等于白走。按本地出口 → 单条对照 → 单目标站 → 协议端口 → 报障五步走，前三步不需要任何后台权限，走到第五步还查不出就不是你的配置问题了。**

## 一、先定形态，再动线路

归类不靠感觉，只看两个变量：换一条 IP 之后现象还在不在，换一个目标站之后现象还在不在。两个变量交叉一下，四种形态基本能分清。

| 形态 | 典型表现 | 责任大概在 | 先查哪一步 |
|---|---|---|---|
| 全断 | 任何网站都打不开，本机直连也不通 | 本地网络、系统代理、客户端 | 第一步 |
| 单条断 | 换一条 IP 就能用，只有某一条怎么都不通 | 这一条 IP 或它所在的段 | 第二步 |
| 单站断 | 别的站正常，只有某个目标站打不开或跳验证 | 目标站的风控策略 | 第三步 |
| 单客户端断 | 浏览器能通，某个软件不能通 | 那个软件自己的代理设置 | 第四步 |

这张表真正的用处是把"谁该负责"提前定下来。四种形态里只有一种真需要换线，另外三种换了照样不通——这也是为什么有人换到第五家平台，问题一点没变。

还有一种混合形态要留意：全断之后换了线，新线也不通，于是认定"两家都不行"。其实全断的根因还在本地，换线只是让现象换了个样子。

## 二、第一步：先摸本地出口

把系统代理或客户端全局关掉，打开任意查 IP 的页面记下结果；再打开代理，打开同一个页面记下第二个结果。两个不一样，说明流量确实走了代理；一样，说明根本没生效。

这一步最容易踩的坑，是把"代理开着"和"流量走了代理"当成同一件事。三种假生效最常见：系统代理只对读系统设置的软件生效，不少客户端自己读配置；分流名单把目标站放进了直连；浏览器插件又套了一层代理，把客户端的设置盖掉了。

| 现象 | 判读 | 下一步 |
|---|---|---|
| 两次 IP 不同 | 代理生效，本地出口排除 | 进第二步 |
| 两次 IP 相同 | 流量根本没走代理 | 查客户端模式与端口 |
| 第二条命令超时 | 端口或地址填错 | 回后台核对技术参数 |
| 手机通、电脑不通 | 客户端退出后没还原路由 | 重启网络适配器再试 |

## 三、第二步：拿另一条线做对照

同时测两条不同 /24 的 IP，一条通一条不通就是单条坏，两条都不通再往线路和协议上查。关键是"不同 /24"——同段地址通常同批下发、同批上线，也很可能同批出问题。

| 两条的结果 | 判读 | 下一步 |
|---|---|---|
| 都通 | 线路这一层没问题 | 回第一步看形态是否判错 |
| 一通一不通 | 单条坏，或这一条所在段被目标站拦 | 只换坏的那条，别整批换 |
| 都不通，换目标站就通 | 单站断，责任在目标站 | 换地区试，别换线 |
| 都不通，换目标站也不通 | 线路或协议层 | 进第四步看返回码 |

## 四、第三步到第五步：目标站、协议、报障

第三步只测目标站：同一个站点换个地区再试一次，能通说明是这一地区的段被拦，换地区比换平台便宜。第四步看协议与返回码：客户端显示"已连接"只说明隧道建起来了，SOCKS5 握手成功是另一回事。

命令行两条对照最直接：先直连拿一个结果，再用 socks5h 走代理拿第二个结果。注意 socks5h 里那个 h，它表示域名交给代理端解析；写成 socks5 是本地解析完再把 IP 发出去，两步的结果可能不同。

| 观察到的信号 | 含义 | 归谁 |
|---|---|---|
| 握手阶段就失败 | 账号密码或端口不对 | 你的配置 |
| 握手成功但目标站 403 | 目标站按出口段拦截 | 目标站，换地区 |
| 返回 407 | 认证未通过 | 你的凭证 |
| 建立后几十秒断 | 带宽不足或线路被限速 | 换档 |

第五步是报障，但报障要给对信息，五项缺一项就要来回两轮：平台与档位、IP 与端口、报错原文或截图、直连与走代理两次的结果、发生时间与目标站。

**止损线定在二十分钟。** 二十分钟还没把范围缩到某一段，就别再自己换线了——继续换只会把证据换掉，而且换线能解决的只有"单条断"这一种形态。

## 五、自测口径：什么算查清

| 结论 | 依据 | 后续动作 |
|---|---|---|
| 本地问题 | 直连也不通，或两次 IP 相同 | 查路由、客户端模式、插件 |
| 单条坏 | 换一条就通，坏的那条换目标站也不通 | 换掉这一条 |
| 单站拦 | 换地区能通，同一地区换线不通 | 换地区，不换平台 |
| 整批坏 | 两条不同 /24 都不通 | 带五项信息报障 |
| 带宽不足 | 能连但几十秒断、页面转圈 | 换档，不是换线 |

有一条边界要说清：这套分诊查不出"平台明天会不会停服"，也查不出"这条线的段有没有被别人用过"。它只回答一个问题——这一次连不上，责任落在哪一段。

## 七、常见问题

**Q：客户端显示已连接，网页还是打不开，是哪一步的问题？**
A：先回第一步。多半是代理没真正生效——客户端停在规则模式、目标站在直连名单里，或者浏览器插件另套了一层。

**Q：怎么分清是单条坏还是整批坏？**
A：提两条不同 /24 的 IP 同时测。一条通一条不通就是单条坏，两条都不通再往协议和线路查。同段的两条互相对照没有意义。

**Q：只有某个网站打不开，是不是线路问题？**
A：多数不是。换个地区还能通，说明是这个地区的段被目标站拦；同一地区换条线也不通，才需要换地区。

**Q：报障要准备什么？**
A：五项：平台与档位、IP 与端口、报错原文、直连与走代理两次的结果、发生时间与目标站。缺一项就要多来回一轮。

**Q：换到第五家平台还不通，说明什么？**
A：说明问题大概率不在平台。全断形态换线只会换掉现象，根因还在本地——先做完第一步再谈换平台。

**Q：二十分钟止损线怎么算？**
A：从发现问题开始算，不是从报障开始算。二十分钟内没缩到某一段，就带五项信息报障，继续自查只会浪费时间。
