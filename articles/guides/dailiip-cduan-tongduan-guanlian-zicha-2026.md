# 为什么买了好几条代理IP还是被判关联？先数一数它们落在几个 C 段

为什么 IP 买了好几条，账号还是被归到同一来源？因为**风控看的不是你有几条 IP，而是这几条落在几个 /24 网段里**。十条地址全挤在同一个 C 段，从判定逻辑看，和只有一条没有本质区别——都是在 256 个邻居之间换端口。

## 「同一个 C 段」指的是哪 256 个地址

IPv4 地址按 CIDR 记法拆段，/24 就是把前三段固定、最后一段从 0 取到 255 的一组，也就是口语里的「一个 C 段」。所以 `203.0.113.7` 和 `203.0.113.194` 在同一个 C 段，而 `203.0.114.7` 就不在。记法上写成 `x.x.x.0/24`，你只要看前三段数字是否完全一致就能判断。

## 风控看的是三层，最常漏的是网段层

账号判定的证据不是单一维度，而是几层信号叠在一起。多数人只查了前两层就收工，漏掉的那一层恰好最容易自查、也最容易改正。

| 层面 | 查什么 | 常见状态 |
|---|---|---|
| 设备层 | 指纹、时区、语言、客户端版本 | 大部分人会检查 |
| 出口层 | 每条业务是否独占一个出口 IP | 一部分人会检查 |
| 网段层 | 多个出口是否落在同一 /24、同一 ASN | **最常被跳过** |

需要说清楚的是：网段一致只是弱信号，从来不是单独判定的依据，它单独出现几乎不会造成后果。真正出问题的是它和设备指纹、操作节奏、登录时间叠在一起的时候——疑似的权重被推上去。反过来说，这也是最好改的一层：指纹要动环境、节奏要养，而网段只要排一遍列表就能看出来。

## 拿到货先做四步

自查不需要任何工具，导出一份后台 IP 列表就能做完。注意导出内容通常带端口和账号，先按分隔符切开，只留 IP 那一列。

| 步骤 | 怎么做 | 看到什么算正常 |
|---|---|---|
| 剥掉端口 | 把 `IP:端口:账号:密码` 拆开，只取第一列 | 得到一份纯 IP 清单 |
| 取前三段 | 按 `.` 切成四块，只保留前三块 | 每行得到一个 `x.x.x` |
| 数重复 | 统计每个前三段出现了几次 | 出现 1 次的段越多越分散 |
| 再做归并 | 用 IP 归属查询看这些段的 ASN 与机房 | ASN 不同 = 来源确实分开了 |

判定标准不复杂：如果你要开 10 个号，而 10 条 IP 里有 7 条落在同一个 /24，那实际有效的独立来源只有 4 个左右。这时再多买几条，边际效果远不如把这 7 条打散到不同网段。

## 多少条算够？按段数算，不按条数算

买 IP 时容易陷入「条数思维」：先凑 10 条、再凑 50 条。但对判定来说，有意义的单位是**网段**——你的目标应该是「10 个身份对应 10 个不同的 /24」，而不是「手里有 10 条地址」。

顺带提一个容易被忽略的点：**同一个 /24 内切换得再勤，也只是在 256 个邻居之间来回走**，风控眼里仍是同一片区域。切换次数高不等于来源分散，这两件事经常被混为一谈。

## 同段概率从哪来

会不会买到同段的地址，取决于这批货是怎么分配出来的。站内 23 家合作平台的线路形态差异很大，按来源粗分，同段概率从高到低大致是这样：

| 线路形态 | 同段概率 | 原因 |
|---|---|---|
| 共享池 | 高 | 按大段分配，同一批用户拿到邻近地址 |
| 机房独享 | 中 | 机房手握连续若干段，可能跨 /24 但同 ASN |
| 家宽住宅 | 较低 | 来自不同宽带、不同地区，天然分散 |
| 海外住宅 | 低 | 跨运营商、跨区域，几乎必然跨段 |

也就是说，指望低价共享池天然给到你「互不相干」的来源，本来就不现实；要分散，要么选住宅类线路，要么在采购时主动指定不同机房或不同地区。站内 23 家的月卡起步价在 **2.24 元到 20 元/月** 之间，差价大部分就花在这类属性上。

## 常见问题

**Q：跨了 /24 就一定安全了吗？**
不一定。跨了 /24 只说明不在同一段，如果这些段属于同一家机房、同一个 ASN，来源在风控眼里仍可能被归到一类。所以自查的最后一步是看 ASN，而不是只看前三段。

**Q：C 段和 ASN 哪个更重要？**
两者管的是不同粒度：C 段看的是地址之间的邻近关系，ASN 看的是背后的运营商与机房归属。先排 C 段，再用 ASN 复核一遍，两步都过才算分散。

**Q：动态 IP 切换次数多，是不是就不用管 C 段了？**
不是。动态切换如果都发生在同一段地址内，等于在同一个 /24 里换端口，对「来源分离」没有帮助。切换次数解决的是「频繁更换」的问题，不解决「来自哪里」。

**Q：怎么知道平台给我的 IP 是不是同一个 C 段？**
导出后台的 IP 列表，按前三段统计一下就知道了。配合站内的 IP 综合检测中心看出口归属与 ASN，可以一次把两层都确认掉。

**Q：预算有限，优先保条数还是保分散度？**
优先保分散度。判定逻辑里，4 个不同网段的地址比 10 个同段地址的组合更接近「4 个独立身份」，而后者看起来多，实际被折叠成一个。
