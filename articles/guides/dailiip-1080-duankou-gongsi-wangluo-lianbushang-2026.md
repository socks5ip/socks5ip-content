# 代理IP 到公司就连不上：你填的 1080 不是服务端的端口（2026）

在办公室的电脑上把代理配好，浏览器一直转圈——这一段账号密码在家里用得好好的。

**一句话结论：**连不上分三层：**本机、所在网络、平台那一侧**。客户端里的 **1080 只是 SOCKS5 的约定端口**，它做的是本地监听，改它不影响出网；真正要出网的是**服务端端口**，写在你提取出来的凭证里。办公网、酒店、校园网的出站策略常常只放 **80 与 443**，非标端口出不去，十条线一起躺平。判断成本最低的一步是**换一次手机热点**：换了就好，问题在你的网络，一分钱都不该花。

## 一、两个都叫「端口」的输入框，填反了很常见

客户端里常有两个叫端口的格子，位置还挨着：一个是本机监听，一个是服务器端口。

| 填的地方 | 常见值 | 作用 | 填错的后果 |
|---|---|---|---|
| 本机监听端口 | 7890、10808、1080 | 软件在你电脑上开的本地入口，只在本机生效 | 程序连不上客户端，不是客户端连不上服务器 |
| 服务器端口 | 凭证里的那一段（如 9555） | 真正出网的那道门，由平台分配 | 连接超时或被丢包，看起来像"线路坏了" |

一个高频的无效动作是把本机监听从 7890 改成凭证里的 9555，然后宣布"我按凭证改了还是不行"。改的是本地入口，出网那一端的端口从头到尾没动过。

## 二、凭证是五段，第二段才是门

站内天行IP 价格表页附过一个公开的实例检测线路，原文是 `113.142.41.123|9555|cqvn03y2|k3QGtKER|2026-06-03`，五段依次是 **IP、端口、账号、密码、到期日**。那个 9555 才是要出去的门。

SOCKS5 的协议是 RFC 1928，1080 是 IANA 给它登记的**约定**端口。约定不等于强制：平台完全可以把服务端开在 9555、10086 或三万以上的高位端口，不需要通知任何人，也不需要改协议。教程里写 1080、凭证里写 9555，两句话都对，只是说的不是同一个端口。

## 三、从你电脑往外数，一个连接要过三道门

| 门 | 位置 | 典型特征 | 该做什么 |
|---|---|---|---|
| 第一道 | 本机：安全软件、防火墙出站规则 | 同一网络换个程序能通，只有这个客户端不行 | 查规则与端口占用 |
| 第二道 | 所在网络：办公网、酒店、校园网出站策略 | 同一套凭证换个网络立刻就好 | 换网络或申请端口例外 |
| 第三道 | 平台一侧：端口没监听、来源白名单、凭证过期 | 换任何网络都不通，报错形态稳定 | 核对凭证、问客服端口 |

三道门里最容易被误判成"线路坏了"的是第二道，因为它只在特定网络里出现，而人往往只在一个网络里用。这时候换平台、换档位、加钱升带宽，全是对着空气使劲。

## 四、换一次热点，60 秒定性

把笔记本或手机切到自己的流量热点，用同一份凭证再连一次。这个动作不超过一分钟，但能把三道门砍掉两道。

**换网络就好了**——问题在第二道门，跟平台、档位、IP 纯净度都无关。这笔钱省下来，比任何一次升级都值。

**换网络照样连不上**——往下查第一道与第三道：先看客户端日志的错误码，再逐字核对凭证五段有没有抄错一位（尤其 0 和 O、1 和 l），最后做端口探活。

端口探活可以直接测，示例地址取自站内价格表页的公开案例，请换成你自己凭证里的值：

| 系统 | 命令 |
|---|---|
| Windows（PowerShell） | `Test-NetConnection 113.142.41.123 -Port 9555` |
| macOS / Linux | `nc -vz 113.142.41.123 9555` |

返回 True 或 succeeded 说明 TCP 握手通了；timeout 说明连接被中间设备丢弃；refused 说明那头没有服务在监听。三种结果指向三个不同的责任人。

别用 ping 判端口。ping 走 ICMP、端口走 TCP，两套东西互不背书。办公网里 ping 得通、非标端口被丢，是最常见的组合。

## 五、只放 80 和 443 的网络，能走的路就三条

| 路径 | 做法 | 代价 |
|---|---|---|
| 换协议口径 | 平台若同时给 SK5 与 HTTP，HTTP 代理挂在 443 上是存在的做法 | 下单前就要问清"服务端端口多少、能不能指定" |
| 换传输方式 | L2TP 走 UDP 1701，和 TCP 端口是两条独立通道 | 有的办公网连 UDP 一起封，且要设备本身支持拨号 |
| 换网络 | 手机热点最直接；长期作业拉一条独立宽带 | 热点吃流量，宽带吃月租 |

还有一条不技术的路：向网络管理员申请端口例外。办公网有自己的管理规则，通道走不通时，技术手段不该被拿去当绕开管理的办法。这里讲的都是怎么判断卡在哪一层、按判断去选线。

## 六、端口不写在价目表里，加钱也不会变成 443

| 认知 | 实际情况 |
|---|---|
| 价目表上应该能查端口 | 查不到，端口是套餐附带属性，不单独收费 |
| 买贵一档端口会更好 | 不会，端口分配方式与价格无关 |
| 端口会变吗 | 固定端口的套餐续费与切区都不改；随机端口的每次提取都可能换 |
| 受限网络里该问什么 | "服务端端口是多少、能不能指定"，下单前问，不花钱 |

一个常被忽略的对比：2.6 元的特价档和 10 元的 J 节点，差的是带宽、IP 出身与稳定性，不是"端口自由度"。业务只在受限网络里跑，高价档并不会让端口自己变成 443。

## 七、自测口径：先定性，再花钱

1. **看现象属于哪一类。** 全套凭证在任何网络都不通 → 平台或凭证；换网络就复现 → 你的网络；同一网络里别的程序正常、只有这个客户端不行 → 本机。
2. **量一次端口。** 用上面的命令测服务端端口，三种返回对应三种责任人。
3. **确认代理有没有生效。** 连上之后打开 IP 综合检测中心，显示的还是本地运营商，说明流量没走代理，问题在客户端配置。

什么情况别在端口上折腾：目标站返回 403 或 429 是对方在限流，端口通得很；"能连上但很慢"是带宽或对端问题，跟端口无关。这两类混进来只会拖长排查。

## 常见问题（FAQ）

### Q：代理IP 的 1080 端口连不上，改成 9555 有用吗？

要看你改的是哪一栏。改本机监听端口没有用，出网端口不会跟着变；只有当凭证上的服务端端口确实是 9555、而你把"服务器端口"填成了 1080，这一改才有意义。凭证五段里第二段就是答案。

### Q：同一个 IP 在手机热点下能用，公司网络就不行，是账号问题吗？

不是。换网络即好，说明凭证本身没问题，卡在公司网络的出站策略上。这类情况换平台、换档位都不会好转，除非新平台的服务端端口正好落在被放行的范围里。

### Q：SOCKS5 默认端口是 1080，为什么平台不用？

1080 是 IANA 给 socks 登记的约定端口，不是强制。平台为了减少被扫描、被误封，常把服务端开在非标端口上。客户端填 1080 也没错，那是本机监听，两回事。

### Q：端口能通，但网页打不开，问题在哪？

TCP 通了说明门开着，打不开通常在认证、DNS 或对端。先看是不是 407（账密或来源白名单），再看 DNS 有没有走本地解析，最后才怀疑线路质量。这三步的顺序别颠倒。

### Q：代理IP 的端口会变吗？

看平台的分配方式。固定端口的套餐，续费与切换地区都不改端口；随机端口的套餐，每次提取都可能换一个。前一种对受限网络友好，后一种在白名单与防火墙面前最麻烦。

### Q：公司网络里用代理IP，算不算出格？

技术上它只是一个出站连接，和访问任何网站没有区别；但公司网络有自己的使用规则，规则怎么定由管理方说了算。要长期用，走管理员申请端口例外，比私下绕开更省事。
