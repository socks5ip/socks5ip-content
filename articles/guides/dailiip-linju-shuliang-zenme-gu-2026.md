# 邻居数不是买来的参数，是自己量出来的

同一段 IP 上还站着多少人，数量本身其实不决定后果。真正会落到你账上的是「这批邻居干了什么」——而这件事没有任何平台会写进参数表，只能自己量。

站内检测工具能给出的三项直接读数：IP 归属与 ASN、洁净度与风险分、相邻地址的出口类型。**把这三项组合起来，就能把「邻居」从一句玄学变成一个可以按季度复核的数字。**

| 要看的 | 在哪看 | 读出来是什么 | 判读门槛 |
|---|---|---|---|
| IP 归属与 ASN | IP 综合检测中心的归属项 | 这段挂在哪家机房、哪个运营商 | 数据中心还是家庭宽带，决定出身 |
| 洁净度 / 风险分 | 同一页的纯净度项 | 是否命中公开黑名单 | 命中即换段，不议价 |
| 相邻地址类型 | 取同段前后各一个地址单独查 | 相邻地址是否也是代理出口 | 三个里两个以上是代理 = 密集段 |
| 出口是否随请求变化 | 连续请求二十次记出口 | 固定型 / 轮换型 / 池化型 | 与商品页写的形态是否一致 |

## 三层邻居，只有第一层你能直接感知

**同 IP 邻居会挤带宽、会让你掉线，所以你能感觉到；同段和同 ASN 的邻居你完全感知不到，但他们出事时你照样受损。**

| 层级 | 范围 | 能否感知 | 受损方式 |
|---|---|---|---|
| 同 IP 邻居 | 共用同一条出口的其他用户 | 能，表现为挤带宽、频繁掉线 | 直接互相干扰 |
| 同段邻居 | 同一 C 段内其他地址 | 不能 | 整段被标记时一起受损 |
| 同 ASN 邻居 | 同一机房或同一运营商下所有地址 | 不能 | 影响「这段像不像住宅」的判断 |

所以「用着挺快」不能推出「邻居干净」。速度只反映第一层，而封号这类后果多数来自第二层和第三层。

## 三个动作，把邻居估成一个数

**顺序不能反：先看段、再看相邻、最后看历史标签。** 反过来的话，你会拿一条「速度不错」的线去解释一个「整段被标记」的结果。

| 步骤 | 动作 | 记什么 | 结论怎么下 |
|---|---|---|---|
| 第一步 | 查出口 IP 的 ASN 与归属 | 机房名 / 运营商名 | 机房段做登录态业务要打问号 |
| 第二步 | 把同段前后各一个地址单独查一次 | 是否也是代理出口、是否同机房 | 三个里两个以上是代理 = 密集段 |
| 第三步 | 查洁净度与风险分 | 黑名单命中、风险等级 | 命中即换段，不讨论 |

三步做完，你会得到三种组合，处置完全不同：

- **段内干净 + 出身是家宽**：邻居少，可以承载登录态业务。
- **段内干净 + 出身是机房**：邻居未必多，但「不像住宅」这件事本身就是门槛，敏感平台会直接拒。
- **段内有代理 + 命中黑名单**：与你无关也要换，这段已经是共享出口，标签跟着段走。

## 密集段的四个信号，出现两个就该换

**这些信号都来自聚合数据，不是针对你个人。** 平台按整段的历史行为打标签，不做逐个核实——这是申诉里最常被误解的一点：账号是新的，IP 不是。

| 信号 | 它是怎么形成的 | 对你的影响 |
|---|---|---|
| 该段近期注册量偏高 | 同段其他用户批量注册 | 新号进人工复核或被直接拒 |
| 该段存在多账号同设备指纹 | 别人没做环境隔离 | 你的账号被要求二次验证 |
| 该段命中黑名单 | 历史被举报或被爬虫滥用 | 访问被直接拦，与你的行为无关 |
| 该段为机房归属 | IP 段注册信息就是数据中心 | 部分平台对机房段天然更严格 |

四个里出现两个，说明这段的标签已经不由你控制。**换段比换平台便宜**：同平台换一条线就能解决，换平台要重配整套环境。

## 复测间隔，按业务周期定

**一次检测的结论只在那一天成立。** 黑名单在变，段的使用者也在变，所以复测不是「想到才做」，而是按业务周期排进日历。

| 业务形态 | 建议复测间隔 | 为什么是这个节奏 |
|---|---|---|
| 长期固定出口、账号数稳定 | 每季度一次 | 段不变，主要防上游把整段回收转卖 |
| 新开账号、扩量阶段 | 每两周一次 | 新号最容易被段历史拖累 |
| 高敏感平台（金融、店铺主账号） | 每月一次 + 出事即测 | 一次连带损失的代价远高于检测成本 |
| 纯采集、无登录态 | 出问题再测 | 被拦重试即可，不需要预防性复测 |

复测只做两件事：**出口是否还是原来那段、洁净度是否新增命中。** 两项都没变就不必展开，变了就按上一节的三个动作重走一遍。

## 邻居少，也不等于可以承诺结果

**任何平台都保证不了「独享就不封号」。** 影响账号的因素里还有环境指纹、操作节奏和平台策略本身，IP 只是其中一项。能通过选档改善的，只有「被邻居牵连」这一项。

反过来说，也别把独享当成万能。全独享住宅的邻居天然很少、出身也是家庭宽带，代价是单价高一截，而且资源本身仍可能被上游回收。**先定业务能承受多大连带风险，再决定为邻居这件事付多少钱。**

## 常见问题

### 邻居数量能查到一个准确数字吗？

查不到准确数字，只能估区间。公开数据能告诉你这段属于哪家机房、性能如何，但查不到这段上正在跑多少活跃账号。可操作的做法是取同段前后各一个地址做对照，三个里两个以上是代理出口，就按密集段处理。

### 用着很快，是不是说明邻居很少？

不一定。速度只反映同 IP 邻居有没有在挤带宽，反映不了同段、同 ASN 的邻居。很多封号是段级标签导致的，跟快慢无关。

### 机房 IP 一定不能用吗？

不是。机房段的问题是「出身不像普通用户」，不是「脏」。对登录态敏感的平台要避开，采集、比价、测速这类业务影响有限。

### 换了独享，就一定不会被牵连？

不能保证。独享解决的是「同 IP 邻居」这一层，同段和同 ASN 的连带仍然存在，只是概率低。上游把整段回收转卖时，历史标签也会跟着走。

### 复测发现洁净度新增命中，要马上换段吗？

要。命中黑名单意味着访问会被直接拦，与你的行为无关，等它自然恢复的周期不可控。同平台换一条线通常当天就能解决。

### 怎么判断是「邻居牵连」还是我自己的操作问题？

看对照组。同一段 IP 上换一个新号、按最保守的节奏操作，如果仍被要求验证，说明问题在段；如果新号一次就过，问题在操作节奏或环境指纹上。
