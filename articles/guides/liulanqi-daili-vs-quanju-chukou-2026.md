# 浏览器代理和全局代理差在哪：一份配置只管一半流量

只给浏览器挂代理，还是整台机器一起换，差别不在覆盖范围大小，而在覆盖面的形状：前者是一条窄路，后者是一张网。

**浏览器代理只管浏览器进程里走 HTTP 与 HTTPS 的请求；同一次页面加载里，WebRTC 的 UDP 包不走它，桌面软件、模拟器、下载器更不在范围内。全局代理改的是默认路由，对象是程序，不是站点。**

| 维度 | 浏览器代理 | 全局代理 |
|---|---|---|
| 管到谁 | 只有浏览器里的 HTTP/HTTPS 请求 | 所有读默认路由的程序 |
| 改的是什么 | 浏览器里的一份代理配置 | 系统默认路由 / 虚拟网卡 |
| 换不换程序 | 不换，非浏览器一律直连 | 换，整机或指定进程都换 |
| 典型漏点 | WebRTC、UDP、插件自带通道 | 绕过局域网 / 大陆 IP 的例外规则 |

数据来源：Chrome / Firefox 代理设置与 WebRTC 工作机制，站内实测口径（2026-11-24 复核）

## 配置存在哪里，决定了谁会跟着变

**同一句「给浏览器挂代理」，在 Windows 上至少有三种落脚点：系统 Internet 选项、浏览器自带的一份、以及工具里按环境存的配置。**

落在系统里，改的是当前用户的 WinINET 设置，所有读系统代理的程序会一起变——这时候你用的其实已经不是纯粹的「浏览器代理」了。落在浏览器自己手里（Firefox 的连接设置），只有那个浏览器生效。落在指纹浏览器里，一个环境一份，互不影响。

三种落脚点的差别，在日常使用里表现为「同一个 IP 查询页，在两个地方打开显示不同结果」。不是线路故障，是查询时站的位置不同：浏览器站在代理配置后面，桌面软件直接站在网卡上。

| 配置在哪里 | 谁改的 | 改了之后谁生效 |
|---|---|---|
| 系统 Internet 选项 | Chrome / Edge 的代理设置会跳到这里 | 所有读系统代理的程序 |
| 浏览器连接设置 | Firefox 自己维护 | 只有 Firefox |
| 指纹浏览器环境配置 | 每个环境独立保存 | 只有那个环境对应的窗口 |

## 一次页面加载里，三类请求走三条不同的路

**页面文档与子资源走代理，HTTPS 先发 CONNECT 建隧道；WebRTC 的 UDP 包自己去找对端，不经过你填的代理地址；浏览器更新与扩展下载则看具体实现。**

第二类最容易被忽略，也最影响结果。风控系统读的不是「你从哪条线来」，而是「浏览器告诉了我哪些地址」。WebRTC 会把候选地址报出去，包括局域网地址和一条公网地址——只挂浏览器代理、不做处理时，那条公网地址很可能就是本机真实出口。

所以「浏览器已挂代理，WebRTC 检测仍显示本地 IP」是正常现象，不是代理没生效。要把这一类也盖住，得在浏览器层面关掉 WebRTC 或改成 relay 模式，这件事和填代理参数是两码事。

| 请求类型 | 走不走浏览器代理 | 怎么自己验 |
|---|---|---|
| 页面文档 / 脚本 / 图片 | 走 | 浏览器里打开 IP 查询页看出口 |
| HTTPS 隧道 | 走，先 CONNECT | 看是否报 407 或隧道失败 |
| WebRTC（UDP） | 不走 | WebRTC 泄漏检测页看候选地址 |
| 桌面软件、模拟器 | 完全不涉及 | 在软件内部查出口 IP |

## Chrome 读系统那份，Firefox 自己存一份

**Chrome 与 Edge 的代理设置本质是系统设置的一个入口，Firefox 默认跟随系统但可以改成手动独立生效，两家在同一台机器上配同样的参数，结果可能完全不同。**

Windows 上 Chrome 点开代理，弹出的是系统的 Internet 选项，改完以后跟着系统走的程序一起变。Chrome 另有一条路：装扩展调用浏览器代理接口，可以只在 Chrome 内生效，还能按域名分流。

Firefox 手动档里，SOCKS v5 旁边有一个「使用 SOCKS v5 时代理 DNS」的勾。勾上，域名解析在远端完成；不勾，由本机解析。这一格的差别会直接体现在 DNS 泄漏检测的结果上，也是很多人「换了出口仍被认出本地」的原因之一。

## 指纹浏览器按环境存，才谈得上单窗口单 IP

**只有把代理配置绑在「环境」这一层，一个窗口一个出口才成立；绑在浏览器或系统上，所有窗口共用一条出口。**

指纹浏览器的做法是：一个环境一份代理配置，加上独立的 Cookie、时区、语言与指纹参数，打开时整份环境一起加载。它解决的不只是 IP，还有「同一台机器上多个账号看起来像不像同一个人」。

代价是配置量变大：每个环境都要单独填一次代理参数，出口数一多，手填出错率就上来了。这也是为什么批量场景更常见「按段导入」而不是逐条填——四个字段一条，错一位的表现是连接超时，不是报错。

## 三个动作验收，两分钟能做完

**一查浏览器出口，二查 WebRTC 候选地址，三查桌面软件自己的出口；三项结果一致才算「整机都换了」，只有第一项变了就是浏览器代理在起作用。**

第一项在浏览器里打开 IP 查询页，看归属地是否为目标地区。第二项打开 WebRTC 泄漏检测页，看候选地址里有没有本机公网 IP——有，说明 UDP 这条路还在外面。第三项在微信、模拟器或下载器里各查一次出口，它们不走浏览器配置，显示本机 IP 属正常。

三项都对上之后，再谈线路质量。顺序反了会白折腾：出口没换对就去测带宽，测出来的数没有意义。

## 常见问题

**问：浏览器挂了代理，为什么网页里显示的 IP 还是本地？**
答：三种可能：配置落在了另一个浏览器上、代理没连上、或者你看的是 WebRTC 检测结果而不是 HTTP 出口。

**问：Chrome 改代理会不会影响别的软件？**
答：会。Chrome 的设置跳的是系统 Internet 选项，跟着系统走的程序会一起变；要只影响 Chrome，用扩展那条路。

**问：Firefox 能独立于系统吗？**
答：能。连接设置里改成手动配置代理，就只对这个浏览器生效。

**问：WebRTC 泄漏要关掉哪些？**
答：至少关掉非代理 UDP，或把策略改成只走 relay；只填代理参数不管这一项，公网地址仍会被报出去。

**问：指纹浏览器为什么能一个窗口一个 IP？**
答：因为代理配置绑在环境上，一个环境一份，窗口之间不共享。

**问：桌面软件要不要单独配？**
答：要。它不读浏览器的配置，要么走系统代理，要么在软件内部填一份。
