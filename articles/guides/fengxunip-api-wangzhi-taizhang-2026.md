# 烽迅批量取号要管几张网址？

20 条线路的取号成本是 120 元/月，20 条网址的维护成本却不在任何一张价目表上——这两笔账要分开算，第二笔才是批量取号真正的门槛。

烽迅（官网自称烽讯加速器，域名 fengxunip.com）后台的「SK5 API 提取」页只做一件事：把「从哪个订单取」固定下来，生成一条可长期调用的网址。**订单与网址是 1:1，没有「一个接口取全部线路」的形态。**

## 网址数量由订单数量决定

| 对象 | 数量关系 | 在哪儿处理 |
|---|---|---|
| 订单 | 一张订单对应一组线路 | 后台下单与续费 |
| 线路 | 单窗口单 IP，窗口多就按窗口数加购 | 后台订单管理 |
| API 网址 | 与订单 1:1 | SK5 API 提取页 |
| 窗口编号 | 每个窗口对一条线路 | 你自己的调度表 |

后台那张页面上，五个控件里只有「选择订单」带红色星号，其余四项都有默认值。这个设计把批量的规模写在了订单上：**你有几个订单，就有几条网址要管。**

## 台账五个字段，缺一个就会在夜里出问题

| 字段 | 记什么 | 缺了会怎样 |
|---|---|---|
| 订单名 | 后台显示的项目名（756 个项目池里的那一个） | 续费时找不到是哪一单 |
| 订单到期日 | 与线路有效期一致 | 到期当天取号全失败，脚本空跑 |
| 生成的网址 | 完整地址，含参数 | 换机器或换人接手就断 |
| 返回口径 | txt / json + 换行符 | 解析层按行切，格式一变整批错 |
| 服务器地址格式 | 常规地址 / 固定域名 | 换线后地址是否变化由它决定 |

第三、四两个字段要连着记：返回口径变了，解析代码就得改，而解析代码往往不在同一个人手里。**台账里写一行「txt + `\n`」的成本，比事后排查一次解析失败低得多。**

## 三种失效，与各自的自愈动作

| 失效 | 触发原因 | 表现 | 自愈动作 |
|---|---|---|---|
| 订单到期 | 忘了续费 | 取号返回空或报错 | 续费后原网址继续可用 |
| 换城市 | 后台重新提取 | 常规地址格式下地址变了 | 重新导出，更新台账 |
| 改返回口径 | 有人动了换行符或格式 | 脚本解析出 1 条而不是 20 条 | 回滚口径，不要改脚本去迁就 |

三种里第一种最隐蔽：**它不会在白天出问题，总是在订单到期那一刻开始静默失败**，脚本没有报错，只是拿到 0 条，业务侧表现为「今天所有任务都在用旧 IP」。

「服务器地址格式」这一栏也会影响失效范围：选固定域名，换线后地址不变，但几分钟内可能还连到旧地址；选常规地址格式，换完必须重新导出。**两种都要写进台账，别靠记忆。**

## 成本：线路条数乘档位价

API 本身不单独收费，账单等于线路条数乘档位价。下表按 2026-10-22 站内价格表读数换算，20 条线路的月成本如下。

| 档位 | 单价（元/条/月） | 20 条月成本 | 适用 |
|---|---|---|---|
| SK5 1M 特惠 | 2.6 | 52 元 | 轻量任务、只取号不跑带宽 |
| SK5 5M | 4.8 | 96 元 | 中等并发 |
| SK5 10M 推荐 | 6 | **120 元** | 游戏档、常规多开 |
| SK5 20M | 8.8 | 176 元 | 多任务并行 |
| SK5 大带宽（视频） | 28 | 560 元 | 视频项目 |
| L2TP 2M | 6 | 120 元 | 整机出口（不走 API） |

**L2TP 那一行放在这里是提醒：API 入口在「SK5/HTTP 管理」这一组下，对应软件级代理；L2TP 是整网隧道，配在软路由里，不走这个按钮。** 买错表，取号这一步根本不会出现。

## 调度：多久取一次、失败怎么补

| 参数 | 建议 | 理由 |
|---|---|---|
| 取号间隔 | 按 IP 存活期定，不按整点定 | 整点取号会让所有线路同时切换，形成尖峰 |
| 单次条数 | 等于该订单的窗口数 | 多取不用，少取要补 |
| 失败重试 | 失败后延后重取，不原地连打 | 连续请求会被限流，越打越慢 |
| 兜底 | 台账里留一条备用订单 | 主订单到期或异常时不断线 |

第二行的口径容易被搞混：一次取 20 条不等于 20 条都能用，取回后还要过一遍可用性检测，这一步不能省。

## 自测口径：先跑通三步再谈批量

| 步骤 | 动作 | 通过标准 |
|---|---|---|
| 第一步 | 用免费测试档生成一条网址 | 能生成，参数回显正确 |
| 第二步 | 脚本调一次，解析出条数与预期一致 | 20 条不被切成 1 条 |
| 第三步 | 换一次城市，再调一次 | 地址是否变化与台账记录一致 |

三步跑通，再按订单数铺开。测试额度能否覆盖 API 提取，平台没有公开写，以客服和后台提示为准。**铺开前先确认一件事：你的订单是不是都挂在同一个账号下——同一账号的订单续费日接近，台账可以合并管理。**

## 常见问题

**问：能不能只用一个网址，把名下所有订单的 IP 都取出来？**
不能。生成的网址带着所选订单的上下文，换订单就得再生成一条。批量的形态是「多条网址并行调」。

**问：换城市之后，之前生成的网址还能用吗？**
看「服务器地址格式」选的是哪一项。选固定域名，地址不变，但换线后几分钟内可能还连到旧地址；选常规地址格式，换线后要重新导出拿新地址。

**问：20 条线路选哪一档最省？**
只取号不跑带宽，1M 档 2.6 元/条，20 条 52 元/月；要跑游戏或常规多开，10M 档 6 元/条，20 条 120 元/月。**带宽不够导致的失败，比省下的 68 元贵得多。**

**问：脚本取到 0 条，先查什么？**
先查订单到期日，再查返回口径有没有被改。这两项占静默失败的绝大多数，脚本本身很少突然坏掉。

**问：L2TP 也能用 API 自动取号吗？**
不能。API 对应软件级代理（SK5/HTTP），L2TP 是整网隧道，配置在软路由里。以后台实际菜单为准。

**问：多条网址会不会互相影响？**
不会，各订单独立。但所有网址都从同一个账号的同一个后台取，取号频率过高时会一起被限流，所以调度时间要错开。
