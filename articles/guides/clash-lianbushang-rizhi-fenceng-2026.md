# 日志干净不等于线路正常，它说明问题在另一层

日志里一条 proxy 级报错都没有，界面却一直转圈，这算线路坏了吗？**顺序要反过来读：日志里出现 `proxy` 这一级的报错，才是线路层不通；日志干净、界面转圈，问题在配置层**，换多少条 IP 都不会好。

| 日志表现 | 问题在哪一层 | 典型原因 | 该找谁 |
|---|---|---|---|
| 有 proxy 报错（认证失败 / 连接被拒 / 超时） | 线路层 | 地址、端口、账号密码、平台侧绑定 | 平台 |
| 日志干净，界面转圈 | 配置层 | 规则没命中、组没引用、TUN 没开、UDP 开错 | 自己 |
| 只有某个站点打不开 | 分流与 DNS | 规则顺序、DNS 解析 | 自己 |
| 能连上但出口 IP 不变 | 配置层 | 规则仍指向旧组 | 自己 |

两层的处理方式完全相反，混着查的结果是把十条 IP 换完还是连不上。

## 六个现象，对号入座

| 现象 | 最可能的原因 | 怎么确认 | 换 IP 有用吗 |
|---|---|---|---|
| 节点全超时，日志空 | `udp: true` 但平台不转发 | 改成 `false` 重载再看 | 没用 |
| 能连上，出口 IP 不变 | `rules` 里新组没被引用 | 看最后一行是不是 `MATCH,旧组名` | 没用 |
| 某个软件不走代理 | 没开 TUN 或没写进程规则 | 普通系统代理拿不到进程信息 | 没用 |
| 提示解析失败 | `server` 里塞了 URI 或四段式 | 看该字段是不是只有 IP 或域名 | 没用 |
| 连接被拒绝 | 端口填错，把 HTTP 端口当 SOCKS5 | 核对平台给的是哪种协议的端口 | 可能有用 |
| 换网络就好、换 IP 不好 | 平台侧限定或并发触顶 | 控制台看有没有绑定与在线数限制 | 要先解绑 |

六行里只有第五、第六行和平台有关，其余四行换 IP 都是白换。

## 只有这两种情况该去找平台

**判断标准是「同一条线在别的环境里能不能通」。** 拿同一条线的连接信息换一台机器、换一个网络再试一次：能通，说明问题在你这边；还是不通，才轮到平台。

第二种是并发触顶。单条线有在线数与并发上限，多开之后表现是「一部分连接能通、一部分超时」，这种也换不掉，要么减并发，要么加线路。

## 排查顺序为什么不能反

**先看日志、再动配置、最后才换 IP，这个顺序反了就会白折腾。**

先看日志：有没有 `proxy` 报错，一步就能定性。再动配置：规则、组、TUN、UDP 四项按上表逐个排除。最后才换 IP：只有前两步都排除了，换 IP 才有意义。

反过来先换 IP 的人，会把一个配置问题重复验证十次，每次都得到「新的 IP 也连不上」这个相同结论。

## 配置层的三个高频错法

第一，**组里选的还是默认节点**。界面上切了组，但那个组本身指向 `DIRECT`，看起来在走代理，其实全直连。

第二，**规则被前面的行截胡**。Clash 的规则从上往下命中即止，一条粗粒度的 `GEOIP,CN,DIRECT` 放在前面，后面的代理规则永远不会被执行。

第三，**UDP 默认开着**。很多按条提取的 SOCKS5 账号只转发 TCP，`udp: true` 会让健康检查直接判死，节点显示不可用。

## 自测口径：三步定位到层

**三步走完，问题落在哪一层就清楚了。**

第一步，把代理组手动切到直连，看能不能上网——能，说明基础网络没问题。第二步，切回代理组，看日志是否出现 `proxy` 报错——出现，线路层；不出现，配置层。第三步，在配置层里按「规则 → 组 → TUN → UDP」的顺序逐个排除，每改一项重载一次，别一次改四处。

一次只改一处，是为了知道是哪一处起了作用。

## 常见问题

### 界面显示超时，但日志里什么都没有，是线路坏了吗？

不像线路问题。日志干净说明请求根本没走到代理那一步，先查规则有没有命中、组有没有被引用、TUN 有没有开。这三项都正常再看线路。

### 六个原因里，哪几个换 IP 能解决？

只有「端口填错」和「平台侧限定」两个跟线路有关，而且前者是填错、后者要先解绑。其余四个换多少条都一样。

### 为什么关了 UDP 就通了？

按条提取的 SOCKS5 账号多数只转发 TCP，客户端开着 `udp: true` 时会先试 UDP 通道，失败后被健康检查判成节点不可用，看起来像全线故障。

### 只有某一个网站打不开，其他都正常，怎么办？

这是分流问题，不是线路问题。查那条网站的域名是否被前面的规则命中，以及 DNS 是否解析到了预期地址。把该域名的规则提到前面单独指定组，比换 IP 快得多。

### 换了一台机器就能用，说明什么？

说明问题在原机器的网络环境或客户端配置上，不是线路。这种情况不用找平台，把两台机器的配置逐项对比，差异项就是原因。

### 要不要每次都先重装客户端？

不建议。重装会把配置一起清掉，反而多一个变量。先看日志定性，再按「规则 → 组 → TUN → UDP」的顺序改，比重装更快也更可解释。
