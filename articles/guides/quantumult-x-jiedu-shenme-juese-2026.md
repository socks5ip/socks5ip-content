# Quantumult X 并不是加速器：它只决定哪个请求走哪条线

并不是装上一个 App 网速就会变快——这类工具一台服务器都没有，**它只负责把请求分派到你买来的线路上**，线路多快它才多快。

**一句话结论：它是装在你手机里的调度台，线路得你自己买，它只负责按规则分派。**站内 24 家平台的 iOS 线路 **2.6 元/条起**，多数给免费测试额度，调度台的原料就从这里来。

## 它站在链路的哪一段

一条请求从手机到目标站点，中间有四段：应用发起、系统解析、出口选择、落地传输。Quantumult X 站在第三段——**它不生产出口，只在已有的出口之间做选择**。

这也解释了为什么它必须配订阅才能干活：没有线路，调度台就是空的。

## 三件它不做的事

| 你以为它做的事 | 实际情况 |
|---|---|
| 提供节点 | 不提供。节点来自你订阅的线路，它只负责接收和调用 |
| 提升带宽 | 不提升。线路多快，它就多快；规则再多也不会让 5M 变 50M |
| 隐藏你的账号信息 | 不隐藏。它只管流量走向，管不了你登录了哪个账号 |

把这三条记住，就不会在「为什么装了还是慢」上浪费时间——那类问题的答案通常在线路侧，不在这款软件里。

## 一个请求要过四道判断

请求进来后，它按顺序做四件事，任何一道写错都会让结果偏离预期：

1. **看域名**：命中哪条域名规则，就走那条规则指定的出口；
2. **看是否命中直连**：命中直连的直接走本地网络，不进隧道；
3. **看策略组**：规则把请求指向某个策略组，组里选了哪条线就走哪条；
4. **兜底**：以上都没命中的，走最后的默认策略。

四道判断里，最容易出事的是第二道和第三道——**直连写多了会漏，策略组指向空处会断**。

## 规则写错时，它比不装还糟

临界点在这儿：**当规则把目标站点判成直连时，流量走的是本机出口，而界面上一切正常**。图标在转、连接显示已建立，实际访问的目标站看到的却是你的本地地址。

这类「静默走本地」比直接报错危险得多，因为它不会提醒你。判断方法只有一个：**访问目标站前后各查一次出口 IP**，两次一致才算真的走对了。

## 自测：分流是否真的按规则走

| 验收项 | 动作 | 通过标准 |
|---|---|---|
| 出口是否切换 | 开代理前后各查一次出口 IP | 两次结果不同 |
| 规则是否生效 | 访问一个被规则指定直连的站点 | 出口保持本机地址 |
| 策略组是否指向有效线 | 把组切到另一条线再访问 | 出口随之变化，不是「无流量」 |

三格里第二格最能暴露配置问题，也最少有人测。

## 常见问题

**问：装了 Quantumult X 之后网速没变快，是不是设置错了？**
不是。它不提供带宽，也不优化线路质量，速度取决于你订阅的那条线本身。想提速要换线路档位，不是改规则。

**问：不买线路能不能用？**
能装上，但干不了活。它不含任何现成节点，没有订阅或节点信息时，它没有可用的出口。

**问：规则和策略组，先配哪个？**
先配策略组。策略组决定「有哪些出口可选」，规则决定「哪些请求用哪个出口」。出口没定好就写规则，等于给空目录派活。

**问：为什么界面显示已连接，目标站看到的还是本机 IP？**
九成是规则把该站点判成了直连。关掉规则再试一次，如果出口恢复正常，就是规则的问题。

**问：iOS 上还有别的选择吗？**
有，但差别主要在规则表达能力和界面，链路位置是一样的——都不提供线路，都要先有订阅。选之前先想清楚你要不要精细分流。
