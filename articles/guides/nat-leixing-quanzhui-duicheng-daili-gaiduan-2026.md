# NAT 类型不决定网速：全锥、受限、对称改的是同一张映射表

同一个房间，两边都在线，为什么就是进不去？换线路、升带宽、换平台都试过，症状一模一样——因为卡点在 NAT 映射，而带宽和地区都不参与这件事。

NAT 类型常被当成一个「网络质量指标」，类型差就以为线路差，于是换平台、升档位，结果同一个房间还是进不去。它跟带宽、丢包、延迟都不在一条轴上。真正参与判断的只有一件事：两台机器能不能互相找到。

**一句话结论：NAT 类型由「映射」和「过滤」两套独立策略组成；只有需要两台机器直接互连的业务才吃这一项，挂上代理之后，STUN 报回来的是平台出口的映射，你家路由器的类型已经不在链路上。**

| 判断项 | 结论 |
|---|---|
| 最吃 NAT 的场景 | P2P 房间联机、主机直连、局域网联机模式 |
| 最不吃 NAT 的场景 | 专用服务器型网游、电商后台、数据采集（只要 TCP 通） |
| 一步判型 | 两个不同目标的 STUN 报同一外部端口＝锥形；报不同＝对称型 |
| 挂代理后测到的是 | 平台出口的映射，不是你家路由器 |

## 映射和过滤是两张表

映射讲的是「内部地址怎么变成外部地址」：内网 192.168.1.20:50000 出门，路由器用一个公网 IP 加一个外部端口替它记账，回包按这张表送回来。过滤讲的是「外面的包能不能进来」：即使外面的人知道你映射后的地址，路由器也可能因为「你没先跟它说过话」而丢掉这个包。

RFC 4787 把两套策略各分三档：

| 策略 | 与目标无关（最宽松） | 与目标地址相关 | 与地址和端口都相关（最严） |
|---|---|---|---|
| 映射 | 一个内部地址固定一个外部端口 | 换目标 IP 就换端口 | 换目标 IP 或端口都换端口 |
| 过滤 | 谁发进来都放行 | 只放行你发过包的 IP | 只放行你发过包的 IP:端口 |

家用路由器最常见的是「映射与目标无关 + 过滤与端口相关」，也就是端口受限锥形；企业防火墙和运营商级 NAT 更多落在最严的那一档。

## 三种锥形的映射一样，只差门禁

全锥、受限、端口受限这三型，映射行为一模一样，差别只在外人能不能把包送进来，越往后越要先打过招呼。三个名字听起来像三种网络，其实它们是同一张映射表配了三种门禁。

举个具体例子：内网机器 192.168.1.20:50000 访问了 2.2.2.2:6000，路由器分配的外部地址是 1.1.1.1:40000。此刻另一台机器 3.3.3.3:7000 想把包发到 1.1.1.1:40000：

| 类型 | 3.3.3.3:7000 能不能进来 | 门禁规则 |
|---|---|---|
| 全锥形 | 能 | 任意源地址、任意源端口都放行 |
| 受限锥形 | 有条件能 | 你之前访问过 3.3.3.3，源端口不限 |
| 端口受限锥形 | 有条件能 | 你之前访问过 3.3.3.3:7000 这个具体端口 |
| 对称型 | 基本不能 | 每次换目标都换外部端口，对方拿到的地址已作废 |

所谓「打洞」，本质是主动去满足门禁：双方各自往对方的映射地址发一个包，在各自的过滤表里开一个洞，之后对方进来的包就能过。这个动作在锥形下成功率高，因为洞开一次就长期有效、映射地址不变。

过滤严不严只影响「谁主动发起」。如果双方都由一台有公网地址的服务器牵线中继，过滤再严也照常通信——这也是绝大多数现代网游并不在意 NAT 类型的原因。

## 对称型的麻烦在端口不可预测

对称型每换一个目标就换一个外部端口，对方刚拿到手的地址立刻作废。它的危害不在「更严格」，而在「不可预测」：你以为拿到的是长期地址，实际上那是一次性的。

还是上面那个场景：同一台内网机器访问 2.2.2.2:6000 得到 1.1.1.1:40000，紧接着访问 4.4.4.4:8000，拿到的可能是 1.1.1.1:40017。第三方即使通过服务器交换到了 40000，等你回头去连对方时，自己的映射已经换成 40017，对方的过滤表里没有你。

剩下一条路是端口猜测：公网可用端口大致在 1024 到 65535 之间，六万多个位置，猜几十次命中概率不到千分之一，而且高频探测很容易被目标站的风控直接拦掉。工程上的结论很干脆：两侧都是对称型，几乎不可能直连。

哪些环境注定是对称型？运营商级 NAT 下的 4G／5G 上网、随身 WiFi、物联卡，以及大部分云主机的默认网络。在自己家里能把路由器改成宽松映射，在运营商的设备上没有任何设置入口。

## 两个 STUN 各测一次就能判型

不用装专业工具，两条命令就够：找一个能返回外部地址的 STUN 服务测两次，第二次换一个不同目标 IP 的服务，比较两次报回来的端口号。

| 两次结果 | 判型 | 能不能打洞 |
|---|---|---|
| 同一外部 IP、同一端口 | 锥形（进一步看过滤档位） | 能 |
| 同一外部 IP、不同端口 | 对称型 | 基本不能 |
| 两次外部 IP 都不同 | 走了多出口或负载均衡 | 需固定单出口再测 |

测的时候注意两点：一是必须关掉所有代理再测，否则测到的是出口那边的映射；二是两次测试之间不要重启路由器，重启会重新分配端口。

## 挂上代理之后，这张表换人做了

代理改变的是「谁在做映射表」，改不了「要不要做映射表」这个事实。挂上代理之后，STUN 报回来的是平台出口的映射类型，你家路由器那一层被跳过了。

由此得到两条实用结论：

1. **要判自家网络，必须直连测**。挂着代理测出来的类型，跟你的本地环境无关。
2. **要判能不能联机，测代理出口那一段**。有些平台的出口本身就是对称型，换成独享线路或者换平台才可能改善。

## 常见问题

**问：NAT 类型差是不是网速就慢？**
答：不是。类型只影响「别人能不能主动连进来」，跟带宽、延迟、丢包不在一条轴上。网速慢要查线路和本地出口。

**问：怎么知道自己是全锥还是端口受限？**
答：锥形三型的映射一样，区别在过滤。用两个不同的源端口从外部往你的映射地址发包，能收到就是全锥，收不到但同 IP 不同端口能收到是受限，必须同 IP 同端口才收到是端口受限。

**问：手机热点为什么联机总失败？**
答：移动网络的运营商级 NAT 多是对称型，外部端口每次都在变，对方拿到的地址立刻失效。

**问：挂了代理，NAT 类型会变好吗？**
答：测到的会是平台出口那一层的类型。锥形出口有帮助，对称型出口一样连不上，这时候要换线路而不是调本地设置。

**问：云服务器上的程序连不上对端，也是 NAT 问题吗？**
答：先看安全组和防火墙。云主机默认网络多为对称型，但更常见的原因是端口没放行。

**问：改路由器设置能变成全锥吗？**
答：部分家用路由器有「全锥 NAT」开关，开了会放宽过滤。但出口如果不是公网 IP，改了也没用，因为映射还在运营商那层。
