# 烽讯IP 的 API 怎么用？把提 IP 这件事的成本压到零

手动提 IP 的时间成本，在条数上到几十条之后会迅速盖过写脚本的一次性投入——烽讯IP 这次上线的「API 文档与调用示例」，做的就是把这套动作变成一条可长期调用的地址。

## 一句话结论

烽讯IP 这次新增的不是一条线路，而是一套**让程序自己去提 IP 的说明**：后台「SK5 API 提取」页上先选订单，再依次定好返回格式、换行符、输出格式与服务器地址格式，点「生成API网址」拿到一条可长期调用的地址；旁边的「API 文档与示例」负责解释这条地址怎么用、返回什么、出错怎么查。**手动提 IP 的成本是「次数 × 人工」，API 提 IP 的成本是先写一次脚本。**

| 关键项 | 口径 |
|---|---|
| 入口位置 | 后台「SK5 API 提取」页 |
| 控件数量 | 5 个：订单 / 返回格式 / 换行符 / 输出格式 / 服务器地址格式 |
| 生成动作 | 3 步：选订单 → 定格式 → 点生成 |
| 支持格式 | txt（纯文本）与 json（结构体） |
| 配套文档 | 接口说明、请求参数、返回格式、错误码及注意事项 |
| 线路价格 | SK5 1M 特惠档 2.6 元/月起，10M 游戏档 6 元/月 |

## 控件清单：五栏依次定什么

五个控件不是并列关系，而是有先后依赖：前一项定错，后面全要回来重配。

| 控件 | 定的是什么 | 定错会怎样 |
|---|---|---|
| 订单 | 从哪个已购套餐里提取 | 提到别的套餐的 IP，白花额度 |
| 返回格式 | txt 或 json | 选错要回来重配，脚本解析失败 |
| 换行符 | 多条 IP 之间怎么分隔 | 按行读取的脚本会把多条当一条 |
| 输出格式 | 输出的字段组合 | 缺少端口或账号，工具粘不进去 |
| 服务器地址格式 | 地址写法（常规地址 / 固定域名） | 某些客户端只认一种写法，另一种连不上 |

**这五栏里，前三栏是必须一次定对的。** 后两栏相对宽松，但也建议在正式接入前逐项试一遍。

## 返回格式选错的代价

txt 和 json 的选择看起来是小事，实际决定了你后面要不要再写一层解析。

| 返回格式 | 拿到手是什么 | 适合的消费方 | 代价 |
|---|---|---|---|
| txt | 纯文本，一行一条 | 直接粘进客户端、按行读取的脚本 | 字段顺序固定，取整条方便、取单个字段要再切 |
| json | 结构化对象，字段带名 | 需要按字段取值的程序 | 多一层解析，但字段含义明确 |

判断口径很简单：**下游是「人」还是「程序」。** 人要粘贴，就选 txt；程序要按端口、账号、地区这几个字段分别取值，就选 json。至于换行符，只有当你的消费方按行切分时才需要特别确认——**它决定的是「拿到几条」，而不是「拿到什么」。**

## 服务器地址格式差在哪

同一个出口，地址写法不同，客户端的接受度也不同。

| 写法 | 特点 | 典型适配 |
|---|---|---|
| 常规地址 | 直接给 IP 与端口 | 桌面代理工具、指纹浏览器 |
| 固定域名 | 用一个域名承载出口 | 只接受域名格式的客户端、部分软路由插件 |

**这一栏的意义不是「哪个更好」，而是「你的客户端吃哪种」。** 遇到「地址填进去连不上」的情况，先换一次这一栏的写法，往往比反复检查账号密码更有效。

## 三步拿到一条长期地址

| 步骤 | 动作 | 拿到什么 |
|---|---|---|
| 第一步 | 选订单 | 指定要从哪个套餐提取 |
| 第二步 | 定返回格式、换行符、输出格式、服务器地址格式 | 一段带参数的请求地址 |
| 第三步 | 点「生成API网址」 | 一条可长期调用的提取地址 |

这条地址的参数已经写死在链接里，**意味着以后不用每次回后台重新勾选**。把这条地址交给脚本或带定时任务的工具，就完成了从「手动提」到「自动提」的切换。

## 什么活该交给脚本，什么活手动更省

| 场景 | 更适合 | 理由 |
|---|---|---|
| 每天要提几十条以上 | API | 人工点击的时间成本迅速超过一次写脚本的成本 |
| 需要按业务节奏定时取用 | API | 定时任务可以直接调这条地址 |
| 只在一台机器上偶尔换一次出口 | 手动 | 写脚本 + 调试的时间比省下来的点击多 |
| 需要按返回值做分支判断 | API | 结构化返回便于程序处理 |

**判断标准是「提多少」和「提多勤」。** 一天几次、只在一台机器上用的场景，手动提反而更省事；一旦上到几十条、还要跟着业务节奏走，脚本的优势会立刻显现。

## 常见问题（FAQ）

**Q：txt 和 json 到底怎么选？**
A：看下游是「人」还是「程序」。直接粘进客户端就选 txt；要在程序里按端口、账号、地区分别取值就选 json。选错了要回后台重新生成一次地址。

**Q：生成的 API 地址会不会过期？**
A：地址本身可以长期调用，参数已经写死在链接里。需要注意的是套餐额度与有效期——地址有效，不代表套餐内的 IP 数量还有余额。

**Q：调用报错是地址写错了吗？**
A：先按「先检查订单、再检查格式」的顺序排。订单失效或选错套餐是最常见的成因；格式栏错位则通常表现为返回内容能拿到但下游解析失败。

**Q：脚本里需要做频率控制吗？**
A：需要。提取接口通常有调用频率限制，脚本里要加退避重试，而不是拿到报错就死循环重发——高频请求很容易被后端当成异常流量。

**Q：密钥怎么保管？**
A：只存在服务端的配置里，不要写进前端页面或公开仓库。请求地址一旦外泄，等于把套餐额度交出去。
