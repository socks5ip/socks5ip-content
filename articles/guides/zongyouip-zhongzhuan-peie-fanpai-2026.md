# 配额数字大不代表更好，只看你要开几条

100 条和 30 条，是同一台中转服务器上两组配额的上限，跟线路质量、带宽峰值一点关系都没有。两组的线路完全相同：国内 BGP 三网优化、带宽峰值 **200Mbps**。

中转的本质是端口转发——**本地端口 → 中转服务器 → 代理出口**。它改的是你到出口这一段路径，不是出口本身。

| 项目 | 免费组 | 收费组 |
|---|---|---|
| 线路 | 国内 BGP 三网优化 | 同样一组线路 |
| 带宽峰值 | 200Mbps | 200Mbps |
| 单台服务器转发上限 | **100 条** | **30 条** |
| 开通位置 | 静态代理 → 我的代理 → 选代理点「开通中转」 | 同左 |
| 启用方式 | 到「中转」详情取那组连接信息登录 | 同左 |

## 为什么配额会反着排

**免费组按「单台 100 条」封顶，收费组按「单台 30 条」封顶，看起来收费的更差，其实只是形态不同。**

收费组卖的是线路质量与优先级，条数上限压低是因为它面向的是「条数不多、但对链路很挑」的人。你要开 30 条以上，收费组单台接不住，只能走免费组——**这不是免费组更好，是你没得选。**

| 你的情况 | 怎么选 | 理由 |
|---|---|---|
| 要开 30 条以上转发 | 免费组单台就够 | 收费组单台上限 30 条，接不住 |
| 要开十几条，对线路很挑 | 可以看收费组 | 条数不多时，单台 30 条不会成为瓶颈 |
| 只想先跑通试试 | 随便选一组，先开 1 条 | 验证链路用一条足够 |

## 走中转，出口 IP 不会变

**这是最容易误会的一点：中转压的是延迟和抖动，不是身份。** 出口 IP 还是代理节点的 IP，归属地也不变。

| 对比项 | 直连代理 | 走中转 |
|---|---|---|
| 连接路径 | 你 → 代理出口 | 你 → 中转服务器 → 代理出口 |
| 出口 IP | 代理节点的 IP | 同一个 IP，不会变 |
| 链路跳数 | 一跳 | 多一跳 |
| 延迟取决于 | 你到出口之间的线路质量 | 你到中转服务器那一段的线路质量 |
| 适合的情况 | 直连本来就稳 | 直连抖动、丢包、绕行严重 |
| 额外风险 | 无 | 中转服务器本身成了新的单点 |

所以「IP 被目标站拉黑了，开中转能不能救」——不能。封的还是同一个 IP。要换的是代理节点，不是加一跳中转。

## 开通三步，第二步入错后面全废

**三步里只有第二步需要判断，但第一步和第三步最容易被跳过。**

| 步骤 | 在哪操作 | 你要决定什么 |
|---|---|---|
| 第一步 | 静态代理 → 我的代理，勾选代理点，点「开通中转」 | 给哪几条开；支持批量，但建议先开一条验证 |
| 第二步 | 弹窗里选分组（免费/收费），挑配额充足的中转服务器 | 单台剩余配额够不够你要开的条数 |
| 第三步 | 开通后进「中转」详情，复制连接信息，用它登录 | 原来那组连接信息要停用 |

第二步的关键是**「剩余」这两个字**。单台封顶 100 条是总量，不是给你一个人的，选之前先看一眼那台还剩多少。

## 开通后最容易错的一步：还在用原连接信息

**中转开通了、客户端里还是原来的地址和端口，等于没开。** 这是「开了中转延迟一点没变」的第一号原因，占了大部分误判。

| 现象 | 最可能的原因 | 怎么处理 |
|---|---|---|
| 开了中转，延迟毫无变化 | 客户端还在用原代理的连接信息 | 换成「中转」详情里那组地址和端口 |
| 提示配额不足 | 选的那台剩余条数不够 | 换一台，或减少这次要开的条数 |
| 走中转反而更慢 | 你到中转服务器那一段本身就差 | 换一台中转服务器，或退回直连 |
| 连不上、连接被重置 | 中转服务器在维护或已满载 | 换一台；仍不通就看代理点本身是否正常 |

## 该开和不该开，各三种情况

| 你遇到的情况 | 该不该开 | 说明 |
|---|---|---|
| 直连延迟忽高忽低、有丢包 | 该开 | 这正是中转的设计目标：换一条更顺的路径 |
| 同一个出口白天快、晚上慢 | 该开 | 高峰拥堵走中转能绕开一段 |
| 出口 IP 被目标站拉黑 | 别开 | 出口不变，封的还是同一个 IP |
| 想让出口显示成另一个地区 | 别开 | 换代理节点，不是加中转 |
| 直连本来就稳 | 别开 | 白多一跳，也多一个可能出故障的环节 |

## 自测口径：三步验中转是否真的生效

**判据不是「感觉快了」，是出口通路走的是哪一组地址。**

第一步，记录开通前的出口 IP 与延迟基线。第二步，换成中转连接信息后重查出口——**IP 应该完全一致**（一致才对，说明出口没变）。第三步，对比同一目标站连续二十次请求的延迟分布，看的是波动幅度而不是平均值。

三项都对，说明中转发的是路径；出口变了，说明你换的其实是代理节点，不是中转。

## 常见问题

### 免费组 100 条、收费组 30 条，是不是免费组更好？

不是「更好」，是配额形态不同。判断依据只有一条：你要开几条转发。超过 30 条，收费组单台接不住；十几条以内又对线路敏感，才轮得到收费组去比。

### 开了中转，出口 IP 会变成中转服务器的地址吗？

不会。出口仍是代理节点的 IP，中转只改你到出口这一段路径。如果出口变了，说明你换的是代理节点，不是开了中转。

### 中转能救被拉黑的 IP 吗？

不能。中转不改变出口 IP 与归属地，被目标站拉黑的还是同一个 IP。这种情况要换代理节点。

### 开通后延迟没变化，最可能是什么原因？

客户端还在用原来那组连接信息。开通中转后要进「中转」详情复制新的一组地址和端口，用它登录，原来那组要停用。

### 中转和多跳代理是一回事吗？

都多了一跳，但代价不同。中转是平台侧配好的端口转发，你只换一组连接信息，不用管中间认证；代理链要自己串两段，协议、认证、超时都得自己处理。

### 中转开着，代理点换国家了还能用吗？

原来的转发关系会失效，要重新开。更稳的做法是：长期要换点的业务走直连，线路抖动明显的固定业务才挂中转。
