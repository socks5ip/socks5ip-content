# 天行IP 推荐人账号留默认的 0，为什么会被拦

推荐人账号留默认的 0，为什么提交会被拦？因为 0 在这套校验里是「非空但无效」：它过了必填那一关，正好死在「纯数字且数值不超过 999999」这一条上。

**天行IP 注册表单共 8 个字段，「推荐人账号」那一格的初始值被页面写成 0，整页搜渠道号 tianxingA0 命中 0 次；这一格必须手动改成 tianxingA0，否则一定弹「此账号不可成为推荐人」。**

| 校验顺序 | 判的是什么 | 0 的结果 |
|---|---|---|
| 第一道：必填 | 字段是否为空 | 通过（0 是非空字符串） |
| 第二道：账号合法性 | 是否纯数字且 ≤ 999999 | 拦下，弹「此账号不可成为推荐人」 |
| 换成 tianxingA0 | 带字母，不命中数字段规则 | 通过 |

## 那个 0 是页面写死的占位值，不是链接带过来的

**把注册页整页抓下来能看到：初始化数据里 agent 的值是 "0"，其余七个字段都是空字符串——它是被写死的，不是从 URL 读的。**

这就解释了一个反复出现的误会：很多人以为「链接里带了渠道号，表单自然就填好了」。天行的落地页确实是按渠道分发的，地址里那一段只负责把你送到对应的页面，和表单里那一格是两件事。整页 HTML 搜不到 tianxingA0，就说明它从未进过这个输入框。

副作用很具体：框里既然有内容（哪怕是 0），人就默认「已经填好了」，一路填到提交，问题才在最后一步暴露。报错文案又偏偏写成「不可成为推荐人」，读起来像在禁止你填推荐人，而不是说你填的这个号不合格。

## 两道校验一前一后，0 恰好过第一道、卡在第二道

**必填判断只看字段有没有值，0 作为字符串是有值的；合法性判断专门排除「123456789」和「纯数字且 ≤999999」这两类号段，0 正好落在第二类里。**

把两道判断连起来看，报错看起来自相矛盾，其实是同一套逻辑的两段：第一段放行，第二段才拒绝。所以你不会看到「推荐人必须填写」，只会看到「此账号不可成为推荐人」。

反过来，带字母的渠道号不命中这条数字规则。它要排除的是明显的测试号和小号，不是「所有填了东西的人」。想通这一点，改法就只有一个：把那一格清空重填，填 tianxingA0。

| 你看到的提示 | 真实含义 | 该改哪里 |
|---|---|---|
| 推荐人必须填写 | 这一格是空的 | 填 tianxingA0 |
| 此账号不可成为推荐人 | 号码格式不合格（纯数字小号） | 清空后填 tianxingA0 |
| 提交后一切正常但归属没挂上 | 链接落地页与表单没对上 | 回头核对这一格内容 |

## 八格表单里，只有这一格需要从链接搬一次

**八个字段是用户名、密码、确认密码、邮箱、QQ、手机号、短信验证码、推荐人账号；前七个按你自己的信息填，第八个要照着渠道号抄一遍。**

这一步之所以值得单独讲，是因为它不像「填资料」，更像「对暗号」：填错不报格式错，只报资格错。其余七项都是常规信息，唯独这一格决定新账号挂在谁名下。

顺手记一个判断口径：同一台电脑连续注册两个号时，第二遍这一格仍然是 0。它不会记住上一次的输入，也不会因为浏览器缓存变成渠道号——每次都要手动改。

## 注册完怎么确认归属真的挂上了

**登录后到账号信息页看「推荐人/上级」那一栏，显示 tianxingA0 才算挂对；显示空白或 0，说明这一格当时没改成。**

三个动作可以两分钟内验完：一看账号信息里的推荐人字段；二看有没有渠道专属的价格或套餐差异（渠道价通常体现为折扣档位不同）；三是一周后再看一次，确认没有被系统回退。

如果发现没挂上，多数平台不支持注册后补填推荐人，只能换邮箱重新注册一个号。这也意味着——第一次提交前把这一格看清楚，比事后找客服省事得多。

## 常见问题

**问：链接里已经有 tianxingA0 了，表单那格还填不填？**
答：要填。链接只负责把你送到对应落地页，不往输入框写值，整页里搜不到这个字符串就是证据。

**问：不填推荐人能不能注册成功？**
答：不能。这一格是必填，空着会提示「推荐人必须填写」，流程走不到下一步。

**问：填了别人的号会怎样？**
答：能注册，但归属算别人的，你拿不到渠道价，出问题时也找不到对应的人。

**问：报「此账号不可成为推荐人」是账号被封了吗？**
答：不是。它只说明这一格的号码格式不合格，最常见就是留着默认的 0。

**问：注册后还能补填推荐人吗？**
答：多数平台不支持，只能换邮箱重注册。所以提交前把这一格核一遍，比事后补救划算。

**问：一个渠道号能给几个账号用？**
答：没有数量上限的说法，同一个号下注册多个账号都算同一归属；但同一手机号、同一实名通常只能开一个。
