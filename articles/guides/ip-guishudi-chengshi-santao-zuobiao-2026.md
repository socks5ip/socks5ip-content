# IP 归属地显示隔壁城市：三套坐标各管一段

归属地库里那个城市名，从来不是使用者站在哪，而是这段地址被登记在哪个片区——一段登记在佛山的地址，在广州用着也完全正常。

**一句话结论：这三个值来自三套不同的库，谁都不代表「你站在哪」——城市栏的粒度就是到城市，经纬度是这一段地址段的登记中心点，地图上的点是拿经纬度画的示意图；拿它当门牌号用，必然得出「定位不准」的结论。**

## 一、三套坐标，各管一段

| 你看到的 | 它到底是什么 | 粒度 | 能不能当门牌号 |
|---|---|---|---|
| 城市名 | 这段地址在 IP 库里登记的归属城市 | 城市级，偶尔到区 | 不能，只说明落在哪个市 |
| 经纬度 | 该城市或该地址段的登记中心点 | 城中心，误差几公里 | 不能，同一城市共用一个点 |
| 地图上的点 | 把经纬度画到地图上的结果 | 与上一行同源 | 不能，它只是可视化 |

三栏里真正有信息量的是第一栏：城市。后两栏是它的派生品，看起来更「精确」，实际只是把城市级的结论换了个表达方式。

## 二、为什么会显示隔壁市

| 现象 | 真实原因 |
|---|---|
| 显示隔壁市或隔壁省 | 运营商按省集中出口，整省的移动用户共用一个出口池 |
| 手机流量与宽带显示的市不一样 | 移动网络走基站出口，与固网宽带不是同一套地址池 |
| 公司网络显示总部所在城市 | 企业专线登记地在总部，分支机构流量从总部出去 |
| 同一个 IP 隔几天查到的城市变了 | IP 库更新，或这段地址被重新分配给别的地区 |

第一条是电商与社媒运营最常撞上的：一条「看起来该在广州」的线，实际落到佛山的出口池，因为运营商在省一级做汇聚。这不算错，只是这段地址的登记地就在那儿。

## 三、地图上的点为什么偏一截

地图上的点有两种画法：按地址段登记的中心点画，或者按城市行政中心画。前者在省会城市往往落在市中心，后者干脆所有同城 IP 都叠在同一个点上。

所以「点在海边」或「点在市中心」都不说明什么。真要判断一条线落在哪个片区，看城市名加运营商，比看那个点可靠得多。

## 四、业务上该怎么用这一栏

| 你的需求 | 该看什么 | 不该看什么 |
|---|---|---|
| 判断这条线是不是目标城市 | 城市名 ＋ 运营商（ASN） | 经纬度、地图点位 |
| 判断同城两台设备是否一致 | 城市 ＋ ASN 两个字段都要对上 | 只看城市名 |
| 判断地址类型（住宅／机房） | 检测报告里的「类型」与「原生」两栏 | 归属地城市 |
| 判断线路是否真的换了地区 | 换线前后各查一次，比城市变化 | 后台显示的「可选地区」列表 |

第三行是关键：**归属地城市不回答「这条线干不干净」，它只回答「这段地址登记在哪」。** 干净与否要看类型、原生广播、以及是否被目标站标记。

## 五、两个最常见的误判

第一个误判是把「城市不准」当成「IP 有问题」。归属地库的误差是结构性的，换一条同城的线结果一样，换平台也一样，它不是你这条线独有的毛病。

第二个误判是拿城市栏去验收地区切换。后台写着可选 400+ 地区，实际给你的是省级出口池，城市名可能落在省会而不是你勾的那个市。验收方法只有一个：**换完之后实测一次出口 IP，看城市与 ASN，而不是看后台的勾选项。**

## 七、常见问题

### Q：为什么我的 IP 显示的城市和我实际所在地差了一个市？

因为归属地库记录的是「这段地址登记在哪个片区」，不是终端位置。运营商在省一级做出口汇聚、或把这段地址重新分配给相邻地区，都会让显示的城市偏一档。

### Q：手机流量和宽带查出来不是一个市，正常吗？

正常。移动网络走基站出口，固网走另一套地址池，两套库的登记地本来就不完全一致。做多账号运营时要按实际出口对齐，不要假设两者同城。

### Q：代理后台写着可选某个城市，为什么实测不是？

后台列的是可售地区，实际分配受出口池限制，省会城市常常代表整个省。验收标准是实测出口的城市与 ASN，不是后台的勾选项。

### Q：经纬度能不能用来判断两条线是否同一条？

不能。同城所有 IP 的经纬度往往落在同一个中心点，看起来一样；真正能区分的是 ASN 与地址段，前者看运营商，后者看前三段。

### Q：归属地显示得越精确，是不是说明这条线质量越好？

没有关系。精确度取决于 IP 库里这段地址的登记信息是否齐全，与线路速度、稳定性、是否被标记都不相关。选线还是要看类型、可用性与实测延迟。
