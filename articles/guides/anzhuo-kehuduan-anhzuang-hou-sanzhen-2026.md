# 新装的客户端先做三项自检

打开客户端的第一屏，先别急着填线路。三项离线自检加起来不到一分钟，却能决定后面的排查往哪个方向走——**把变量从三个减到一个**，比装三个新客户端都省时间。中间换了设备或换了新版本，也一样从这个顺序开始，后面的每一步都有确定的方向。

## 一、三项离线自检，不与线路发生关系

这三项都在没有线路的情况下就能做完，所以它们的结论是干净的：客户端要么是好的，要么不是。

| 自检项 | 正常表现 | 不对时说明什么 |
|---|---|---|
| 关于页 | 同时显示外壳版本号与 sing-box 内核版本号 | 只显示外壳版本，包被重新打包过 |
| 新建配置 | 点「+」能打开协议类型列表（SOCKS5 / HTTP 等） | 列表缺项或打不开，安装包不完整 |
| 日志页 | 不闪退，日志区没有持续的红色报错 | 一开就崩，通常是架构包下错了 |

三项都过，客户端这一层就可以排除了。接下来无论出现什么问题，都应该往参数和线路上找。**这一步的价值在于把变量从三个减到一个**，而不是省下多少时间。

## 二、首次打开的授权清单

第一次打开时会连着要几项系统授权，它们不会以报错的形式出现，缺少任何一项的表现都是"看起来装好了，实际不工作"。

| 授权项 | 缺了会怎样 | 在哪里补 |
|---|---|---|
| 系统隧道连接请求 | 客户端完全不工作，所有线路都连不上 | 应用内重新触发，或到系统设置的连接类权限里手动允许 |
| 通知权限 | 前台状态看不到，掉线无提示 | 系统设置 → 应用 → 通知 |
| 电池优化白名单 | 锁屏几分钟后连接被系统掐断 | 系统设置 → 电池 → 不受限制的应用 |
| 读取已安装应用列表 | 分应用代理列表为空，分流规则形同失效 | 应用内提示跳转，或系统设置的权限页 |

最后一项从 1.4.1 版本起才被显式声明，老版本不会提示你，这也是很多人觉得"分应用代理没用"的原因。**拒绝这一项不影响连通性，只影响分流，所以它最容易被当成"客户端坏了"。**

## 三、后台被掐断：保活三件套

装好能用、锁屏一会儿就断，这不是安装问题，也不是线路问题，是国产 ROM 的省电策略。三件事一起做才稳，只做一件通常还会掉。

| 动作 | 具体设置 | 为什么单独做不够 |
|---|---|---|
| 加入电池优化白名单 | 电池设置里选"不受限制" | 只能挡一层省电，后台冻结仍会发生 |
| 允许后台活动 | 应用管理里打开自启动或后台运行 | 部分 ROM 会在一段时间后重新收紧 |
| 最近任务里上锁 | 任务卡上加锁，阻止一键清理带走 | 防止手动清后台或系统清理进程时被杀 |

做完这三项之后，用一个普通业务连接挂着跑半小时再回来看看连接是否还在——**保活效果要靠一段时间的实际挂载来验证，打开设置页看不出结果。**

## 四、升级直接覆盖，降级要留后手

同一款客户端的版本升级不需要卸载，覆盖安装就会保留全部分组与配置。真正要留神的是反方向操作。

| 操作 | 是否需要卸载 | 数据影响 |
|---|---|---|
| 升级到更高版本 | 不需要，直接覆盖安装 | 节点、分组、分流规则全部保留 |
| 降级到更低版本 | 建议先备份 | 部分版本起数据库格式更新过，退回旧版会丢配置 |
| 换成另一个客户端 | 需要重装并重填参数 | 配置字段口径不同，照抄容易出错 |

留后手的动作只有一步：进工具的备份入口，把当前配置导出一次。几秒钟的操作，能在降级或换设备时省掉重录一遍节点和分组的时间。

## 常见问题

**Q：装完之后怎么判断是客户端的问题还是线路的问题？**
A：做三项离线自检：关于页能否显示内核版本号、能否新建配置、日志有没有持续报错。三项正常就说明客户端是干净的，问题出在参数或线路上。

**Q：拒绝授权弹窗之后，客户端还有救吗？**
A：有。系统隧道连接的授权是必须项，缺了它客户端完全不工作；到系统设置的连接类权限里手动允许就能恢复，不必重装。

**Q：分应用代理列表是空的，怎么修？**
A：补授"读取已安装应用列表"的权限。这项从 1.4.1 版本起才被声明，拒绝它不影响连接，只让代理列表为空，容易被误判成客户端故障。

**Q：锁屏几分钟后连接就断了，是线路掉了吗？**
A：先看是不是省电策略。把客户端加入电池优化白名单、允许后台活动、最近任务里上锁，三件一起做，再挂半小时验证。

**Q：升级新版需要先备份吗？**
A：升级方向是安全的，直接覆盖安装，配置和分组都会保留。要备份的是降级前的时刻——部分版本起数据库格式更新过，退回旧版本会丢配置数据。

**Q：自检都过了，还是连不上怎么办？**
A：这时候问题在客户端之外。先确认线路端口是否可达、鉴权参数是否与后台一致，再看出口归属是否正确。站内的真实握手检测可以直接把端口可达性测出来。
