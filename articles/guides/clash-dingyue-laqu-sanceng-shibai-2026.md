# 浏览器能打开，证明不了客户端能拉

订阅链接浏览器能开、客户端报错：重装客户端，还是回控制台换链接？先别选，这两条路都可能是错的。浏览器与客户端用的是两套 UA、两套 URL 编码规则，**「浏览器能打开」这句话什么都证明不了**。真正要先分清的是失败发生在哪一层。

| 现象 | 失败层 | 最可能的原因 | 怎么处理 |
|---|---|---|---|
| 转圈很久后超时 / 无法解析主机 | 网络层 | 本地 DNS 异常，或当前网络到该域名不通 | 换 DNS，或先关代理拉一次 |
| 提示 401 / 403 | HTTP 层 | 订阅到期、账号被重置、UA 不被接受 | 回控制台重新生成链接 |
| 提示 404 | HTTP 层 | 平台换了路径，旧链接失效 | 回控制台复制新链接 |
| 拉到了但解析失败 / 内容为空 | 内容层 | 返回的是 HTML 页面或 Base64 文本 | 确认是否需要解码，或链接指向了错误接口 |
| 解析成功但没有节点 | 配置层 | provider 没被任何策略组引用 | 补引用，或写进策略组 |

三层加一层，一共四种表现，处理动作互不通用。

## 先分清「整份订阅」和「只有节点」

**这是两件不同的东西，混着用是大部分「拉到了却不生效」的根源。**

| 对比项 | 订阅配置（远程 profile） | proxy-providers |
|---|---|---|
| 提供什么 | 整份配置：节点 + 策略组 + 规则 | 只有节点列表 |
| 更新方式 | 整文件替换，手改的部分会丢 | 只替换节点列表，规则和组保持你的 |
| 适合谁 | 想开箱即用 | 自己维护规则，只借用节点 |
| 常见误用 | 手改后被覆盖，白改 | 拉了节点但没被组引用，界面看不到 |

如果你在「配置」页手动加的东西每次更新都消失，那是远程订阅的整文件替换机制，不是客户端 bug。

## 六个原因，按出现频率排

第一，**本地 DNS 解析不到订阅域名**。表现是转圈后超时，换一个公共 DNS 或先在能通的网络里拉一次，之后再更新。

第二，**订阅已过期或被重置**。表现是 401 / 403。回控制台重新生成链接，旧链接会立刻失效。

第三，**平台换了订阅路径**。表现是 404。这种要回控制台复制新链接，自己猜路径猜不出来。

第四，**链接指向了网页而不是接口**。表现是拉到了 HTML，解析失败。判断方法是把链接直接贴进浏览器，看返回的是一段 YAML 还是一个页面。

第五，**内容是 Base64 文本**。部分平台输出的是编码后的节点串，客户端需要解码，或者链接要换成 `?flag=clash` 这类参数形式。

第六，**provider 没被引用**。表现最迷惑：日志显示拉取成功，界面上一个节点都没有。

## provider 的三个必填项

| 字段 | 作用 | 漏了会怎样 |
|---|---|---|
| `url` 或 `path` | 从哪拉，或读哪个本地文件 | 整段无效 |
| `path` | 缓存到本地的文件名 | 能拉，但每次重启重新下载 |
| `interval` | 自动更新间隔 | 不自动更新，线路失效了也不知道 |
| `health-check` | 健康检查地址与间隔 | 不通的节点仍显示可用，选了才发现连不上 |

第四项最容易被省略，也最影响使用体验：没有健康检查，节点列表看起来全是可用的，实际挑到哪条能通全凭运气。

## 拉下来了但没节点，问题不在订阅

**日志说「拉取成功」而界面空着，一定是引用没写。**

provider 只提供节点池，必须被某个 `proxy-groups` 用 `use:` 引用，才会出现在可选列表里。写法是组里加一行 `use: [供应商名]`，供应商名要和 provider 的键名一致，大小写都算。

引用加对了还看不到，再查两处：组本身有没有被 `rules` 指向、客户端的「当前配置」是不是你改的那一份。

## 自测口径：四步定位到层

**每一步都对应一层，跳过任何一步都会误判。**

第一步，浏览器里打开订阅链接，看返回的是 YAML、页面还是编码文本——这一步定内容层。第二步，把链接贴进命令行用客户端同款 UA 拉一次，看状态码——这一步定 HTTP 层。第三步，换一个 DNS 再拉，看是否还超时——这一步定网络层。第四步，看配置文件里 provider 有没有被 `use:` 引用——这一步定配置层。

四步都过，问题只可能在客户端版本上，换一版再试。

## 常见问题

### 浏览器能打开订阅链接，为什么 Clash 拉不到？

浏览器有完整 UA 和自动编码，Clash 用自己的 UA、按自己的规则切分链接。浏览器能打开只说明域名通，不说明客户端能被接受。要按 401、404、超时三种表现分别处理。

### 订阅更新之后我手加的节点全没了，怎么办？

这是远程订阅的整文件替换机制。要长期保留自己的节点和规则，改用 `proxy-providers` 只借节点列表，或者把改动写进「合并 / 脚本」这类不会被覆盖的位置。

### 提示 401 是不是账号被封了？

多数情况是订阅到期或链接被重置，不是封号。回控制台重新生成一次订阅链接，用新链接替换旧的即可。

### 拉取成功但一个节点都没有，是什么原因？

provider 没被任何策略组引用。它只提供节点池，必须用 `use:` 挂进组里才会显示，挂进去之后还要确认「当前配置」是你改的那一份。

### 订阅链接能不能自己改参数？

一般不建议手改。参数形式由平台决定，改错会落到另一个接口、返回 HTML 或 404。需要换输出格式时，用控制台提供的选项，不要拼参数。

### 多久更新一次订阅合适？

按平台给的 `interval` 来，通常几小时一次足够。间隔设得太短，遇到接口限流反而会拉取失败；设得太长，线路失效了你还不知道。
