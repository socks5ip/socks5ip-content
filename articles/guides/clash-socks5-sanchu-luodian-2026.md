# 登记的代理不等于会用的代理

在 Clash 里填完地址、端口、账号密码，流量却纹丝不动——原因其实不是填错，是那条代理还挂在 `proxies` 里没被任何策略组引用。Clash 的配置是三层结构，**只有三处都落到位，流量才会真的过去**。

| 层 | 写在哪儿 | 起什么作用 | 缺了会怎样 |
|---|---|---|---|
| 第一层 | `proxies` | 登记一条候选线路 | 界面上看不到这条代理 |
| 第二层 | `proxy-groups` | 把它挂进某个可选的组 | 组里选不到，等于没有 |
| 第三层 | `rules` | 让流量命中那个组 | 全部流量走默认出口，出口 IP 不变 |

这三层不是「进阶用法」，是最小可用配置。多数「加了没反应」的配置，第一层都是对的。

## 六个字段，错一个整段作废

**SOCKS5 在 Clash 里的字段是固定的六项，格式错一项，整段配置就解析不了。**

| 字段 | 填什么 | 常见错误 |
|---|---|---|
| `name` | 自定义名字，如「上海-独享」 | 用中文标点，解析失败 |
| `type` | `socks5` | 写成 `socks` 或 `sk5` |
| `server` | 只写 IP 或域名 | 把 `IP:端口:账号:密码` 整串塞进来 |
| `port` | 纯数字 | 带空格或引号 |
| `username` / `password` | 各写各的 | 只填一个，或两个都空 |
| `udp` | 平台支持才写 `true`，不确定写 `false` | 平台不转发 UDP 却写 `true`，节点全超时 |

第四行是最高频的错误。平台给的是四段式连接信息，`server` 只收第一段，其余三段各有各的字段。

## 三种配法，按你要解决的问题选

| 做法 | 写在哪 | 适合 | 代价 |
|---|---|---|---|
| 单节点写死 | `proxies` + 手动选择组 | 一条固定 IP 长期不变 | 换 IP 要改配置并重载 |
| 订阅动态拉取 | `proxy-providers` | 按量提货、IP 会轮换 | 需要平台提供订阅链接或 API |
| 链式两跳 | `relay` 组 | 先过国内一段再出境外 | 延迟叠加，链路更长更易断 |

固定 IP 的业务（店铺后台、账号登录）用第一种，配好之后基本不用再动。需要轮换的采集类业务用第二种，规则和组自己维护，只借用节点列表。

## 配完怎么验，才算真的配好

**判据只有一条：出口 IP 变了，而且变的是你那条线所属的城市。**

第一步，配之前先用检测页记下当前出口 IP 与归属地。第二步，把 `rules` 里最后那行 `MATCH` 指向新组，重载配置。第三步，再查一次出口，IP 与归属地都应该跟着变。

三项里第一项和第三项容易漏。只看到「节点显示绿色」不算配好——绿色只说明握手通了，不代表流量走了这条路。

## 五个最常见的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 界面上找不到新加的代理 | 没被任何策略组引用 | 补进 `proxy-groups` 的 `proxies` 列表 |
| 能选中，但出口 IP 不变 | `rules` 没指向新组 | 改最后一行 `MATCH,组名` |
| 只有某个软件不走代理 | 没开 TUN，或没写进程规则 | TUN 与 `PROCESS-NAME` 要配对 |
| 节点全超时 | `udp: true` 但平台不转发 | 改 `false` 后重载 |
| 提示无法解析 | `server` 里塞了完整 URI | 只留 IP 或域名 |

## 自测口径：两查一对比

**两查是查配置、查出口，一对比是对比改之前与改之后。**

查配置：打开当前生效的配置文件，确认那条代理同时出现在 `proxies`、某个组的 `proxies` 列表、以及至少一行的目标位置。查出口：用检测页看 IP 与归属地。对比：把两次结果并排看，出口没变就是没生效。

只做「界面显示已连接」这一步，等于没验。

## 常见问题

### 代理加进 Clash 了，为什么浏览器里查出来还是本机 IP？

因为只做了登记，没做引用和分流。`proxies` 里那条只是候选，必须被策略组引用、并且 `rules` 命中那个组，流量才会过去。补上这两处再重载。

### `server` 里能直接写平台给的整串连接信息吗？

不能。平台给的是 `IP:端口:账号:密码` 四段式，Clash 要求拆开填：`server` 只收 IP 或域名，`port` 收端口，账号密码各有字段。整串塞进 `server` 会报解析失败。

### 加了代理之后网速变慢，是线路问题吗？

先分两步看。把 `rules` 改成全部走直连，如果速度恢复，说明慢在代理段；如果还是慢，问题在本地网络或目标站。代理段的延迟用线路检测页测，别用感觉判断。

### 一条 SOCKS5 能不能同时给多个软件用？

能，只要这些软件的流量都命中同一个组。但要注意并发上限是平台侧定的，软件越多越容易触顶，触顶后的表现是部分连接超时。

### TUN 模式必须开吗？

看你需不需要按进程分流。只做全局或按域名的分流，普通系统代理就够；要让某个软件单独走代理，必须开 TUN 并配 `PROCESS-NAME`，因为普通代理拿不到进程信息。

### 改完配置需要重启客户端吗？

多数情况重载配置就够，改的是 `proxies` 里的字段时建议重载一次再看。如果界面显示的还是旧配置，先确认「当前配置」指向的是你改的那一份。
