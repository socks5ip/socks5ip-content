# vmess:// 与 ss:// 解开是什么：逐字段对照

把那串以 vmess:// 开头的字符粘进解码框，出来的是一段带缩进的 JSON——它从头到尾都不是加密。

**一句话结论：vmess:// 是「JSON 套一层 Base64」，ss:// 是「加密方式与密码先 Base64、再拼上服务器和端口」，两者都能被完整还原成明文，所以这类链接等同于账号密码，转发一次就等于把节点交出去了；而 UUID 是服务端生成的标识，解码只能看到它，不能反推出密码。**

## 一、三种链接，三种结构

| 协议 | 里面装的是什么 | 解开后看到 |
|---|---|---|
| vmess:// | 一整段 JSON 做了 Base64 | v / ps / add / port / id / aid / net / type / host / path / tls |
| ss:// | SIP002 格式：Base64(加密方式:密码) 拼 服务器:端口 | 加密方式、密码、服务器、端口、备注 |
| vless:// / trojan:// | 明文 URL 加查询参数 | UUID 或密码、sni、type、host、path、security |

只有前两种需要解码，后两种本来就是明文——你看到的字符串就是最终字段，只是被 URL 编码挡住了。

## 二、vmess 的十一个键，各管什么

| 键 | 含义 | 填错会怎样 |
|---|---|---|
| v | 协议版本，常见是 2 | 客户端不认这个版本会直接拒绝导入 |
| ps | 备注名，只影响显示 | 随便写，不影响连接 |
| add | 服务器地址 | 写成域名解析不了就连不上 |
| port | 端口 | 与传输层不匹配时握手超时 |
| id | UUID，相当于用户名 | 错一位就认证失败 |
| aid | 额外 ID（alterId） | 与服务端不一致会握手被拒 |
| net | 传输方式：tcp / ws / grpc | 选错传输，端口通也不通 |
| type | 伪装类型，多为 none | 一般留空 |
| host | 伪装域名 | 走 ws 时填错会导致 404 |
| path | 路径 | 与 host 一起决定请求落在哪 |
| tls | 是否启用传输层加密 | 服务端要求而这里没开，握手失败 |

**这十一个键里真正决定「能不能连」的是 add、port、id、aid、net、path、tls 七个**，其余是显示与伪装用的。

## 三、ss:// 的 SIP002 拆法

ss:// 的标准写法是：Base64(加密方式:密码) ＋ @ ＋ 服务器:端口 ＋ #备注。解开 Base64 那一段，得到的是 `method:password`，例如 `aes-256-gcm:xxxxxxxx`。

所以一条 ss 链接能还原出四个值：加密方式、密码、服务器、端口。拼成一行就是 `服务器:端口:加密方式:密码`，这也是很多批量导入格式要求的顺序。顺序颠倒是最常见的失败原因——四个值都在，位置错了照样连不上。

## 四、什么情况下才真的需要解码

| 场景 | 要不要解码 | 原因 |
|---|---|---|
| 客户端报「链接格式不支持」 | 要 | 先看解出来是不是标准 JSON，缺键还是编码坏了 |
| 要批量导入到另一款客户端 | 要 | 转成目标客户端认的格式，而不是整条链接粘贴 |
| 想核对服务端给的是不是同一台机器 | 要 | 比对 add 与 port 两个字段就够 |
| 想找回密码 | 不要 | UUID 与密码都不是可逆的，解出来也变不回去 |
| 只想改个备注名 | 不要 | ps 字段可以直接改，不必整体解码 |

## 五、UUID 为什么变不回密码

UUID 是服务端在创建账号时随机生成的一串标识，它本身就是凭据——服务端记住这串值，客户端出示它就算通过。整条链路上不存在「明文密码」这个东西，所以任何解码工具都变不出密码。

这也解释了另一个常见误会：**把链接发给别人＝把节点借给别人**。对方不需要你的账号密码，解出来的 UUID 直接能用。分享前先确认这条线是不是独享。

## 七、常见问题

### Q：解出来的 JSON 里有一堆没见过的键，是节点有问题吗？

不一定。不同服务端会加自己的扩展键，客户端不认的会自动忽略。判断节点是否正常只看 add、port、id、net、tls 这五个是否齐备，其余键缺失不影响连接。

### Q：ss 链接解开后密码里带冒号，怎么拆？

SIP002 规定以第一个冒号分隔加密方式与密码，所以密码里可以有冒号，加密方式里不会有。按第一个冒号切，后面整段都算密码。

### Q：为什么同一个节点在两个客户端里，一个能连一个连不上？

多半是 net 与 tls 的默认值不同。有的客户端把 net 默认成 tcp，而服务端走的是 ws，端口通但握手失败；把 net 显式写成 ws、path 与 host 填对就能连。

### Q：链接能不能直接存到笔记里？

不建议。这类链接等同于凭据，存在公开或共享的笔记里，等于把节点分享给了能看到这篇笔记的所有人。要留档就存在本地加密文件里，或只记 add 与 port。

### Q：解码工具会不会把我的链接上传？

站内这个格式转换工具是纯浏览器本地处理，不发起上传请求。是否可信可以用一个办法验证：断网之后再粘一次，功能是否照常可用。
