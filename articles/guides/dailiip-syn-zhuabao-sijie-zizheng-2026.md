# 换 IP 后自证换没换：抓一个 SYN 看 TCP 头四项（2026）

64 和 128——同一个出口地址，两次抓包给出两个初始 TTL。把程序从机房代理指到本机拨号，地址没变，这一项却换了主人，目标站那边看到的已经不是你原来那台机器。

**一句话结论：**换 IP 只换得掉源地址，换不掉写在 TCP 头里的四个默认值：**初始 TTL、窗口大小、MSS、时间戳选项**。这四项由「谁跟目标站建这条连接」决定——走 SOCKS5 或 TUN 时是**平台机房**建的，四项统一成机房的系统默认值；走 L2TP 拨号时是**你自己电脑**建的，多台机器挂在同一出口上，等于把「多台真实机器」写进同一行记录。多账号场景优先用应用层代理，一台机器一条线。

## 一、四层里只有最下面一层是买来的

| 层次 | 留下什么 | 换 IP 之后 |
|---|---|---|
| 应用层（JS 能读） | UA、时区、Canvas、字体、WebGL | 不变，跟 IP 无关 |
| 加密层（TLS 握手） | ClientHello 的套件与扩展顺序，即 JA3/JA4 | 不变，由浏览器版本决定 |
| 传输层（TCP 头） | 初始 TTL、窗口大小与缩放、MSS、时间戳选项 | 取决于接法，不取决于 IP |
| 网络层 | 源地址、途经跳数 | 这是唯一真正被换掉的东西 |

四层里只有最下面那层是花钱买的。所以你换了几十个 IP 还被串起来，从来不是 IP 数量的问题——上面三层一个字都没动。

## 二、抓一个 SYN，三步

只要能看到「我发出去的包长什么样」，就不用猜。

1. **选一个能抓包的位置。** Windows 用 Wireshark 选对应网卡；Linux 直接 `tcpdump -i any -n 'tcp[tcpflags] & tcp-syn != 0'`。
2. **只抓握手。** Wireshark 过滤框写 `tcp.flags.syn==1 && tcp.flags.ack==0`，只留客户端发出的第一个 SYN，避免被后续数据包淹没。
3. **读四个字段。** 展开 IP 头看 TTL；展开 TCP 头看 Window size、MSS（Options 里的 Maximum segment size）、Timestamps 选项是否存在。

同一台机器、同一个目标，分别在不走代理、走 SOCKS5、走 L2TP 三种状态下各抓一次，三项结果放在一起对比，归属就很清楚了。

## 三、三种接法，四项分别归谁

| 四项 | SOCKS5 / TUN 网卡 | L2TP 拨号 |
|---|---|---|
| 初始 TTL | 机房系统默认（Linux 常见 64、Windows 常见 128） | 你本机的系统默认 |
| 窗口大小与缩放因子 | 机房网卡的默认值与内核参数 | 本机设置，随系统版本变 |
| MSS | 由机房 MTU 推导，通常 1460 | 由本机 MTU 推导，PPPoE 下常 1400–1480 |
| 时间戳选项 | 机房内核开关决定 | 本机内核开关决定 |

关键差别在「一致性」：走 SOCKS5 时，无论你有几台机器，目标站看到的都是机房那一套参数，天然统一；走 L2TP 时，每台机器各自建连，窗口缩放、时间戳偏移、MSS 都可能不同——**同一个出口地址上出现几种不同的 TCP 指纹，等于自报家门说这里有好几台机器**。

## 四、多账号为什么优先应用层代理

道理在这里：账号隔离要的是「一个账号对应一台稳定的机器」，而不是「一台稳定的机器跑十个账号」。

- 走 SOCKS5：目标站的 TCP 由机房建，你本机的差异被抹平。一台机器一条线，看起来就是「一台机器、一个出口」。
- 走 L2TP：TCP 由本机建，多台机器共用一条出口，目标站那边是「一个出口、多套指纹」，比不换 IP 更显眼。

所以正解不是「多买几条线让每台机器都拨号」，而是「按账号数买线，每个账号环境配一条应用层代理」。L2TP 留给整机转发的场景——软路由、整屋拨号、设备直连，那些场景本来就不追求账号级隔离。

一个提醒：TTL 在浏览器里查不到，因为 JavaScript 只能读应用层。但目标站前面若挂着 CDN 或 WAF，它在四层就收了这个包，TTL、窗口、MSS 全在它手上。所以能自测的只是「我发出去的包」，不是「目标站眼里的我」——两者的差，就是上面那个抓包实验要补的课。

## 常见问题（FAQ）

### Q：换了代理 IP，为什么网站还是认得我？

因为换的只是源地址。UA、时区、Canvas、Cookie、TLS 指纹全在本机，一个都没动。地址是最容易被替换的一层，也是最不稀缺的一层——真正的识别依据在上面三层。

### Q：怎么确认目标站看到的 TCP 参数是不是机房那一套？

自己抓一个 SYN 就能看出方向：如果四项与你本机的系统默认值一致，说明连接是你本机建的（拨号类接法）；如果 TTL 与你系统差一截（比如你 128、包里 64），说明是机房那台机器建的。

### Q：走 SOCKS5 和走 TUN 网卡，TCP 层有区别吗？

两者在目标站那边都是机房建连，四项基本一致。区别在于 TUN 会把所有流量都塞进去，包括不支持的 UDP 应用可能异常；SOCKS5 是应用层指定，可控性更好。

### Q：一台机器开十个账号，用一条线够吗？

不够。一台机器一条线只是「看起来像一台机器」，十个账号仍然落在同一个出口上。要隔离得按账号数配线，一个账号环境一条线；同一条线上跑多个账号，平台侧看到的是同一台机器在用多个身份。

### Q：抓包会不会影响正常上网？

不会。抓包是旁路复制流量，不改变转发路径。唯一需要注意的是别长时间开着抓全量包，容易把磁盘写满，用过滤条件只留握手就够了。
