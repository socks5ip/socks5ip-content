# IP 信息查询的三层指标：归属地对只过了第一关

把一条 IP 填进客户端，打开查询页看到归属地是本城，就回头去下单——这一步省掉的，恰好是后面最难补的两层。

**一条 IP 要过三关：握手通不通决定能不能连，延迟分级和丢包决定能不能用，住宅判定与纯净度决定会不会被认出来；归属地只是第一关里最容易满足的一项，对上它不代表后两关也过。**

| 层级 | 看什么 | 不合格的表现 |
|---|---|---|
| 第一层 能连 | SOCKS5 / HTTP 真实握手、端口开放 | 连不上、超时、返回 407 |
| 第二层 能用 | 延迟分级、丢包率、带宽 | 能连但频繁断、速度忽高忽低 |
| 第三层 不被认出 | 住宅/机房判定、纯净度、ASN | 一直出验证码、登录态频繁掉 |

数据来源：全网低价IP 检测流程整理（2026-11-23 核对）｜判据以实际业务表现为准

三层的失败表现完全不同，混在一起看必然得出错误结论。第一层是链路层，问的是「现在通不通」，结果非黑即白；第二层是质量层，问的是「通了之后稳不稳」，结果连续、只能分级；第三层是身份层，问的是「目标站认不认」，结果取决于对方规则，不取决于你怎么测。

## 第一关只认握手，不认端口亮不亮

**第一层的判据是布尔值：按协议真握手能不能完成，通就是通，不通再多指标都没意义。**

很多查询页给的是端口扫描结果，端口开着就标绿。但端口开着不等于协议能用——一台开着 1080 端口的机器可能根本不是 SOCKS5 服务，扫描器照样标绿。真实验证要按协议走一遍：SOCKS5 要完成 RFC 1928 的协商与方法选择，HTTP 代理要完成 RFC 7231 的 CONNECT。

这一层还能顺带分开两种失败：认证失败通常回 407（HTTP）或方法选择后被拒（SOCKS5），说明服务在、密码错；链路不通是超时，说明服务不在或路被挡。前者改密码，后者换出口，处置完全不同。

## 第二关看分布，不看某一刻的数字

**单次 ping 出来的 30 毫秒说明不了稳定，把一段时间内的延迟按区间统计，跑满一分钟才算数。**

网络抖动是常态：一条平时 30 毫秒、高峰 300 毫秒的线，你 ping 的那一下恰好落在低谷，就会得出「很快」的结论。有用的读法是分级——多少比例落在 50 毫秒以内，多少超过 200 毫秒。

丢包率比延迟更值得看。1% 的丢包浏览网页几乎感觉不到，跑长连接、传文件就是灾难，表现是「能连、能用、但老是断」。带宽要单独测：延迟跟路由跳数有关，带宽跟线路容量有关，一条 30 毫秒 2M 的线跑单线程够快，十个并发就挤爆。

这一层没有绝对标准，取决于业务：网页访问 200 毫秒以内、丢包 0 就够；长连接挂机丢包必须 0；视频与大文件先看带宽。

## 第三关测的是身份，不是线路

**同一地区、同一延迟，住宅标注和机房标注在目标站眼里是两类人，这一关决定成败。**

「住宅」还是「机房」来自 IP 数据库对地址段的标注，依据主要是 ASN 类型：挂在家宽运营商下面的段通常标住宅，挂在云厂商、IDC 下面的标机房。目标站的风控基本都读它。

纯净度是另一个维度，指这条 IP 的历史：有没有进过黑名单、有没有被大量滥用、有没有跟一堆账号共用。一条刚放出的住宅 IP 纯净度高，一条反复回收的机房 IP 纯净度低，两者在查询结果里可能显示同一个地区。

这两项加起来才是「会不会被认出来」的答案。查到归属地对、类型标着住宅就认定没问题，登录却仍要验证码——那多半是纯净度掉下去了，或者这段地址被目标站单独标记过。

## 三个最容易看错的指标

**归属地、单次 ping、端口状态，这三个指标最容易给人虚假的安全感，因为它们便宜、快、一眼能懂。**

| 指标 | 它实际回答什么 | 误读的后果 |
|---|---|---|
| 归属地 | 数据库认为你在哪 | 机房也按城市注册，对上了照样被认成服务器 |
| 单次 ping | 某一刻的往返时间 | 高峰期的真实延迟可能是它的十倍 |
| 端口状态 | TCP 端口有没有人应答 | 服务不对、协议不符时照样是「开」 |

比归属地更接近真相的是 ASN。标称「某地家宽」但 ASN 指向云服务商的，基本可以判定为机房段套了层皮；一批 IP 的 ASN 散在好几个不相干组织下，说明供货方没有自己的段，一致性最差。

再补一组一致性：时区、浏览器语言、DNS 解析地。IP 在洛杉矶、系统时区还是 UTC+8、Accept-Language 写 zh-CN，这三项在日志里一眼可见，比归属地错位更容易被识别。它们不要求与 IP 完全匹配，但必须自洽。

## 自测：五项按顺序走，三五分钟能走完

**自查顺序固定为握手、延迟分级、身份标注、一致性、业务模拟，前一项不过就不必往下走。**

1. 用对应协议真握手一次，确认不是端口亮着但服务不对。
2. 连跑一分钟延迟，统计落在 50 毫秒以内和超过 200 毫秒的比例。
3. 查 ASN 组织名与住宅/机房标注，对不上就换。
4. 时区、语言、DNS 三项对齐，任何一项跳回本地都不自洽。
5. 走一次完整业务动作——登录、进目标页、执行一次操作，别只测首页。

业务模拟放最后，因为前面的检查是筛子，它一旦跑起来结论权重最高：三层全绿但业务模拟失败，说明这套判据对当前目标不适用。

## 常见问题

**问：IP 信息查询看到归属地对，是不是就能用了？**
答：只能说明没明显错。归属地是初筛指标，住宅判定、纯净度和目标站的实际反应才是结论。

**问：开了代理还是本地 IP，是查询工具不准吗？**
答：先确认流量真的走了代理。多数情况是客户端只接管了部分进程，或者 DNS 还在本地解析，查询页读到的仍是本机出口。

**问：延迟 30 毫秒算好还是不好？**
答：单次数字没有意义。要看一分钟内的分布，以及丢包率；长连接场景丢包比延迟更致命。

**问：标着住宅但一直被要验证码，问题在哪？**
答：多半是纯净度或 ASN。这段地址可能被反复用过、进了黑名单，或者标注是住宅但 ASN 指向 IDC。

**问：三层都过了，业务还是失败怎么办？**
答：跑一次完整业务模拟，看拦截点落在第几个请求。风控常在登录后的第二、三个请求上触发，只测首页会得出过于乐观的结论。
