# 代理开着游戏还是本地 IP：WinINET 和 WinHTTP 是两套账（2026）

线买回来了、参数也填好了，游戏登录器里显示的仍是家里那条宽带。**代理能不能改掉某个程序的出口，取决于那个程序读不读代理设置，而不取决于你买的是哪条线。** 浏览器走系统代理，游戏和模拟器多数不读；要整机接管只能靠虚拟网卡，要按程序分线得靠进程级重定向。

| 你的现象 | 八成卡在哪一层 |
|---|---|
| 浏览器查 IP 变了，游戏里查还是本机 | 只到了系统代理层 |
| 系统代理填了，某下载器/更新器仍用本机 | 它走 WinHTTP，不读 IE 设置 |
| 装了虚拟网卡，国内站点却还是本地访问 | 客户端勾了「绕过局域网/大陆 IP」 |
| 模拟器里怎么查都是本机 IP | 宿主机接管没覆盖模拟器的 NAT |

数据来源：Windows 网络栈与 SOCKS5/HTTP CONNECT 工作机制；线路价格取自站内价格表页，核实于 2026-11-09。

## 一、那个框之前，先分清两本账

Internet 选项里那份代理只是 WinINET 的账，WinHTTP 另有一份，默认状态是直连。两套账各管一批程序，改了一套不等于两套都改。

WinINET 那份写在当前用户的注册表里（`HKCU\...\Internet Settings` 下的 `ProxyEnable` 与 `ProxyServer`），你在「Internet 选项 → 连接 → 局域网设置」里勾的那个框改的就是它。IE、Edge、Chrome 默认跟随它，一部分国产桌面软件也读它。

WinHTTP 是另一套，服务、后台更新、部分安装器和命令行工具会走它，它默认不跟随 IE 设置。查它只一条命令：`netsh winhttp show proxy`，输出「直接访问(没有代理服务器)」就是直连。要让 WinHTTP 跟着 IE 走，用 `netsh winhttp import proxy source=ie`。

注意这条命令的效果范围：它改的是本机 WinHTTP 的默认代理，对公司策略下发的配置可能被覆盖回去。所以它解决的是「后台程序也要走代理」，不解决「游戏要不要走代理」——游戏多数连 Winsock 都不经过系统这两套账。

顺带说一个反直觉的点：`curl` 在 Windows 上读的是环境变量 `http_proxy` / `https_proxy`，不读注册表。所以在 IE 里勾了代理，命令行裸跑 `curl` 仍从本机出口出去——这可以当验证工具用。

## 二、覆盖面各不相同，三个读数并存不算矛盾

| 接管层 | 覆盖谁 | 能不能转 UDP |
|---|---|---|
| 系统代理（WinINET / WinHTTP） | 读系统设置的浏览器、部分桌面软件 | 不接管 |
| 进程级重定向 | 按进程名命中的程序 | 依实现与线路 |
| 虚拟网卡 / TUN | 走默认路由的全部 IPv4 流量 | 需 fake-ip 才成 |

**层决定这条线有没有被用上，线决定出口在哪、稳不稳、快不快。** 层不对，35 元档和 4 元档的结局一样——都是本机 IP 出去，只是账单不同。

反过来也一样：只想要浏览器换个出口，却先装了带虚拟网卡的客户端，会出现「全局都被接管、本地网银和公司内网也跟着跳」的新麻烦。

## 三、按进程名匹配：够得着游戏，够不着自研网络栈

它按程序名和端口匹配，能覆盖不读系统代理的游戏，但绕不开不走 Winsock 的那部分流量。它是在应用与系统之间插一层，把指定进程发起的连接改道去代理，所以比系统代理广、比虚拟网卡窄。

强项正是系统代理的死角：模拟器、游戏登录器、只认自己网络库的桌面软件。配法通常是「规则表 + 默认动作」。

三个短板要提前知道。一是 UDP：能不能转取决于工具实现和线路，SOCKS5 要线路侧支持 UDP 转发才谈得上。二是绕过方式多的程序：带自研网络栈或驱动级通信的软件可以完全不出现在 Winsock 这一层，规则写了也不生效。三是全接管的错觉：它只管被规则命中的进程，没写进规则的程序照旧直连。

花钱这件事上它不省：它本身不带线路，你还需要一条 SOCKS5 或 HTTP 的线。沧海二区 4 元/月是这一层最容易起步的成本，按条计的线也在同量级，差别在你需要几条、要不要独立出口。

## 四、默认路由被抢走，仍有三处漏点

它把默认路由抢过来，走默认路由的 IPv4 流量基本都进隧道，但仍有三个口子会漏。它工作在网络层而不是应用层，所以不依赖程序愿不愿意读设置。

三种常见实现效果接近：SSTap 装 TAP-Windows 虚拟网卡，Clash 新版用 Wintun，安卓侧和多平台客户端多用 tun2socks。共同点是把一条 SOCKS5 或 HTTP 线包成一张假网卡。

第一个口子是客户端的绕过选项。「绕过局域网」「绕过大陆 IP」这类开关一勾，命中的目标就走直连——国内站点访问正常了，但你测国内目标时看到的当然是本机 IP。第二个口子是 IPv6：不少客户端只挂 IPv4 路由，目标站是双栈时可能优先走 IPv6，那条路没进隧道。第三个口子是主动绑网卡的程序，少数下载器和 P2P 工具会指定物理网卡出网。

还有一个前提：UDP 和 DNS。虚拟网卡要接管 UDP，一般得开 fake-ip 之类的假地址机制，并把 DNS 请求也导进隧道；否则域名还在本地解析，出口换了、CDN 节点没换，速度反而更差。

## 五、四种「看着通了其实没通」

| 错位类型 | 表现出来的样子 | 处置 |
|---|---|---|
| DNS 没进隧道 | 能上但慢，打开的是本地节点 | 开远程解析或 fake-ip |
| UDP 被放直连 | 网页正常，语音和组队不通 | 换支持 UDP 的线路，或接受不接管 |
| IPv6 优先 | 偶尔查出来是本机 IP | 关本机 IPv6，或让客户端一并接管 |
| 程序自带代理 | 系统里改了，程序里没变 | 在该程序自己的设置里单独填 |

第四类最容易被忽略。指纹浏览器、下载器、部分开发工具有自己的代理设置项，优先级高于系统代理，你在 Windows 里改的那个框对它无效。

## 六、四路读数对照，只认目标程序那一栏

同一台机器上浏览器、`curl`、PowerShell 三个结果不一致是正常的，说明它们读的是不同层。验收的目的不是让三个数一样，而是搞清楚每个程序从哪个出口出去。

| 测法 | 它反映的是 | 结果不一致说明 |
|---|---|---|
| 浏览器打开检测页 | 系统代理或虚拟网卡是否生效 | 与命令行不同：命令行没被接管，属正常 |
| 命令行裸跑 `curl` | 环境变量这一路 | 与本机 IP 相同：没设环境变量，不代表代理失效 |
| PowerShell 请求 | WinINET 系统代理 | 与浏览器相同：这一层确实生效了 |
| 目标程序自身 | 它到底走哪条路 | 只有这一项才决定业务安不安全 |

第四项才是最该看的：游戏登录器里的 IP 显示、模拟器内置浏览器、软件「网络」页里的出口信息。前面三项都在推断，只有目标程序自己承认的出口才算数。很多「买了没用」的投诉，是前三项测出来都换了、第四项一直没换。

## 七、先定层再定档，加预算治不了配置

| 你的需求 | 该停在哪一层 | 线路量级 |
|---|---|---|
| 只用一个浏览器比价、看后台 | 系统代理 | 4 元/月档起步 |
| 要开模拟器、游戏内也换出口 | 虚拟网卡 | 6 到 10 元/月档 |
| 按程序分线、部分直连 | 进程级重定向 | 按条计费 |
| 批量采集 | 脚本自己设代理 | 按条计费，先确认脚本支持 |

有三类人这次不用买：只想查一次自己的 IP，站内工具免费；只在国内站点之间比价，本来不需要出口变更；公司网络已下发统一代理策略，本机再改会被覆盖，先问网管。

最后一句实话：接管层决定流量走不走隧道，线路只决定走出去之后好不好用，别用加预算的方式解决配置问题。

## 九、常见问题

**Q：系统代理填好了，Chrome 走了，微信和 QQ 还是本机 IP？**
它们不读 WinINET 那份设置，属于直连。这类程序要么靠虚拟网卡整机接管，要么在程序自己的网络设置里单独填代理。

**Q：模拟器里查 IP 一直是本机，是不是线路有问题？**
先别怀疑线路。模拟器有自己的虚拟网络和 NAT，宿主机代理不一定覆盖到内部；确认客户端是否整机接管、模拟器网络模式是不是 NAT、有没有勾绕过规则，三项都对了再看线路。

**Q：虚拟网卡开了，游戏照样掉线，是接管没成功吗？**
接管和稳定是两件事。接管成功只说明流量进了隧道；掉线要看线路的丢包、延迟和目标服距离。先用检测页确认出口换了，再按丢包排查线路。

**Q：L2TP 的线能填进 SSTap 吗？**
不能。SSTap 只认 SOCKS5 和 HTTP 这类代理协议，L2TP 是另一种接入方式，走系统拨号或软路由。

**Q：三个检测结果不一样，到底该信哪一个？**
信目标程序自己显示的那个。前三个测法只是在验证各层有没有生效，业务安不安全只看业务程序实际用的出口。

**Q：怎么确认 UDP 有没有走隧道？**
看目标程序的行为而不是看网页。语音、组队、直播推流这类依赖 UDP 的功能如果只在开代理后失效，基本就是 UDP 没被转发。
