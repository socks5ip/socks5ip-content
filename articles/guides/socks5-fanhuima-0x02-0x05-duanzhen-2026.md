# 代理连不上先看返回码：0x02、0x05 各卡在哪一段（2026）

0x02 与 0x05 只差一个数字，卡的位置却在链条两端。前者意思是服务端收到了你的请求、但不允许这次连接；后者意思是服务端放行了、目标那边主动把连接拒了。同样是「连不上」，一个要改账号设置，一个要查目标端口。

**一句话结论：**SOCKS5 的失败分两类：**握手阶段失败**（0x01–0x04、0x06）说明出口到目标之间不通，**协商阶段失败**（0x02、0x07、0x08）说明服务端或客户端参数不匹配。**0x02＝策略拒绝**（白名单、IP 绑定、协议开关），**0x05＝目标端口拒绝**（目标主动 RST）。看到返回码再动手，比反复重装客户端省一小时。

## 一、九个返回码，各卡在哪一段

RFC 1928 定义了八种失败原因，加上成功共九个码。它们不是错误等级，而是失败位置。

| 返回码 | 含义 | 卡在哪一段 | 该动哪里 |
|---|---|---|---|
| 0x00 | 成功 | —— | 不用处理 |
| 0x01 | 服务端一般性失败 | 代理服务器自身 | 换节点或联系客服 |
| **0x02** | **规则不允许此连接** | **服务端策略** | **白名单、IP 绑定、协议开关** |
| 0x03 | 网络不可达 | 出口到目标的路由 | 换地区节点 |
| 0x04 | 主机不可达 | 目标主机 | 核对目标地址与端口 |
| **0x05** | **连接被拒绝** | **目标端口** | 目标服务未开、被防火墙拒 |
| 0x06 | TTL 过期 | 链路跳数 | 换更近的节点 |
| 0x07 | 命令不支持 | 客户端请求类型 | 改用 CONNECT，别用 BIND |
| 0x08 | 地址类型不支持 | 地址格式 | 域名换成 IPv4 地址 |

记住一个分界：0x02 之前的失败都发生在「服务端处理你的请求」这一层，0x03 之后才轮到「服务端去连目标」。这一句话能省掉大半排查时间。

## 二、0x02：服务端认识你，但不放你过

0x02 的原文含义是「按规则集不允许」。它不是网络问题，是权限问题。最常见的三种触发方式：出口 IP 不在白名单里、账号绑定了别的 IP、协议开关没开。

| 触发方式 | 现象 | 处理 |
|---|---|---|
| IP 白名单未加当前出口 | 换网络环境后突然全不通，换回原网络就正常 | 后台把当前出口加入白名单 |
| 账号绑定了固定 IP | 只有原机器能用，复制到别的机器就 0x02 | 后台解绑，或按新 IP 重新绑定 |
| 协议开关没开 | Socks5 能连、HTTP 不通，或反之 | 后台打开对应协议的开关 |

第一行最容易被误判成「线路坏了」。判断方法很简单：回到原来那台机器、原来那条网络再试一次，通了就说明线路没问题，是白名单在拦。这类配置在国内几家平台上都是后台自助，不需要找客服。

## 三、0x05：服务端放行了，目标自己把门关了

0x05 代表代理服务器已经成功连到目标地址，但目标端口回了 RST。这是目标端的决定，跟你买的线路质量无关。三种典型情况：目标服务没在该端口监听、目标侧防火墙按来源 IP 拒绝、目标只接受特定协议。

| 情况 | 验证方式 | 结论 |
|---|---|---|
| 端口没开 | 换一个确定可用的目标（如常规网页端口）再试 | 换目标即通，是目标端口问题 |
| 按来源 IP 拒绝 | 换一条不同地区的线路访问同一目标 | 某些地区通、某些不通，是目标侧限制 |
| 协议不符 | 同一目标用直连访问一次 | 直连也不通，与代理无关 |

第二行是关键区分。同一个目标、不同出口，一个 0x05 一个正常，说明目标在按来源地区做限制，这时候换线路比换平台更有效。

## 四、0x03、0x04、0x06：路由层的三个信号

0x03 网络不可达、0x04 主机不可达、0x06 TTL 过期，这三个都发生在「服务端去连目标」的路上。区别在于断点位置：0x03 是整段网络不通，0x04 是目标主机本身不可达，0x06 是跳数用尽。

| 返回码 | 断点 | 典型原因 |
|---|---|---|
| 0x03 | 出口所在网络 | 出口地区到目标无路由，换地区 |
| 0x04 | 目标主机 | 目标下线、域名解析错、目标内网地址 |
| 0x06 | 链路中段 | 中间设备丢弃，或目标在极远地区 |

0x06 在跨国线路上偶发，重试一次通常就恢复；连续多次 0x06 说明这条路径被中间设备处理了，换节点是最快的解法。

## 五、0x07、0x08：参数不匹配，不是网络问题

0x07 命令不支持，指的是客户端请求了服务端没实现的命令。SOCKS5 有三种命令：CONNECT（正向连接）、BIND（反向）、UDP ASSOCIATE（UDP 转发）。绝大多数代理平台只实现 CONNECT，客户端却因为配置写了 UDP 而被拒。

0x08 地址类型不支持，指的是地址字段用了服务端不认的类型。常见的是客户端把域名解析成 IPv6 再发过去，而平台只支持 IPv4。处理办法是把目标写成 IPv4 地址，或在客户端关掉 IPv6 优先。

## 六、自测口径：三个动作拿到返回码

第一个动作，用命令行直接看码。常见的做法是在 curl 里指定 socks5 代理后访问一个确定可用的目标，失败时终端会打出对应的错误描述，配合客户端日志能看到具体返回码。

第二个动作，用站内的代理线路可用性检测批量跑。它按真实握手验证 TCP 是否可用，能明确区分「端口开着但握手失败」与「握手成功」，这一步能先把线路自身的问题排掉。

第三个动作，换目标复核。同一个出口分别访问两个不同目标，都失败说明是出口或账号问题，只有一个失败说明是目标侧限制。

## 常见问题（FAQ）

### Q：开了代理还是本地 IP 怎么办？

先分清是「没连上」还是「连上了但没生效」。看返回码：报 0x01–0x08 说明连接没建立，浏览器显示的自然是本地 IP；返回 0x00 但出口仍是本地 IP，说明客户端只接管了部分流量，要在客户端里把规则改成全局，或检查是否被系统代理设置覆盖。

### Q：0x02 是不是线路被封了？

不是。0x02 是服务端的规则拒绝，线路本身是通的。最常见的原因是当前出口 IP 不在账号白名单里，或者账号绑定了另一台机器的 IP。回到原环境试一次就能确认。

### Q：0x05 出现是不是说明代理坏了？

不是。0x05 表示代理已经连到目标，是目标端口回的拒绝。换一个目标地址再试，如果新目标正常，问题就在原目标那一侧，跟代理无关。

### Q：同一个账号，有的软件能连有的报 0x07？

0x07 是命令不支持。多数平台只实现 CONNECT 命令，如果客户端配置里启用了 UDP 转发或反向连接，就会被拒。把客户端改成只走 TCP 正向连接即可。

### Q：怎么快速判断是代理问题还是目标站问题？

两条线对照：挂代理访问目标 A 失败、访问目标 B 正常，是目标 A 的问题；两个目标都失败，是代理侧的问题。再把代理换成直连访问同一个目标，直连也不通就与代理完全无关。
