# 换线之前先测一次

连不上时最费额度的动作，反而是立刻去后台换一条线——问题若在使用侧，换十条也一样连不上，额度却已经花掉了。**线路问题只有两类：IP 本身的问题和使用侧的问题。**而它们的前置动作是同一步：跑一次批量检测，看结果落在哪一侧。站内线路 2.6 元/月起，换线额度不算便宜，把它花在试错上实在可惜。

## 一句话结论

检测结果是分界线。**显示 IP 正常，就别再换线了**，往配置、本地网络、项目与 IP 类型匹配这三个方向查，这一类换线完全无效；**显示超时、连接被拒或出口异常，那才是线路侧的事**，去平台后台换一条、换完复测确认。把这一步做在换线之前，能省掉绝大多数无效换线。

| 检测结果 | 问题在哪 | 该做什么 |
|---|---|---|
| IP 正常 | 使用侧 | 查配置 → 换环境复测 → 核对 IP 类型 |
| 认证失败 | 使用侧（多为配置） | 核对线路账号密码、确认协议与端口对应 |
| 超时 / 连接被拒 | 线路侧 | 后台换线 → 复测 → 同步客户端 |
| 出口异常 / 归属地不对 | 线路侧 | 换线；若业务要求特定地区，按地区筛线路 |

## 一、批量检测怎么用：四个字段，格式与平台导出一致

入口是 [代理线路批量检测](https://socks5ip.com.cn/proxy-check/)。它最省事的地方是输入格式与平台后台复制出来的完全一致，不需要改写成别的样子，多行粘贴即可批量测。

| 字段 | 含义 | 常见填错 |
|---|---|---|
| 地址 | 线路的连接入口地址（host） | 填成了平台网站域名 |
| 端口 | 该线路对应协议的端口（port） | 用了另一个协议的端口 |
| 账号 | 线路用户名（ipid），不是平台登录账号 | 填了平台会员账号 |
| 密码 | 该线路的密码（pwd），不是平台登录密码 | 复制时末尾多带了空格 |

如果结果里出现「格式无法识别」，先检查分隔符是不是竖线——从表格里复制时偶尔会把竖线一起带进来，用纯文本方式复制更稳。

## 二、结果一：IP 正常，问题在使用侧

检测显示 IP 正常（能握手、有出口归属地），说明线路本身是好的。这时连不上的原因在使用侧，按四类方向往下查即可，**这一类换线是无效的**。

| 方向 | 典型表现 |
|---|---|
| ① 配置使用问题 | 提示认证失败、无法连接，多见于账号密码或协议填错 |
| ② 本地网络 / 设备原因 | 同一条线路换台设备就能用，或某些协议在本机不生效 |
| ③ 项目与 IP 类型不匹配 | 能连上但目标站点不认，或刚连就断 |
| ④ 其他 | 并发、端口占用、客户端版本等零散因素 |

方向一占了绝大多数，而且几乎都是几个固定位置填错。「线路账号」与「平台账号」是两套东西——线路的 ipid / pwd 是平台为每条线路单独生成的；从后台复制时请复制线路那一行，而不是登录信息。协议选错也很常见：同一档位常常同时给 SOCKS5 和 L2TP 两种接入方式，端口与凭据并不通用，报错通常只写「认证失败」，看起来像账号错了，实际是协议错配。

方向二的判断方法很直接：把同一条线路换一台设备、换一个网络环境再测一次，换了就能用说明问题在原来的环境里。方向三最有迷惑性——IP 能连、检测全绿，但业务就是用不了，原因是目标站点对出口 IP 的类型有要求，比如对机房段做额外校验，或者要求特定地区的出口。这时用检测工具看出口归属地与 IP 类型，和目标方的要求对照。

## 三、结果二：超时或异常，问题在线路侧

| 步骤 | 动作 |
|---|---|
| 1 | 到购买 IP 的平台后台，用「切换线路 / 换 IP」功能换一条 |
| 2 | 换完重新测一次，确认新线路的状态 |
| 3 | 把客户端里的地址 / 端口 / 凭据同步更新（换线后入口可能变化） |
| 4 | 若连续切换多条仍异常，记录线路信息联系平台客服 |

第 3 步最常被漏掉：换线之后，平台侧的入口地址或端口可能已经变了，而客户端里还是旧的，于是出现「换了线还是连不上」的错觉。换完务必回客户端核对一次。

## 四、换线之后要做完的三件事

| 动作 | 目的 |
|---|---|
| 再跑一次批量检测 | 确认新线路本身是通的 |
| 在客户端里实际连一次 | 确认入口变化已同步、凭据生效 |
| 看出口归属地是否符合业务要求 | 避免「通了但地区不对」再来一轮 |

还有一条容易误判的情况：同一条线路账号在多台设备上同时测试时，部分平台一条线路只允许一个连接，第二个连上会把第一个断掉，看起来就像时好时坏。排查时建议一次只在一台设备上测，避免把并发冲突当成线路故障。

## 常见问题

**Q：检测显示 IP 正常，但我还是连不上，最先该查什么？**
先核对两件事：线路账号密码是否用的 ipid / pwd（不是平台会员账号），以及协议与端口是否对应。这两项占了「IP 正常但连不上」的绝大多数。

**Q：账号密码明明没改过，为什么提示认证失败？**
多半是协议选错了。同一档位同时给 SOCKS5 和 L2TP 时，两者的端口与凭据不通用，用 A 协议的端口配 B 协议的账号就会直接报认证失败。先确认客户端里的协议与端口来自同一份线路信息。

**Q：批量检测一次能测多少条？**
多行粘贴即可，没有硬性条数限制，但一次贴太多会影响等待时间。建议按实际需要分批测，先测当前在用的那几条。

**Q：检测超时，是不是线路一定挂了？**
不一定。本地网络限制了对应端口也会表现为超时。换一个网络环境再测同一条——如果换了就通，说明是本地网络问题，这时换线也没用。

**Q：换了一条还是连不上，怎么办？**
按顺序确认三件事：新线路是否已复测通过、客户端里的入口地址与端口是否已同步更新、换线后的凭据是否核对过。这三步排完仍不通，就把线路信息发给平台客服。

**Q：线路快到期也会表现为连不上吗？**
会。到期后线路直接失效，现象与故障很像。如果手上有其他线路能正常用，先核对一下这条线路的到期时间，再参考站内的代理IP 到期处理流程。
