# 25、3389、3306 连不上：端口卡在四处策略上

同一条线路 443 能开，25 为什么一直超时？差别不在客户端的设置里，在出口那一侧：平台放行什么、目标站监听什么、你的客户端转不转这类流量，三处各自独立，任何一处挡住，表现都是「连不上」。

端口这件事最容易被误判成线路质量问题，于是换平台、升带宽，问题依旧。真正要做的第一件事是分清「谁在卡」，而不是「加多少钱能解决」。

**一句话结论：SOCKS5 不看端口，卡住的是四处策略；能连网页却连不上 25／3389／3306 时，先看返回码——**立刻失败且返回 0x02 是平台出站规则拦的**，一直超时是包被丢弃（端口或网络没通），**连上后立刻断开是目标站的安全策略**。**

| 四处策略 | 典型表现 | 一句话判据 |
|---|---|---|
| 平台出口的出站规则 | 网页秒开，25 或 3389 一直超时 | 换平台同样超时＝不是这一家的问题 |
| 目标站是否监听 | 端口能连上，业务立刻断开 | 同一端口换个目标就通＝目标侧没开 |
| 客户端转不转这类流量 | 浏览器走了代理，远程桌面还是本机 IP | 系统代理只接管 HTTP/HTTPS |
| 中间网络 | 公司网、校园网里全都不通 | 换手机热点立刻通＝本地网络封的 |

## 返回码先分层，五类错误对应五个位置

把「连不上」当成一种现象，排查就没有入口。按返回码分五类，每一类指向的位置是固定的：一直卡住到超时，是包被丢弃、对方没有回应；立刻失败并返回 0x02，是代理服务器的出站规则不允许；立刻失败并返回 0x05，是目标侧拒绝连接；连上后立刻断开，是目标站的安全策略；浏览器能开、命令行工具不通，是客户端没接管这类流量。

| 现象 | 大概位置 | 下一步动作 |
|---|---|---|
| 一直卡住、数秒后超时 | 包被丢弃，无回应 | 先换目标端口试，再换出口试 |
| 立刻失败，返回码 0x02 | 平台出站规则不允许 | 直接问客服这个端口放不放 |
| 立刻失败，返回码 0x05 | 目标侧拒绝连接 | 目标站没开这个端口，或只对白名单开 |
| 连上后立刻断 | 目标站安全策略 | 看日志与验证页，与端口无关 |
| 只有浏览器能走代理 | 客户端没接管非 HTTP 流量 | 换成整机接管的方式 |

## 平台拦的是端口号本身，不是你的账号

平台出口的规则通常只拦两类：一类是高风险服务端口，25 最典型——它直接对应发信，被滥用的概率最高，多数平台默认不放；另一类是内网管理端口，3389 与 3306 属于这一类，放开等于把远程桌面和数据库暴露在公网。

这两类的共同点是「平台不针对你，针对的是端口号本身」。所以换一家平台大概率还是一样——判断方法很简单：同样的端口在两个平台都超时，就不是平台的问题；一个通一个不通，才是这家平台的规则。

## 对面那一端常常根本没在听

反向看目标那一端：绝大多数站点只监听 80 与 443，数据库端口只在白名单里开放，25 端口在云厂商侧普遍默认封禁。你连不上，很可能是因为对方根本没收这个连接。

判断方法：把同一个端口换一个目标试。同一个 3306 连 A 站超时、连 B 站立刻返回 0x05，说明链路是通的、是 A 站没监听；两个目标都超时，才轮到怀疑链路。

## 系统代理只认 HTTP 与 HTTPS

系统级代理设置改的是浏览器与部分应用的 HTTP/HTTPS 流量，远程桌面、数据库客户端、SSH 这些走的是自己的协议栈，多数不读系统代理。所以会出现「浏览器查出来是代理 IP，远程桌面连上还是本机 IP」。

解决办法有两条：一是换用能接管整机流量的方式（隧道类协议），二是给具体客户端单独配代理。前者一次配好、后者逐个应用配，代价与收益不同。

| 你所在网络 | SK5（TCP） | L2TP（UDP 1701） |
|---|---|---|
| 家庭宽带 | 通 | 通 |
| 公司网、校园网 | 通（走 443 最稳） | 多数不通，UDP 被拦 |
| 酒店、机场 Wi-Fi | 通 | 常不通，需网页认证后才放行 |
| 手机热点 | 通 | 通，但出口是运营商 NAT |

## 三条命令，按链路到端口的顺序测

第一步用 curl 走 SOCKS5 请求一个网页，看返回里有没有「request granted」，这一步验的是代理到目标的整条链路。第二步用 nc 指定 SOCKS5 去连任意 TCP 端口，停住等输入就是通、超时就是不通。第三步在本机直连同一个端口做对照，排除本地网络的问题。

| 命令 | 测的是什么 | 输出里读哪一行 |
|---|---|---|
| curl -x socks5h://… | 代理到目标的整条链路 | SOCKS5 request granted |
| nc -X 5 -x … | 任意 TCP 端口 | 停住等输入＝通；超时＝不通 |
| Test-NetConnection | 本机直连目标端口 | TcpTestSucceeded |

三步的顺序不能反：先验链路、再验端口、最后对照本地。反过来做，会把「本地网络封了端口」误判成「代理不支持这个端口」。

## 换协议比升带宽更省的那几块钱

需要跑非 Web 端口时，最省的路子通常不是加钱升带宽，而是换协议。SK5 按条计价、只处理 TCP；隧道类协议在 IP 层转发，没有「端口放不放」这回事，但要求本机网络能出 UDP。

## 常见问题

**问：SOCKS5 支持 25 端口发信吗？**

答：协议上支持，实际上多数平台不放。判断方法是看返回码：0x02 是平台拦的，超时是包被丢弃。要发信建议直接用企业邮件服务，不要绕代理。

**问：远程桌面连上了但很卡，是端口问题吗？**

答：不是。能连上说明端口通，卡的原因在带宽与往返延迟。3389 对往返次数敏感，出口离你越远越明显。

**问：为什么浏览器走了代理，远程桌面还是本机 IP？**

答：系统代理只接管 HTTP/HTTPS。远程桌面走自己的协议栈，要单独配代理，或者换成整机接管的方式。

**问：公司网里什么都连不上，换手机热点就好了？**

答：说明是本地网络在拦，不是代理的问题。公司网常封非标准端口与 UDP，换网络环境是最快的验证。

**问：换个平台就能连上 3389 吗？**

答：要看是哪种卡法。同样端口在两家都超时，问题不在平台；一家通一家不通，才值得换。

**问：跑非 Web 端口一定要换 L2TP 吗？**

答：不一定，但概率上更省事。隧道类协议在 IP 层转发，不受端口放行限制，代价是本机网络要能出 UDP，且价格通常从 7 元/月起。
