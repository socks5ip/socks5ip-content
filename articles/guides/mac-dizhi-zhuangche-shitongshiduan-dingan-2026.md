# MAC 地址撞车不是断网是时通时断：多开三步定案（2026）

这条线从来没掉过线，卡顿却每隔几十秒来一次——问题从来不是线路，而是局域网里两个端口在抢同一个地址。去换节点、换平台、重装客户端，一圈下来症状一模一样。

**一句话结论：**MAC 是网卡的 **48 位**链路层地址，以太网帧头 **14 字节**里有 **12 字节**给两个 MAC，它只在一个广播域内有效，每过一跳路由器就被重写成出接口的地址，所以**任何网站服务器都拿不到它**，改 MAC 对账号关联判定没有作用。真正会出事的是**同网段撞车**：克隆机、导入副本、批量镜像沿用了同一个 MAC，交换机地址表在两个端口之间来回覆盖，表现成时通时断。定案只需三步：核对 ARP、断开一台看是否恢复、改末字节验证。

## 一、四种「时通时断」先分清是谁

同样是间歇性卡顿，原因分得很开。先按表现归类，能省掉大半排查。

| 症状 | MAC 撞车 | 代理线路抖动 | 本地 DNS 慢 |
|---|---|---|---|
| 断的时候 ping 网关 | 时通时断 | 通 | 通 |
| 断的时候换一条线 | 还是卡 | 恢复正常 | 还是卡 |
| 受影响范围 | 同网段两台或多台 | 只影响走这条线的进程 | 影响所有域名解析 |
| 恢复方式 | 隔几十秒自动恢复 | 重连或切换节点 | 等解析超时后恢复 |

第三行是关键：换线之后还卡，就不是线路问题。这一条能排掉七成的误判。

## 二、撞车现场：地址表在两个口之间来回翻

交换机会记一张「MAC → 端口」的表，用来决定帧往哪个口发。同一个 MAC 从两个口出现时，表项会被覆盖成最后学到的那个——于是发往这台机器的帧一会儿从这个口出去，一会儿从那个口出去，另一台收不到，就表现为丢包。

这个过程是持续的、有节奏的，所以症状是「卡一下、好一下」，而不是彻底断。彻底断通常是 IP 冲突或网关不通，反而不难查。

## 三、三步定案

**第一步：核对 ARP 表。** Windows 上开命令行敲 `arp -a`，Linux 上 `ip neigh`。看同一网段里有没有两台机器的出口地址指向同一个物理设备，或者同一个 IP 对应两组不同的 MAC。这一步只能看本机视角，所以要在两台机器上各跑一次。

**第二步：断开一台，看另一台是否立刻恢复。** 这是最直接的验证——拔掉或停掉一台虚拟机的网卡，如果另一台的卡顿立刻消失，基本可以定案。反过来，同时开着就一定卡，也说明它们在抢同一个地址。

**第三步：改掉末字节。** MAC 的前三个字节是厂商标识（OUI），后三个是设备序号。改的时候只动最后一个字节，既避开撞车，又不会撞上别的厂商段。虚拟机在「网络适配器 → 高级 → MAC 地址」里改，克隆之后先做这一步再开机。

## 四、服务器那一侧，你的身份是另外三样

| 层次 | 平台能拿到什么 | 改它有用吗 |
|---|---|---|
| 网络层 | 出口 IP、ASN、端口、TLS 域名 | 有用，这是主力 |
| 会话层 | Cookie、localStorage、登录 token | 有用，最常被漏掉 |
| 应用层 | UA、Canvas/WebGL、字体、时区、语言 | 有用，但要成套改 |
| 链路层 | MAC 地址 | 拿不到，改了也没人看到 |

浏览器没有读取 MAC 的接口，网页脚本也调不到——不是厂商克制，是沙箱里没有这个能力。所以把时间花在改 MAC 上，等于给一个收不到的信封换邮票。

多开真正该动的是三样：**出口 IP 分散到不同网段**（不要十条线挤在一个 /24 里）、**浏览器环境成套隔离**（Cookie、UA、时区、语言一起改，只改一样反而更显眼）、**操作节奏错开**（同一秒登录十个账号，出口再散也没用）。

## 常见问题（FAQ）

### Q：改 MAC 能不能防账号关联？

不能。MAC 只在一个广播域内有效，出网关就被重写，目标服务器收到的源 MAC 是最后一跳路由器或机房网关的接口地址。它能影响的只有同一局域网内的设备，网站那一侧看不到。

### Q：为什么撞了 MAC 不是完全断网，而是一卡一卡？

因为交换机地址表是被覆盖而不是被清空：两个端口轮流「抢到」这个地址，帧就往最后学到的那个口发，另一台收不到就丢包。下一个广播或帧又把它抢回来，于是时通时断。

### Q：多开十几台虚拟机，MAC 一定要一个个改吗？

不必全靠手工。克隆或导入之后先给每台生成一个新的 MAC（多数虚拟化平台在克隆时可选「重新生成」），再用脚本核对一遍有没有重复。重点是别让批量镜像带着同一个地址跑起来。

### Q：arp -a 里看到同一个 MAC 对应两个 IP，是冲突吗？

不一定是。同一个物理网卡绑多个 IP 是正常配置，要看的是同一个 IP 有没有对应两组 MAC，或者两个端口在抢同一个 MAC。判断时结合第二步的断开测试更快。

### Q：换 IP 之后还是要重新登录，这算正常吗？

算正常且必要。Cookie 与登录 token 存在本地，换出口不会自动清掉，平台把「新出口 + 旧会话」当成异常更常见。换线之后顺手清一次会话，比只换 IP 更接近一个干净的环境。
