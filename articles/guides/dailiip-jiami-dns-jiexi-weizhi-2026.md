# 代理IP 换了地区网页还是国内版：加密 DNS 把解析留在了原地

打开「安全 DNS」这个开关，查询就从 53 端口搬到了 443——出口没变，答案变了。很多人以为这是 IP 没生效，其实是解析点和出口分家了。

花 5 元买一条海外出口，DNS 查询可能根本没跟过去。市面上的 DNS 泄漏检测还在查 53 端口，看到的是一片正常；而真实情况是查询走了 443、被分流规则判给了直连，解析仍在本地完成。

**一句话结论：解析只发生在三个位置——本机、代理服务商那侧、加密 DNS 服务商的边缘节点。判断地区有没有生效，看解析结果落在哪个城市，不看检测网站的总评。**

| 解析方式 | 查询从哪发出 | 地区跟谁走 |
|---|---|---|
| 明文 DNS（默认） | 本机 → 本地运营商 | 跟本地，不跟出口 |
| 远端解析（socks5h） | 代理服务商出口侧 | 跟出口 |
| 加密 DNS（DoH／DoT） | 取决于 443 走没走代理 | 跟解析点，未必跟出口 |
| 系统级 DoH + TUN | 系统解析器，53 劫持管不到 | 最常见的错位来源 |

## 三条解析路径，决定你看到哪个地区版本

出口 IP 换成了洛杉矶，解析如果还在本机，很多站点给你的仍是按本地就近调度的节点，页面语言、货币、推荐位全都跟着那个节点走。这跟 IP 质量、纯净度、ASN 都没有关系。

**路径一，本机解析。** 这是 SOCKS5 的默认行为：客户端先在本地把域名查成 IP，再把 IP 交给代理去连。查询直接进了本地运营商的递归解析器，目标站拿到的虽然是你买的那条出口，但 CDN 与 GeoDNS 在解析这一步就已经按本地位置给过答案了，后面的连接只是照着这个答案去连。所以有些站点换了三次出口，看到的还是同一批节点。

**路径二，远端解析。** 域名原样透传给代理服务商，由平台侧在出口那一头解析。这条路拿到的节点是出口地区的，代价是每次新域名多一次往返。客户端里通常写作「远程 DNS」「Proxy DNS」「socks5h」，代码里则是 socks5h:// 前缀，或者 curl 的 --socks5-hostname。

**路径三，加密 DNS。** 查询本身变成一条 HTTPS 或 TLS 连接，发给你指定的解析服务商。它既不是纯本地、也不是纯远端，而是「看你这条 443 连接被分流规则判给了谁」。同一台机器、同一条代理，只看这一个开关，结果就能差出一个地区。

前两条由协议和客户端决定，第三条由你自己打开的那个开关决定。多数人出问题，都是因为前两条按默认在跑，第三条又被手动打开，两套逻辑叠在一起互相拆台。

## DoH 把查询塞进 443，于是它跟网页排同一个队

加密 DNS 的本质是把查询包成一条 443 端口的 HTTPS 请求，它因此不再受「DNS 劫持」管辖，改由分流规则决定去留。明文 DNS 是 UDP 53，无连接、不加密，TUN 类客户端常常把 53 整体劫持到自己内置的解析器上，所以「全局代理」在解析这一段是通的。换成 DoH 之后端口变成 443，劫持规则看不见它。

**推论一：任何按域名、按 IP 段、按地区做的分流规则，都会命中这条 443 连接。** 规则写「国内直连、其余走代理」时，若 DoH 服务器在本地可达名单里，这条查询就走直连——加密了，但没走代理，解析点仍在本地，而检测工具查 53 端口什么也发现不了。

**推论二：DoH 服务器自己的域名要先解析一次。** 这一步会退回明文 DNS 或者靠 IP 直连完成，属于先有鸡还是先有蛋的问题。部分客户端因此内置一个引导地址，避免这一步走本地运营商。

两条推论加起来就是最常见的那个错位：出口换了、加密开了、检测全绿、页面还是国内版。

## 四个落点，同一条代理能测出四种结果

| 落点 | 查询发起点 | 检测工具看到的样子 |
|---|---|---|
| ① 本机解析（默认） | 本地运营商递归 | 53 端口检测可能报泄漏 |
| ② 远端解析（socks5h） | 平台出口侧 | 53 端口检测看不到查询 |
| ③ 加密 DNS 走代理 | 境外解析服务商边缘 | 检测全绿，解析跟出口 |
| ④ 加密 DNS 走直连 | 本机 → 境外解析服务商 | **检测全绿，解析不跟出口** |

只有第 ④ 种是「看起来最正常、实际最错」的状态。它的特征很好认：出口 IP 的城市和解析结果的城市不是同一个。

## 自测：看城市，不看总评

一条判据足够：**解析结果的城市，要等于出口 IP 的城市。**

三步做法：

1. 先用任意 IP 查询页确认当前出口在国内还是国外、落在哪个城市。
2. 用支持指定解析服务器的工具，分别向本地运营商 DNS 和一个境外 DoH 查同一个域名，把两次返回的 IP 都记下来。
3. 拿这两个 IP 去查归属地。跟出口同城的那个，才是真正生效的解析路径。

如果两次都落在本地城市，说明加密 DNS 那条 443 被分流规则放行成直连了。这时要么关掉加密 DNS、改用 socks5h 远端解析，要么把 DoH 服务器的地址从「直连名单」里移出去。

## 四种客户端的处理方式

| 客户端类型 | 默认行为 | 要改的地方 |
|---|---|---|
| SOCKS5 客户端（填 IP 端口那类） | 本机解析 | 开启「远程 DNS」，或用 socks5h |
| TUN 类客户端 | 劫持 53 到内置解析器 | 关掉系统级 DoH，避免两套逻辑打架 |
| 浏览器内置安全 DNS | 独立于系统设置 | 在浏览器设置里单独关掉或改成「跟随系统」 |
| 命令行工具 | 本机解析 | 用 socks5h:// 前缀或 --socks5-hostname |

浏览器这一项最容易被漏掉：系统里关了、浏览器里还开着，表现就是「只有浏览器不对，其他程序正常」。

## 什么时候该关

加密 DNS 不是必须开的。三种情况建议关掉或改成跟随系统：

- 业务要按出口地区拿内容（地区版本、货币、推荐位）——本地解析会直接毁掉地区感。
- 已经用了 TUN 类客户端——它自带解析器，两套逻辑叠加只会增加不确定性。
- 排查阶段——先把变量减到一个，问题才好定位。

保留它的场景也清楚：只是要防止本地运营商劫持、不关心地区归属的时候，加密 DNS 有价值。

## 常见问题

**问：开了代理还是本地 IP 怎么办？**
答：先分清是「连接没走代理」还是「解析没跟过去」。浏览器查 IP 显示的是线路地址，就说明连接走了，问题在解析；如果显示本机地址，那是客户端没接管，别查 DNS。

**问：DNS 泄漏检测显示全绿，是不是就没问题？**
答：不一定。多数检测只查 53 端口，DoH 的查询在 443 上，它看不见。要看解析结果的城市跟出口是否一致。

**问：socks5h 和 socks5 差在哪？**
答：差在谁来解析域名。socks5 是本机先查成 IP 再交给代理，socks5h 是域名直接透传给代理、由出口侧解析。要地区跟出口走，用后者。

**问：为什么只有浏览器不对，其他程序正常？**
答：浏览器有独立的安全 DNS 设置，不跟随系统。去浏览器设置里关掉，或者改成「跟随系统」。

**问：加密 DNS 会让网速变慢吗？**
答：每次新域名多一次往返，通常几十毫秒。首次访问有感知，缓存命中后基本无感。

**问：手机热点下也会出现这个问题吗？**
答：会，而且更常见。移动网络常带运营商的强制 DNS，加上系统级 DoH，两层叠在一起，表现就是出口换了、地区没换。
