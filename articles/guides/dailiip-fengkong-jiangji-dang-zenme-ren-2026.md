# 代理IP 没报错却抓不到数据：风控降级档怎么认（2026）

跑了两天，日志一片绿，入库条数却从 4 800 掉到 1 700——连接没断、没有 403、没有验证码，可数据就是少了三分之二。

**一句话结论：状态码 200 只说明连接通，不说明数据真；降级档只能靠「同 URL、双出口、比响应体」认出来，判据是三处量——响应体字节数掉 30% 以上、条目数固定缺口、关键字段整列为空。** 换更贵的 IP 治不好这件事，把请求间隔从 1 秒拉到 8 秒才治得好。

| 你看到的症状 | 大概率所处的档位 | 先动哪里 |
|---|---|---|
| 第 3 页起返回空列表 | 降级（分页深度被限） | 单 IP 单域名配额 |
| 条数、字段、价格对不上，但 200 | 降级（结果集截断／字段屏蔽） | 双出口比对，先定基线 |
| 开始要滑块、要验证码 | 挑战档，比降级更重 | 停手，降频，换桶 |
| 403／429／直接断开 | 拒绝档，已在最末端 | 换出口，查是否已被标记 |

## 一、五个症状都长在「内容变少」这一侧

降级的症状不带错误码，共同点是连接层一切正常：ping 得通、握手成功、状态码 200，只有数据和三天前不一样。

分页深度是第一处：第 1、2 页翻得动，第 3 页开始返回空数组，total 还写着几千条。多数人先怀疑翻页参数写错，其实目标站对深翻页单独计分，正常用户极少翻到第 5 页后。

条数截断是第二处：页面标称每页 20 条，实际返回 12 条，剩下的既不是空也不报错。这一处最难发现，因为脚本只检查「有没有返回」，不检查「够不够数」。

字段级屏蔽是第三处：整条记录都在，但价格是 null、库存是空串、发布时间是 1970。返回占位值是第四处：价格长期停在同一个数字，库存永远「有货」，看起来最像正常数据。耗时变短是第五处：同一个 URL 正常 480 毫秒，现在 210 毫秒，服务端提前 return 了，根本没查数据库。

## 二、目标站为什么不直接拒绝

直接拒绝会暴露规则、误伤真人，降级既能挡住采集又不惊动对方，对目标站是成本最低的一档。

三家目标站的取舍逻辑是同一套。403 是明确信号，你一收到就会改策略，改完再来，等于免费给了你一次反馈；返回「看起来很正常的空数据」，你可能几天后才发现，这几天你的产出是零，对方的服务器压力也是零。风控分数又是概率判断而不是身份判断，真实用户用着共享出口、公司出口也会落在可疑区间，对这批人回 403 误伤太大。

真实的档位是一条链：正常 → 限速 → 降级 → 挑战 → 拒绝。分数由四件事加权：出口出身、历史行为、当前节奏、账号状态。

## 三、三处可以量的缩水，先存基线

降级只能靠比对来认，比的不是速度而是三处量：响应体字节数、条目数、关键字段齐全度。没有基线就没有比对，所以第一件事不是换 IP，是存一份基线。

基线怎么存：拿同一个 URL，在五分钟内、UA 与 Cookie 都不变、不带随机排序参数的条件下，用直连取 3 次，再用一条信得过的出口取 3 次。每次记四个数——状态码、响应体字节数、条目数、关键字段非空比例。

| 量什么 | 正常档 | 降级档 | 读数要点 |
|---|---|---|---|
| 响应体字节数 | 与基线相差 5% 以内 | 掉 30%–70%，反复稳定 | 三次取中位数，别取单次 |
| 条目数 | 等于标称或 total 上限 | 固定少几条，缺口整齐 | 缺口整齐＝规则限制，不是没货 |
| 字段非空率 | 价格、库存、时间都有值 | 某几个字段整列空 | 整列空比零散空更可疑 |
| 深翻页 | 第 5 页仍有数据 | 第 3 页起稳定空数组 | 换出口后是否恢复是关键分叉 |

不比耗时，因为耗时受线路、跨网、晚高峰影响太大，同一件事能差出一倍。响应体字节数是内容侧的硬指标：服务端少给 30 条记录，字节数一定掉，跟线路快慢无关。

## 四、四步判定，顺序不能乱

第一步取直连基线；第二步用代理取同样 3 次，UA、Cookie、URL 参数保持一致，只换出口；第三步换三条不同层级的出口各取 1 次——一条低价共享、一条中档住宅、一条独享；第四步按差异归因。

第三步的结论很好读：三条都缩水，问题在节奏或账号；只有低价那档缩水，问题在出身；三条都不缩水而第二步缩水，说明第二步那条出口被单独标记了。

四步里最容易被跳过的是第一步。跳过它就没有参照物，所有「感觉变慢了」都无从证实。而它只花五分钟。

## 五、换 IP 治不好，降节奏才行

同一批 IP 把每域名请求间隔从 1 秒拉到 8 秒，降级会自己消失；换成独享 IP 但保持 1 秒，降级原样复现。原因在计分权重里，当前节奏占的比重明显高于出身——出身是「你可能有问题」，节奏是「你正在有问题」。

具体调三个数：单 IP 对单域名的请求间隔、单 IP 的并发线程数、同一账号在单位时间内出现的 IP 数量。前两个往下压，第三个往上收。可用起点是：一个域名一条 IP、一条 IP 一个线程、间隔不低于 5 秒，跑半小时不掉数据再按 20% 往上试。

换 IP 还有一笔隐形成本常被算漏：切换额度。鲸云云服务器 5 兆档 30 次／月，家庭 A 区也是 30 次／月；光子是 2000 次／月；天行带 1000 次切换；糖果是 40 次／条／天。把降级当抖动去无脑换 IP，30 次额度十分钟就能烧光。

## 六、自测口径：三件立刻能做的事

分桶、配额、只记一次账，这三件事改的是节奏而不是出口，改完当天就能看出数据回不回来，不需要加预算。

分桶：把手上的 IP 分成三到五桶，轮换周期按分钟算不按秒算，同一桶在一个周期内只服务一个域名。配额：给每条 IP 每个域名设一个每日上限，从每小时 60 次开始，稳了往上加 20%，掉了退回上一档。只记一次账：失败重试封顶 1 次，之后进观察队列，10 到 30 分钟后再跑。

这三件事在免费测试阶段就能验完。天行、沧海都自带 10 次免费测试卡，光子每天 10 条，糖果每天 5 条，用测试卡按上面的节奏跑一遍，掉不掉数据当天就有答案。

## 八、常见问题

**Q：状态码 200、也没有验证码，也可能是被拦了吗？**
A：是。降级档的特征就是不拒绝、只缩水，状态码和验证码都正常。判断依据只能是响应体比对。

**Q：只有几个字段是空的，算不算降级？**
A：整列空基本算。零散一两条缺字段可能是源站数据本身缺失，整列都为空说明是按字段屏蔽的。

**Q：换了独享 IP 还是空，是不是白买了？**
A：不一定。先看直连基线缩不缩水；直连也缩水，问题不在 IP 上。独享买的是「没人跟你抢」，解决不了「你请求太多」。

**Q：降级会自己恢复吗？要等多久？**
A：会，但取决于有没有继续撞。停止对同一 URL 的请求、把节奏降下来，通常几十分钟到几小时回到正常档；继续按原节奏跑，恢复时间会越拉越长。

**Q：一天只采几百条，量不大也会降级吗？**
A：会。触发看的是密度不是总量——一分钟内 20 次远比一天 500 次更容易触发。把同样的量摊到更长时间，通过率通常明显更好。

**Q：怎么排除是自己代码的问题？**
A：拿同一个 URL 用浏览器手工打开一次。浏览器能看到完整内容而脚本不能，问题在请求头或节奏；浏览器也是缩水的，问题在出口或目标站。
