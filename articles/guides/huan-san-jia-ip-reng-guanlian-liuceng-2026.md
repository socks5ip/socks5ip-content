# 换了三家 IP 还被关联：六层信号里五层与出口无关

换到第三家 IP 之后还是被判关联，问题出在哪一层？

**一句话结论：出口只是六层信号里的第一层，平台真正比对的是「六层之间一致不一致」——会话、指纹、路径、行为、资金这五层与 IP 无关，任何一层没断干净，换 3 家还是会被串成一组，所以排查顺序必须是「先定层，再花钱」。**

## 一、把六层摊开，先看哪几层跟 IP 有关

| 层 | 平台在这一层看什么 | 换 IP 有用吗 | 典型漏法 |
|---|---|---|---|
| ① 出口 | 这条 IP 上挂过几个号、是否被标记、地址类型 | 直接相关 | 买的「独享」其实是池子里分出来的 |
| ② 会话 | Cookie、LocalStorage、IndexedDB 是否跨店串 | 完全无效 | 同一个浏览器切号，或直接复制 profile 目录 |
| ③ 指纹 | Canvas、WebGL、字体、时区、语言是否成套 | 完全无效 | 时区改成美东，语言还是 zh-CN |
| ④ 网络路径 | WebRTC 暴露的真实地址、DNS 解析地、TLS 指纹 | 部分相关 | 走代理了但 WebRTC 把本地地址交出去 |
| ⑤ 行为 | 登录节奏、操作顺序、停留时长是否高度相似 | 完全无效 | 几个号每天同一分钟登录 |
| ⑥ 资金 | 收款账户、支付卡、收货地址、退款去向 | 完全无效 | 多个店回款到同一张卡 |

数一下：六层里只有第①层和第④层与出口沾边，其余四层你做多少条 IP 都不会变。

## 二、出口层：先确认「独享」独享给谁

同一个「独享」标签下至少有三种货：整段只卖给你一个人的静态线、一个池子里按次分给你的、以及一条线你独占但上游还有别人共用 ISP 段。这三种在检测报告里可能都显示「可用」，但第一种才真的没有第二个人在同一出口上登录。

判断只需要一个动作：**同一时间用两个账号各发一次请求，看出口是不是同一个 IP。** 是同一个，说明这条线是共用的；不是同一个，才谈得上独享。

## 三、会话与指纹：换 IP 完全无效的两层

会话层最常见的漏法是「同一浏览器切号」。Cookie 清了不代表干净——LocalStorage 里的埋点 ID、IndexedDB 里的离线缓存、Service Worker 注册记录都可能把你的两个号连起来。

指纹层的坑不在「有没有改」，而在「改得成不成套」：

| 看起来改了 | 仍然矛盾的地方 | 怎么修 |
|---|---|---|
| 时区改成 America/New_York | 语言与 Accept-Language 还是中文 | 时区、语言、请求头一起改 |
| 标识写成 Windows | 字体列表全是 Mac 字体 | 标识与字体、平台要对应 |
| 分辨率随机 | 屏幕尺寸与 CPU 核数完全一致 | 这组参数一起变才有意义 |
| Canvas 加了噪声 | WebGL 渲染器还是同一张卡 | 两个指纹要同时处理 |

单改一项等于给平台留了一条更容易比对的线索——**不一致本身就是信号**。

## 四、路径、行为、资金：最难自查的三层

路径层里，WebRTC 是最容易被忽略的一处：代理设好了，浏览器仍然可以通过 STUN 把本机地址报出去，两个号报同一个本机地址，关联就成立了。关闭 WebRTC 或用整机转发的客户端，这一层才算断。

行为层不看技术看节奏：几个号每天同一分钟登录、同样的浏览顺序、同样的停留时长，这种规律性比任何指纹都稳定。资金层最硬——同一张卡回款、同一个收款账户、同一个收货地址，前五层做得再干净，这一层也会把号连起来。

## 五、先定层，再花钱

排查顺序建议倒过来：**先从资金和行为查，再从会话和指纹查，最后才动 IP。** 因为前三项是零成本，改配置就有结果；动 IP 是要花钱的。

| 现象 | 更可能在哪一层 | 该做什么 |
|---|---|---|
| 换 IP 后依然立刻关联 | ② 会话或 ⑥ 资金 | 换独立 profile，或拆开回款账户 |
| 登录几天后才关联 | ⑤ 行为 | 改登录时段与操作节奏 |
| 某些站关联、某些站不关联 | ① 出口或 ④ 路径 | 先看该站是否校验地址类型与 WebRTC |
| 只在新设备上被拦 | ③ 指纹 | 检查语言、时区、字体是否成套 |

## 七、常见问题

### Q：怎么快速判断我的问题是不是在 IP 那一层？

做一次对照实验：同一个号、同一台机器、同一个浏览器，只换 IP 重启一次会话。如果换了就正常，问题在①出口；如果换了还是立刻被拦，问题在②③⑥，别再买线了。

### Q：独享 IP 是不是就一定不会关联？

不是。独享只保证「同一时刻没有别人跟你共用一个出口」，它不解决会话串号、指纹成套、同一张卡回款这些问题。反过来，共用 IP 只要上面没挂过目标平台的号，也可能一直没事。

### Q：指纹浏览器能解决几层？

能覆盖②和③，部分覆盖④（DNS 与 WebRTC 可配）。⑤行为和⑥资金它管不了——账号怎么操作、钱收到哪，是业务流程而不是浏览器参数。

### Q：WebRTC 关了会不会影响正常使用？

影响很小。少数视频会议与点对点传输会用到它，做店铺后台、社媒运营这类场景关掉没有副作用，反而是必须的一步。

### Q：已经关联过的号，换干净环境还有救吗？

看平台。资金层已经连上的号，通常救不回来；只因为会话或指纹被并到一起的，换独立环境加改节奏还有机会。判断方法只有一个：拿一个已经关联的号在全新环境里登一次，看平台的拦截速度。
