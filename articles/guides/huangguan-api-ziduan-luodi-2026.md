# 皇冠 API 取回号之后：四个字段怎么填进客户端

接口能取到号，为什么填进客户端还是不通？

**一句话结论：皇冠（Crown，ipcrown.com）的开放平台能取到线路，但接口文档要登录后台才看得到，公开路径 /api、/docs、/developer 实测均 404；真正决定取号之后能不能用的，是把返回结果落成四个字段（地址、端口、用户名、密码）加两个标记（协议、认证方式），并且逐条验证出口归属与记录一致——共享档 12 元/月、独享 18–45 元/月按国家分档，一条线只对应一个环境。**

## 字段名各家不同，落地只有四个位置

不管接口把返回值叫 host 还是 ip、叫 port 还是 server_port，最终要填的永远是四个位置。多出来的字段是给你对账用的，不是给客户端用的。

| 客户端里的位置 | 对应返回值的哪一类 | 常见坑 |
|---|---|---|
| 服务器 / 地址 | IP 或主机名 | 有的返回带协议前缀，要剥掉 |
| 端口 | 数字 | 被当数值处理会丢前导零 |
| 用户名 | 账号 | 与白名单认证互斥 |
| 密码 | 密码 | 特殊字符没转义，写进配置文件就断行 |
| 协议类型 | socks5 / http | 填错整条线不可用 |
| 有效期 | 到期时间戳 | 决定什么时候该换号 |

前四个是参数，后两个是状态。批量取号出问题，多半出在后两个上：参数抄对了，协议不对或时间过了。

## 坑一：协议标记没对，客户端直接不吃

代理产品的返回里通常带一个协议字段，取值可能是 socks5、http、https 或隧道类的标记。客户端的输入框只认一种时，把 http 的号填进只收 socks5 的框，界面不会拦你，连接会失败。

判断方法：**取号后先看协议字段，再决定用哪个客户端**。皇冠的产品线以 Socks5 与 HTTP 为主，桌面客户端、指纹浏览器、软路由对这两种的支持度不一样，同一条线在不同客户端里的可用性会有差别。

## 坑二：账密认证还是白名单，只能二选一

皇冠同时提供两种认证方式，取号之后必须先确认这条线绑的是哪一种。

- **账密认证**：四个位置都填，任何 IP 都能用。
- **白名单认证**：只填地址和端口，但你当前机器的公网 IP 必须已经在白名单里。

常见的失效场景是：脚本在 A 机器上跑通了，换到 B 机器直接不通——不是号坏了，是 B 的出口 IP 不在白名单。批量场景里这一点尤其致命，因为执行脚本的机器经常换。

判断顺序：先看后台这条线有没有绑定 IP 列表，有就先加当前出口 IP，再加账号密码。两边都配反而容易互相覆盖。

## 坑三：地区字段与出口实际归属可能不一致

接口返回的地区是这条线「应该」在哪儿，实际出口落在哪儿要以检测为准。跨境线路、机房调度、上游换段，都会让两者出现偏差。

| 检查项 | 用什么查 | 不符时怎么办 |
|---|---|---|
| 出口国家 | IP 综合检测中心的归属查询 | 换号，别在客户端里改配置 |
| 机房还是住宅 | 检测中心的线路类型识别 | 业务要住宅就换档，改配置无效 |
| 延迟与丢包 | 检测中心的测速与线路检测 | 明显偏高时换一条同地区线路 |
| 是否被目标站拦 | 业务场景模拟 | 换号后重试，别急着改指纹 |

这一步不能靠客服口头确认。归属与线路类型是可实测的，测一次的成本比来回问低得多。

## 批量之后的对账表：六列就够

脚本一次领几十条号，最怕的是「哪条对应哪个环境」记不清。落一张表，六列：

| 列 | 写什么 | 为什么必须有 |
|---|---|---|
| 领取时间 | 精确到分钟 | 排查时按时间窗对齐日志 |
| 地址 + 端口 | 原样保存，不做格式美化 | 出问题时要能原样复现 |
| 认证方式 | 账密 / 白名单 | 换机器时先看这一列 |
| 地区（返回） | 接口给的值 | 与实测结果对照 |
| 地区（实测） | 检测中心读到的值 | 不一致的号直接弃用 |
| 绑定环境 | 窗口或指纹环境的编号 | 一条线只对一个环境，不共用 |

这张表的价值在事后：一个账号被封，能立刻查到它当时用的是哪条线、那条线的实测归属在哪、以及同期还有哪些环境在用同一批号。

## 授权数与并发：接口再顺也会撞墙

接口只是取号的手段，能同时用多少条由产品档位决定。皇冠的独享档按国家分档计价（美国 18 元/月起，其他国家 28–45 元/月），共享档 12 元/月 覆盖 17 个主流地区但出口在共用池里。

批量之前先算两件事：

1. **环境数**：你要同时在线多少个环境。一条线对一个环境，环境数是硬上限。
2. **换号频率**：业务需要多久换一次出口。频率越高，同一档位下可用的号越容易被自己用尽。

还有一个前提经常被忽略：皇冠的节点全在境外，产品不做大陆转发、仅限大陆以外地区使用。执行脚本的机器如果在境内，接口能取到号，连接也建不起来。

## 自测口径：三条断言

批量取号后，脚本里加三条断言，比人工抽查可靠：

1. **数量断言**：取回条数等于请求条数，少一条就重试，不要吞掉。
2. **唯一性断言**：本轮取回的地址与上一轮记录没有交集，重复的号丢掉。
3. **可用性断言**：随机抽 3 条，各自跑一次握手与归属查询，全部通过才把整批写进对账表。

三条都过再进业务，比跑起来之后逐个排查省时间。

## 常见问题

**问：皇冠到底有没有 API？**

官网首页写着「API 集成」「支持 API 接口调用，并提供可视化监控统计」，帮助中心也设了开发者文档栏目，所以能力是有的。但接口地址、鉴权方式与返回结构都不在公开页面上，/api、/docs、/developer 实测 404，文档要登录后台或向客服索取。

**问：拿不到文档，还能批量取号吗？**

可以，但有代价。一条路是登录后台批量提取，再用脚本接管提取结果；另一条路是等到文档后直接调接口。前者的瓶颈是人工节奏，后者的瓶颈是文档到位时间，按你的并发需求选。

**问：取号成功但客户端连不上，先查什么？**

先查协议标记与认证方式。协议填错整条不可用；认证方式如果是白名单，换一台机器就会失效。这两项都对，再去查出口归属与线路质量。

**问：一条线路能给几个环境用？**

一条对应一个环境。共用会直接破坏隔离，多账号场景里这属于设计错误，不是配置问题。环境数超过线路数时，要加线路，不是想办法共用。

**问：接口返回的地区和实际出口不一样，正常吗？**

会有偏差。返回的地区是这条线应该落在哪，实际出口要以检测为准。做地区敏感业务（比如账号注册国）时，每条线都要实测一遍归属，不一致的直接弃用。

**问：境内的机器能调这个接口吗？**

取号可以，用起来不行。皇冠节点全在境外，官方写明不做大陆转发、仅限大陆以外地区使用。执行脚本的机器需要在境外，或者整条链路的出口在境外。
