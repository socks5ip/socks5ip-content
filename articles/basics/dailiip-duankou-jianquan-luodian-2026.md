# 代理协议选好了，换台设备为什么就不通：端口与鉴权的三个落点（2026）

在 A 电脑上跑得好好的 SOCKS5 账号，原样填进 B 电脑却连不上 —— 协议没变、密码没变，变的只是「谁在用」。这类问题几乎都出在协议之外的另外两栏：**端口**与**鉴权方式**。把这两栏看清，很多「线路坏了」的误判当场就能排除。

## 协议只是名义，要填的其实是另外两栏

选协议决定的是「流量以什么方式被转发」；真正决定「这台设备能不能连上」的，是后面两栏：

| 栏位 | 决定什么 | 填错时的典型现象 |
|---|---|---|
| 协议 | 转发方式（按程序 / 整机） | 工具里根本找不到对应选项 |
| 端口 | 有多少条通道可同时存在 | 一台能上、第二台连不上 |
| 鉴权 | 谁被允许使用这条通道 | 密码对，但一换网络就断 |

把「协议选型」当成全部，是新手最常见的第一处错位。协议选对了照样连不上，八成是下面两栏的问题。

## 端口那一栏：单口和多口差在哪

同样是「一条线路」，按端口形态大致分两种：

| 端口形态 | 特点 | 适合的场景 |
|---|---|---|
| 单口 / 固定口 | 一条线路对应一个入口，通常同时只服务一个连接主体 | 单设备、单浏览器环境 |
| 多口 / 多入口 | 一条线路对应多个入口，可同时给多个设备或环境使用 | 多设备、多环境并行 |

这件事在选型阶段就会咬人：如果一开始只买了单口，等到要同时跑几台设备时才发现「加设备就得加购」。所以**先数清要并行几个环境，再去选端口形态**，比买完再补要省事。

## 鉴权那一栏：三种方式各自的责任边界

| 鉴权方式 | 怎么验 | 责任边界（什么时候会失效） |
|---|---|---|
| 用户名 + 密码 | 每次连接都带账号密码 | 与出口网络无关，换网络照样能连；但要留意同时在线数 |
| IP 白名单 | 只放行预先登记过的出口 IP | 换网络、换宽带、IP 变化后立即失效，需要重新登记 |
| 预共享密钥 + 账号 | 建立一个隧道，密钥用来握手 | 通常在整机接管场景使用，密钥错一处就建不起隧道 |

这三种没有优劣，只有「用在什么位置」。**需要换设备、换网络都能连 ⇒ 用账号密码；需要固定环境、图省事 ⇒ 用白名单，但一旦换网络必须记得回来改。**

## 排错顺序：先验鉴权，再核对端口，最后才怀疑线路

按这个顺序走，绝大多数「连不上」在三步内就能定位：

1. **验鉴权**：确认账号密码有没有多余空格、白名单里登记的出口 IP 是不是当前这个。白名单方式下，换了网络这一步必查。
2. **核对端口**：确认填的端口与后台分配的一致；多环境并行时，确认端口数量够不够，不是「抢同一个口」。
3. **再看线路**：只有前面两栏都对，才需要用检测工具判断线路本身。用 SOCKS5 真实握手一测，能区分「线路不通」和「配置不对」。

第三步放最后，是因为前两步的成本几乎为零，而换线路的成本最高。顺序反过来，很容易在配置没错的情况下去换平台。

## 常见问题

**Q：协议选 SOCKS5 还是 L2TP，会影响能连几台设备吗？**
A：协议本身不决定台数，端口与账号的并发规则才决定。同样是 SOCKS5，单口和多口能并行的环境数量完全不同。

**Q：白名单方式为什么昨天能连，今天不通？**
A：多半是出口 IP 变了。白名单认的是登记过的那个 IP，换了网络、重启过光猫导致地址变化，都会让放行失效。

**Q：账号密码方式会给别人蹭吗？**
A：只要没外泄就不会。需要注意的是**同时在线数**：把它分享给过多设备，可能触发平台侧的并发限制，表现就是「时好时坏」。

**Q：配置全对，还是连不上，先做什么？**
A：用检测工具跑一次真实握手。握手过不去，说明问题在线路侧；握手能过但网页打不开，问题多半在 DNS 或分流规则，不在线路。

**Q：一台设备想同时跑多个环境，怎么配？**
A：按环境分别绑定不同端口或不同出口，而不是所有环境共用一个入口。这属于选型阶段就该定的事，后补通常要加购。

**Q：换台设备要重新申请线路吗？**
A：不用。账号密码方式下换设备只需重新填一次；白名单方式下要在后台把新设备的出口 IP 加进去。
