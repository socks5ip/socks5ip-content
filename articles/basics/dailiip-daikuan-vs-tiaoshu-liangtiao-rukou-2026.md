# 先定带宽还是先数条数：代理 IP 选型的两条入口（2026）

选线路时先定带宽，还是先数 IP 条数？这决定了你为「速度」还是为「数量」付钱。市面上的套餐档位几乎都是从这两个入口组织起来的，选错入口的典型后果不是买贵了，而是买到了一条完全不对路的产品。

## 选型入口有两条，通向两种商品

| 入口 | 你最先确定的量 | 商品形态 | 匹配的业务 |
|---|---|---|---|
| 从带宽出发 | 单路速率、峰值吞吐 | 独享带宽线路 | 拉流、同步、长时间连接 |
| 从条数出发 | 需要多少个独立出口 | 一批可切换的 IP | 多账号、多店铺、多任务并行 |

两个入口不存在先后优劣，只存在匹配不匹配。判断顺序是：先问业务在峰值时刻**同时**需要几个出口，再问每个出口**各自**需要多少速率。

## 入口一：从带宽出发——适合持续吞吐

带宽决定的是「管道每秒能通过多少」，在下面这些场景里它是硬约束：

- 大文件、素材、安装包的持续下载；
- 长时间保持连接的交互（直播类工具、远程桌面）；
- 多路同时拉流，且每路都需要稳定速率。

从带宽入口选型时，先算总需求：**并发路数 × 每路目标速率**，再加上两成冗余。例如四路同时跑，每路希望稳定在 8M 左右，就是 32M 起步、按 40M 找档位。

## 入口二：从条数出发——适合多条独立身份

条数入口对应的约束是身份数量：平台要求「一个账号一个出口」，而此时速率需求往往很低（只是登录、浏览、下单、发消息）。这类业务的瓶颈从来不是带宽，而是可用身份够不够、切换够不够省事。

从条数入口选型要问三个问题：

1. 需要多少个**同时在线**的独立出口，而不是总共需要多少个；
2. 这些身份需要保持多久不变（分钟级、天级还是月级）；
3. 切换是否需要人工操作，还是必须由脚本控制。

## 误配的两种典型症状

| 症状 | 真正的错配 | 怎么改 |
|---|---|---|
| 带宽档位一路加到顶，多账号依然被判定为同一环境 | 缺的是独立身份，不是速度 | 改走条数入口，按并发出口数选 |
| 条数堆到几十上百，单个任务依然慢得没法用 | 缺的是通道宽度，不是身份 | 改走带宽入口，按吞吐选档 |

两种症状的共同点是：加钱买同一种资源，怎么加都不见效。这时候要停下来重新判断入口，而不是继续往同一侧加档。

## 独享与共享：同一个带宽数字的两副面孔

带宽数字相同，含义可能完全不同：

- **独享带宽**：这段通道只分配给你，档位内的速率在你自己几路任务之间分配，不受他人影响。
- **共享带宽**：标注的是池子的上限，实际速率取决于同时使用的其他人。

判断方法有两条：一看档位说明里写没写「独享」；二看**同一档位内切换 IP 是否计次**——按独享带宽组织的套餐，通常把 IP 当作通道的属性，档位内换 IP 不计次；按共享池组织的套餐，会把 IP 条数单独计价。

## 判断路径：照着走五步

1. 写下峰值时刻同时需要的出口数，记为 N。
2. 写下每个出口需要保持的速率，记为 S。
3. 若 N 小（个位数）且 S 高，从带宽入口选，按 N×S×1.2 找档位。
4. 若 N 大且 S 低，从条数入口选，按 N 加两成余量找条数档。
5. 若两者都高，先用带宽入口确定通道，再用条数入口补身份，两个入口组合买。

第 5 种情况最容易被忽略：多数中等规模的工作室既不只需要身份、也不只需要通道，而是两个维度都要，这时一次买一档「全能套餐」通常不如按入口分两次买划算。

## 常见问题

**Q：不确定自己该走哪个入口，怎么办？**
A：数两个数字：峰值同时出口数、单路目标速率。前者大于十、后者不高，走条数入口；前者是个位数、后者要求明确，走带宽入口。

**Q：独享带宽是不是一定比共享快？**
A：在他人流量高峰时差别最明显。独享的速率只在你自己的任务之间分配，共享的实际速率取决于当时池子的使用情况。

**Q：按条数买的 IP，能不能当独享线路用？**
A：不能等同。按条买的是身份，通道仍是共享的；持续吞吐类业务要另配带宽线路。

**Q：并发路数和 IP 条数是同一个数吗？**
A：不是。并发是同一时刻的连接数，条数是你可持有的身份数量。手上有一百条 IP、只允许三路并发，实际只能同时跑三个任务。

**Q：先买小档试，再往上加，会不会更贵？**
A：试错成本主要在时间而不在差价。付费前先用免费测试确认「同时几路、每路多少速率能跑住」，再一次性选到接近的档位。
