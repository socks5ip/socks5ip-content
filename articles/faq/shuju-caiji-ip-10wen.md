# 数据采集用IP 10问

## 一句话结论

**采集选 IP 只看三件事：目标站要求（频率/地区）、你的并发（同时几个任务）、预算。** 默认组合是"动态轮换 + 按并发买量"，遇到强风控目标才需要上住宅或静态。

## 一、先算清楚用量

**Q1：采集需要多少 IP？并发怎么算？**
并发 = 同时进行的任务数。多线程采集：并发 ≈ 线程数；跑脚本抓列表/详情页，先数自己开了多少线程，那就是最低并发需求。套餐写的"IP 数"≠并发，买前问清"支持多少并发"。

**Q2：怎么估算每天要多少流量/请求？**
页面量 × 单页请求数 = 总请求。再用目标站限速要求（每秒几次）反推需要多长采集周期。算完你会发现：多数采集需求用小带宽动态套餐就够，只有高频大批量才需要大并发档。

## 二、线路类型怎么选

**Q3：动态还是静态适合采集？**
**动态**。采集讲究出口多样、降低单出口频率；静态出口固定，高频采集反而容易被目标站盯上。少数场景（登录态采集、固定接口）才用静态。

**Q4：机房 IP 还是住宅 IP？**
先机房——便宜量大，公开网页数据采集够用；目标站风控严（识别机房 IP、验证码频繁）再上住宅。住宅价格高 2-5 倍，能省则省。

**Q5：轮换频率怎么控制？**
默认"按请求轮换"适合低要求站；风控严的站要控制单出口请求频率（每秒 1-2 次以内），别一把梭。能用目标站容忍的频率跑完，就别上大并发硬刚。

## 三、反爬与稳定性

**Q6：目标站反爬（验证码/封 IP）怎么应对？**
先做合规优先级：放慢频率、换住宅线路、模拟真实浏览器行为（UA/指纹）；验证码出现说明已被盯，先降速观察，别继续加并发对冲。采集务必只抓**公开数据**，遵守目标站 robots 与条款。

**Q7：采集过程中 IP 失效/断连怎么办？**
动态套餐支持自动轮换可用出口；脚本要有重试与断点续跑逻辑。买前看平台可用率承诺与实测——可用率 98%+ 的线路才能支撑长任务。

**Q8：多目标站采集，线路要分开吗？**
不同站用同一批出口会被关联画像，风控严的站建议分开出口池；采集对纯净度不敏感时影响不大，按目标站的重要程度决定。

## 四、预算与落地

**Q9：采集预算怎么分档？**

| 需求 | 推荐配置 | 参考档位 |
|---|---|---|
| 轻量采集（几十并发内） | 动态机房，低并发 | 最低档即可起步 |
| 中量多线程 | 动态机房，并发升档 | 中档 |
| 强风控目标站 | 住宅/独享轮换 | 高档 |

起步用最低档跑通代码与频率，量上来了再升档，别一次买满。

**Q10：买到手先测什么？**
按真实脚本小批量跑一遍：可用率、单出口频率限制、轮换是否生效、目标站是否触发风控。测试达标再放量。各平台采集套餐对比可查[价格中心](https://socks5ip.com.cn/jiagezhongxin/)。

## 常见问题

**Q：采集代码里 SOCKS5 和 HTTP 代理选哪个？**
多数采集框架两者都支持：requests/scrapy 配 HTTP 简单，SOCKS5 更通用（支持 UDP 等）。看你的框架文档选，配完先小批量验证再放量。
